# 进化规则回归

这组夹具验证进化查询、成功计划与提交边界。覆盖入口为 [进化查询](../../../src/framework/rules/evolution.ts)、[成功计划](../../../src/framework/rules/evolution-success.ts) 和 [应用提交计划](../../../src/framework/rules/evolution-commit.ts)。

- 先做成员守卫，再按当前形态、触发类型和条目顺序匹配，选中的目标形态不会在演出结束后重新计算。升级判定只在可信的战前等级低于当前等级时尝试；一旦选中或者必要事实不可用，不能改走战后条件。新获得的成员可以合法没有战前等级；缺失原本应有的值则不是相同结果。资格时点的 HP 由调用方提供，不会改写成员实际 HP。队伍条件会排除蛋，但保留濒死成员和自己。
- 事实可以是显式值、确认不存在、不可用或无效；也可按需获取。没有提供事实不等于确认不存在，读取抛错或数据畸形也不能当成正常未命中。地图元数据不存在必须由有效地图确认；天气用世界地图的规范 ID，不借用战斗天气。必要事实不明时不漏出部分的新进化就绪结果；旧就绪状态、治疗及其它有独立证据的变更由应用分别处理。
- 成功计划复制成员、保留原经验值，按目标成长曲线重算等级并重算 HP；原 HP 为 0 的仍是 0。学招意图先列目标的零级招式，再列重算后当前等级的招式。不执行普通升级的友好度、升级学招或链式进化检查。持有物消耗另按实际目标和当前所持校验。额外成员先检查队伍空间，满队不读取精灵球；未提供必需资源也不冒充没球。草稿没有正式 ID，普通球的库存身份由调用方明确提供。资源、图鉴、计数和正式实体 ID 由应用一起提交。石头／正式交换的玩家取消不会中断演出；技术终止不算玩家取消，纯函数不负责演出或写回。
- 目标形态先采用内容声明的 defaultForm，再采用非零目标条目或目标记录的形态，否则从旧形态开始按相应物种身份应用地区特例。地区特例只改旧形态 0 或 1；旧形态 ≥2 保留，不代表支持所有动态形态。战斗计量只用已核验的己方成员事实：有效要害逐次计数，直接伤害按实际失血累计，己方成员濒死只清伤害累计，不清要害累计。纯计量函数不能代替实战来源证据。
- 用例为 test-evolution-rules.cjs、test-evolution-success.cjs、test-evolution-commit.cjs 和 test-postbattle-evolution.cjs。对应夹具中的 METHOD-SUPPORT.csv 是方法登记；VECTOR-MAPPING.zh.md 解释断言映射。它们不证明窗口演出、宿主或完整场景都通过。
