# 飞行抵达失败的断言

测试在被测 VM 自己的 realm 中构造回调或清理阶段抛出的 Error，并保留对象身份。期望的短错误原因独立来自注入阶段，不从实际结果反推，也不接受多余的 “Error: ” 前缀。反例覆盖跨 realm 错误和理由不匹配。

失败与成功等待使用不同条件。失败时同时检查 Promise 已完成、失败类型、原因、原请求和回执、所有者、代次、原生地图数据、登记表、租约、序号、地图创建和移交状态。最多等待 140 帧。失败诊断只读缓存的观察值，输出有界的短字符串和布尔值，不序列化循环对象，也不再次调用恢复、确认、完成、回调或帧更新。包装必须透传原 Promise、返回值和异常对象。

显式重试之后走完整的原生空闲检查。固定天气随机数前缀不得重掷，测试辅助代码本身不消费业务随机数。合成的错误注入检查不能替代真实飞行、正式保存和宿主窗口验证。
