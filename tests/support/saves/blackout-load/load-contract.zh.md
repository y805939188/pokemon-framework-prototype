# 战败回程：正式保存与冷读档

`scripts/tests/f-load-current-production.test.cjs` 先生成存档，再让独立消费者从正式加载入口读取。每个消费者只接受本次运行、同一 family、同一构建绑定的生产者回执；核对物理摘要后以排他创建复制手动槽 8 和全局索引，不复用其他运行的存档。

生产者通过真实完成步、中毒和资源失败产生稳定的待回程状态，不手填 pendingReturn、owner、nonce、回执或到达确认。正式 onBeforeSave、框架快照检查、DataManager、JsonEx 和 pako 写入隔离文件系统。消费者通过 `Scene_Load.executeLoad(8)` 启动，覆盖直接恢复、版本变更触发原地图重载、真实目的地图失败及显式重试，以及旧 schema 存档的迁移恢复。稳定失败的观察门不要求成功 restore；稳定 12 帧也不能自动重试。

成功后的断言要求当前应用、读档代次、目标地图、场景、玩家、地图创建、实际 restore 完成及之后的 map update 属于同一条链。核对最终自动槽与全局索引、金钱、步数、战败统计、HP、checkpoint 清除、手动槽字节未变和业务/原生随机前缀。源场景、过期回执和旧代次不能完成新回程。

相邻的原生场景测试另外检查正常及无传送分支、返回后同一接收者、迟到和重复回执。负例可以调用旧接收者，不可手动触发新的正常接收者，或伪造保存请求。真实文件读写与业务入口属于本组覆盖范围；绘制、音频、物理输入和新 NW 窗口不在其中。
