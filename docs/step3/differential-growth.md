# 第一条 Ruby／TS 差分链：成长曲线（WP30-A）

**结论：3504 条原版实际运行的用例，TS 实现与原版逐条相同（0 条未解释差异，0 条分类差异）。** 这是本项目第一次有“原版运行”类证据（之前所有规格向量都只是推导期望）。范围仅限成长曲线这一个模块，不外推到其他模块。

## 怎么做的（隔离）
- **观察端**是单独会话（`observe-growth`），独立目录 `observation-growth/`（不在任何仓库里，不提交），读取并运行固定提交 `8c5911e4a4b07b07e832e4bb0d5d8859e88b4a9b` 的原版 Ruby；实现端（本会话）没有读过 Ruby、没有读过观察端的私有目录。
- 交接只有一个按固定 schema 生成、由观察端先自检再交付的**行为数据包**：`experiments/step3/reference/growth-cases.json`（只含输入、配置、结果种类/整数值、异常类名）、`decision-record.md`、`READY`（文件的 SHA-256）。实现端收到后先用同一个校验器机器校验（`validate-handoff.cjs`：schema、字段白名单、无自由文本、记录里无代码围栏/代码关键字），再读决策记录。
- 观察环境（见决策记录）：Ruby 3.1.3p185（用户态安装在观察端的私有目录，系统自带的 2.6.10 未动）；方法 `loaded-original-logic`，**没有任何替身**——原版文件原样加载，只有最大等级配置按进程不同。每个配置在固定提交和 v21.1 标签的导出上各跑一遍，结果逐条相同。
- 观察端报告的版本事实：固定提交是 v21.1 标签的后继（多 83 个文件），成长曲线源文件与标签、发行包逐字节相同（发行包仅换行不同）。因此结论对“固定提交 + 标签”都成立。

## 覆盖
六条曲线 × 四个函数（某等级最小经验、最大经验、经验加法钳制、经验→等级反查）；最大等级配置 50 / 100 / 101 / 105 / 120 / 200；等级 1..100 全表（600 个表值）、越界与钳制、表外登记公式（Erratic、Fluctuating 与表内分段不同）、阈值前后各一单位、非法输入（空/0/负）。证据类型全部为 `original-run`。

## 差异记录
- 第一次对照有 6 条不同：`levelFromExp(nil)`——原版抛 `NameError`，TS 却返回 1。原因是 JavaScript 里 `null >= 0` 为真，空值通过了“经验 ≥ 0”检查。**分类：TS 实现错误**，已修（显式要求数字）并保留回归；其余 3498 条第一次就相同。
- 规格的“静态推导场景”（WP30 §12.2：锚点、反查示例、Erratic=618,474 与 Fluctuating=20,505（max=101）、非单调、加法钳制、错误种类分列、默认钳制）逐项被原版实际输出证实：规格里这一节没有错误。
- 映射说明（环境差异，不算差异）：原版对非法等级“返回错误对象”（`ArgumentError`），TS 返回 `{ok:false}`；原版对空/负经验“抛 NameError”，TS 抛 `RangeError`。对照只比较结果种类。
