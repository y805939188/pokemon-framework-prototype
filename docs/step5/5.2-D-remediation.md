## 2. 产品缺陷 P-01（P1）：NW 跨上下文请求被 `nonplain-intent` 拒绝

**现象**：c544652 上，在真实 NW 0.117 宿主中修好 D-01 后，背包里选 Use 时，`target()` → `flushBrowse()` 发出的 browse 请求被拒绝，UI 显示 “Cannot continue: nonplain-intent” 并关闭。商店交易（U52-03）和队伍内使用（U52-04）同样失败。

**根因**：
- NW.js 中，`require` 加载的引擎运行在 Node 上下文，插件运行在 window 上下文，两者的 `Object.prototype` 不同。
- `semanticFingerprint` 只接受本上下文的 `Object.prototype` 或 null。因此插件构造的请求，以及 `PS_BattleFlow` 提供的物品世界 `{mapId}`，全部被判为非 plain。
- 实证：在真实 NW 中，引擎对象的原型与 window 的 `Object.prototype` 不同；window 中的对象字面量和 `JSON.parse` 结果都会抛出 `nonplain-intent`。
- VM 测试宿主（`inventory-ui-host.cjs`）对 `inventoryRequest`/`manage` 的请求先 `clone` 再传入，把这一点掩盖了。真实运行一直被阻塞，因此没有发现。

**影响**：真实游戏中，背包的使用、商店的买卖，以及所有经过 `inventoryRequest` 的操作都不可用。不涉及数据损坏：请求在提交前就被拒绝。5.1 的 `manage` 不做指纹，所以不受影响。

**最小修复**：`src/framework/rules/semantic.ts` 的 `plainPrototype` 把“任一上下文的 `Object.prototype`”视为 plain，判断依据是：
- 原型的原型为 null；
- 自有的 `constructor` 是名为 `Object` 的函数，且其 `prototype` 指回该原型；
- 全部只通过描述符读取。

以下拒绝都保留：类实例、Map、Date、非根原型、访问器、循环、非有限数。伪造的根原型中，构造函数名不是 `Object` 或 `prototype` 不回指的会被拒；名称和回指都伪造正确的 null 原型根会被接受（独立复核 F-08，已知并接受的边界）——指纹只读自有可枚举键，对结果没有影响，旧实现对 Proxy 包装的普通对象同样接受。同一上下文内的指纹值不变（复核差分 20000 例逐例一致），产品语义不变。

**VM 宿主保真**：去掉请求克隆，只保留方法绑定，让 VM UI 测试也走跨上下文路径。旧的 `semantic.ts` 在这条路径上会让 VM UI 测试失败，见反向用例 P-01。

**回归**：
- 跨上下文的 plain 数据与本地数据指纹相同；
- 跨上下文的非 plain 值仍被拒绝；
- 应用层的请求和物品世界都来自另一上下文时，可以提交、识别 duplicate 和 conflict，并只消费一次；
- 46 项 VM UI 测试在无克隆的情况下通过；
- 真实 U52-01…08 通过。
