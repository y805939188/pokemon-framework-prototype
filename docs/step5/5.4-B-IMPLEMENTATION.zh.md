## 生产数据流

1. `composition` 选择正常实际 Showdown 工厂，应用构造时封存该工厂来源；操作预留先建立 required 期待值，再读取宿主端口。应用的来源表、工厂根和当前期待记录使用原生私有字段，不能用调用者同名属性或 JSON 布尔降级。
2. Gateway 给实际 Pokemon 对象绑定稳定 ID，记录 C（当前）、I（还原）、R（回收）与有序变化。实际属性写入覆盖原语、直接赋值和嵌套消费；未知更改会使整份必需事实不可用，不返回成功空表。Illusion 显示名不参与寻址。
3. 终局（不要求有下一 request）由真实 ended driver 提供完整事实；会话私有封存绑定原 raw hash、generation、内容身份和同源 lineage。捕获只填写既有 v1 `member.item`，不新增冻结 v1 字段。Checkpoint 的来源、journal 和封存结果在私有不透明 token 表中恢复；静态恢复函数已封存，任意 JSON／另一场同状态不能重建来源。
4. 应用 fresh 准入验证来源和完整事实，将主战果、接收／仓储、C/I/R、两个奖金阶段、图鉴／成长、击败、统计合成一个 next，仅调用一次 StatePort.replace。零写失败沿原 owner/context 重试；部分／不可读安装保持 reload-required；完整安装后宿主失败不撤销、不再付钱。
5. Schema9 为已安装的新结果增加可选 `appliedBattles[id].settlement={version:1,pairHash}`。8→9 不伪造旧 pair、不改旧 raw hash／trainer／钱包。旧账本精确主 hash 重放与新配对冲突分别处理，已安装查询不补读新引擎事实。

应用只传递值和端口；本批规则／会话不依赖图片、布局或动画时长。可替换的正式战斗控制器及 AI 仍属后继批次，不由这些测试脚本实现。

## 兼容与所有安装入口

冻结 v1 纯 `applyBattleResult` 仍是规划器，不授予安装权限；普通 `GameStatePort.replace`／`SaveStore.save` 是已验证完整状态的宿主安装边界，不能把它们说成裸战果来源证明。

| 消费方 | 新 fresh 行为／迁移方式 |
| --- | --- |
| 正常 composition + `GameApplication.startBattle/startTrainerBattle` | 一律 required，双方初始空也不降级；实际工厂/操作/代次绑定 |
| `finishBattle`、`commitResult`、接收恢复、`PSFlow.commit` | 同一准入；未注册／脱离／退休／克隆 fresh 拒绝，调用者 legacy/required=false 无效；已安装精确查询保留 |
| 受信旧 create-only／匿名内容会话 | 在应用创建前显式选择 `createLegacyNoHeldSessionFactory` 或 `createLegacyNoHeldBattleSessionFactory`；两能力门必须关闭，实际双方与捕获均无物 |
| 受信旧同步结果生产者 | 在应用创建前 `createLegacyNoHeldResultFactory(producer)`；原 `commitResult` 输入与预选 producer 的结果 hash 对照，或用 `createLegacyNoHeldBattleHandle/commitLegacyNoHeldResult`。不能拿现有裸结果事后登记 |
| Node `new SaveStore(...).commit(raw)` | fresh 默认 unknown 拒绝；应用先安装完整配对候选到 store.save，之后原 raw 可精确查询 |
| 受信旧 Node 无持物生产者 | 在读取／提交前 `store.createLegacyNoHeldSaveStore(file,producer,...)`，拒绝带物、错生产者、重入及写前文件变化，保留原子备份／保存／重放语义 |

这明确改变未经来源预登记的裸 fresh 用法，**不宣称所有旧裸 JSON 行为完全兼容**。没有公开 legacy 布尔或缺方法自动 fallback。旧方法名与两类已安装查询保留；下一批不能通过选择旧适配器开启持物门。

历史纯／假适配器测试在 `legacy-test-support.cjs` 和 testing-only `createFixtureSaveStore` 中显式选择旧合成生产者，保留原业务、原子故障、PP 和回放断言。它们不证明正常 required 来源。旧 PP 带物匿名 Session 测试分别验证纯规划 PP 和完整状态保存，不再冒称其裸结果有 fresh 权限。新的 `test-held-app/engine/store` 不使用该旧应用 subclass。生产入口不导出这些测试源注册工具，testing/legacy 共用同一实现身份。

## 物品与奖金边界

普通消费清 C、C==I 才清 I，并记 R；Air Balloon 不记 R；Knock Off 临时清 C 保留 I；Bug Bite／Pluck／Incinerate 永久移除目标但不造回收记录。真实 Fling／Natural Gift 的直接赋值纳入 journal。野生永久获得／失去与训练家临时转移分开，Trick 的非对称 I 规则按批准规格保留。当前队伍用 I，换出已送盒的旧成员用 C，捕获入队／送盒用其实际 C。野生用户的 Thief/Covet/Knock Off 不移除，野生 Trick/Switcheroo 失败，与训练家对照测试分开。

有效 Gen8 的静态枚举读的是合并 mods 后的实际 Dex handlers（含嵌套 condition），不是根文件正则数量。当前清单在证据目录 `effective-gen8-audit/INVENTORY-r2.json`：128 个匹配 handler，122 属已处理的原语族，6 个受控拒绝路径；**不是 128 个运行通过**。Corrosive Gas、Sticky Barb、Magician、Pickpocket、Pickup 若产生未支持的变化则整场必需事实失败；五类单打实际负例及任意未知直接写入负例在 `test-held-engine.cjs`。Symbiosis 属本首版未支持的多席条件，不称已执行。它们不能被写成正常效果已完成或 silently unchanged；完整 WP50 行为不由本批替代。首次清单把 `===` 比较误记赋值，保留 r1 及更正，不把误报计为产品缺陷。

真实 Dex 给持物返回可选 canonical ID；已组装训练家／赠送和正常开战拒绝不能一致消费的别名，不在运行末尾猜修。护符金币、幸运熏香是规格定义的 RPG 物品描述，不存在于固定 Showdown 目录；框架明确提供这两项精确 ID 和实际入场资格 hook，无广泛“未知物可用”兜底。

护符按最初持物的玩家对象实际入场登记，不要求物有效；未上场者无资格。Happy Hour 取实际主要效果、只给玩家；成功 Pay Day 取当时等级累计，失败／保护不算。训练家奖金先 cap，Pay Day 再独立 cap；两阶段只计实际正收入、不报 +0，正常败战不领取，moneyGain=false 不规范化旧钱包。捕获接收 pending 时尚不安装或发奖金。
