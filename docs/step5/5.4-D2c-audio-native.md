媒体使用本机现有ffmpeg原生Vorbis编码器（该安装没有libvorbis），从明确频率、振幅1000、44100Hz PCM生成有效Ogg；编码器要求双声道，来源WAV为单声道后复制声道。v3媒体资格要求完整离线解码采样数、逐帧nb_samples总和与容器末granule精确一致，源采样数的编码填充差在一个实测编码帧内。首包priming PTS、逐包/逐帧连续性和末包duration另外校验，拒绝单个EOS音频页、时间戳缺口/下溢和截短数据。原生时长门收窄为容器granule对应时长±2个源样本，不按旧观测扩大范围；仍要求真实AudioBufferSourceNode/参数/偏移。offline decode不是NW验证。8秒ME合成夹具不变；故意损坏Ogg与确实缺失路径只用于负控。

驱动不替换AudioBuffer／AudioContext。取消、超时、接管场景对真实已解码buffer做受控ready通知延迟；记录原生对象和完整decoded元数据后才触发迟到控制，不把延迟控制称为自然解码慢。M02只延迟真实App创建完毕的Session返回；M09在MZ普通数据属性状态端口注入一次明确未写入的错误，原文档不动且显式单次retry，禁止自动重试到绿。

接收／图鉴／进化使用真实App+Session+根继续操作及公开API程序化回答，不声明完整管理、图鉴或进化UI验收；M15默认交接子例也用真实Session程序化终局，以保持原生ME仍在播放的窗口。其他正常战斗仍走实际Scene与合成DOM按键。M16通过真正Scene_Save观察slot/global落盘promise、完整状态／receipt／BGM登记；M17只能读取同轮生产报告hash和expected文件hash、同一隔离slot，正常Title/Continue/Scene_Load进入。不会写用户已有档，不把旧结果或旧APP转授新版本；MZ原有跨进程BGM恢复不承诺保持seek，战内回程单独严格核实际play偏移。

M13 的 abort 只退休自有音乐，不隐式恢复世界曲；回到同地图且没有transfer时也不假定MZ会autoplay。验证“abort保留Next预设”的下一场之前显式播放世界曲，不调用reset（会清掉待测预设）。未来预设不被旧战清理、abort保留本预设、正常消费后三项原断言全部保留。持续受控Scene回归直接执行M13的实际驱动动作块，并删除这一步做反向控制，缺前态必须在world回程断言失败；不能为了测试改生产abort规则。

地图实例已经 create 不代表已完成异步加载或 start。驱动的取消回图、夹具重置前后、load/newgame替换回图、正常读档与保存回图统一等待真实 Scene_Map 的 isStarted()、message window、spriteset 以及无待切场景，再允许后继 setup/transfer；不查询未初始化窗口的 busy、不吞宿主 fatal，也不通过固定多等几帧替代生命周期。持续回归执行实际驱动动作及安装宿主的 Map create/isReady/onMapLoaded/start/busy 方法，受控延迟地图 I/O 和 start；撤掉取消就绪门必须重现原 isClosing 异常。此为纯路径控制，不是 NW 实跑。驱动变化由新 Git HEAD、测试插件 hash 和新冻结输入/APP 绑定；v2 的六组17项、种子、业务输入和 M13 显式前态不变，旧失败包及其证据保留。

正常无tskip/rrui的冷启动先到Title。只有第一次reset额外允许已经start、命令窗open/active、非busy且无待转场的真实Scene_Title，随后由原toMapId发起测试地图过渡，再等待完整mapReady；这一许可消费后，后继reset仍必须从就绪Map开始。未ready Title或其他非Map场景不能借用此许可，不靠用户按键或开启skip-title。持续受控纯路径从真实Boot基础/后置Reactor及UI路由、实际System配置出发，执行真实Title/start、reset、toMapId和M01动作块的双战/取消/再次reset闭环，并检查未start、排队继任、后继Title、取消/超时传播与撤销首次许可的反向失败；音乐/session/renderer端口受控，只证明驱动可达性，不声称17项原生音频通过。

v3只改变测试资源分页：Ogg mux page_duration固定100000微秒，确保首个含有效granule的音频页先于EOS。原intro在首音频页即EOS时，离线出现起始PTS错误、末包duration下溢及多余trim；同PCM/同音频包重新分页后这些口径一致。此为夹具资格缺口与demux/decoder交互证据，不声称已核定冻结浏览器内部实现或发现产品播放缺陷。[Vorbis规范](https://xiph.org/vorbis/doc/Vorbis_I_spec.html)规定PCM位置及末页裁剪语义；[FFmpeg官方Ogg解析器](https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/libavformat/oggparsevorbis.c)可作分页/时间戳规则背景，不能替代固定宿主实测。新音频字节、v3元数据及收窄区间必须重新freeze和独立复审；原PCM、频率、请求时长、17项义务及seed不改，旧失败及资源不覆盖。

### 原生 loadGame 成功码与剩余尾部合同（ULTRA-06）

安装版 MZ 的 `DataManager.loadGame` 在 loadObject→createGameObjects→extractSaveContents→correctDataErrors 成功后 resolve **0**；PS_SaveState 的计数包装保留该值，内容验证错误还可能通过 `_psSaveError` 诊断。因此 M11 不使用真值判断：精确核0、无加载错误且有验证记录、完整已保存框架状态及BGM记录、新Game_System身份、旧app generation失效，以及应用/音乐owner释放。仍从真实隔离slot调用 loadGame，不直接extract替代；newgame子分支和迟到旧回调/新曲保护保持。M17也核加载诊断、同轮slot和固定产品身份。此为版本化纠正错误oracle，原断言的恢复目标保留并加强，不继续声称142条原文全不变。

M12的playBgm／M13的预设与abort／M14的None交接／M15的playMe与自然stopMe不以undefined返回判断成功，检查实际通道/播放次数/owner；M15的Session.chooseMove检查`ok`，终局才finish。M16的Scene_Save.executeSave按Promise fulfilled调用onSaveSuccess，无需truthy成功值，仍等待slot/global两个实际写入；M17的Scene_Load.executeLoad同样按fulfilled推进_loadSuccess，terminate后由Game_System.onAfterLoad恢复音频，不修改生产返回合同。

持续纯路径直接执行M11–M17实际动作块，并使用安装版DataManager、AudioManager、Scene_Save/Load/Title和编译PS_SaveState/PSFlow；解码、渲染、时钟、Session、存储codec/I/O受控。它验证尾部可达性和拒绝门，不代替NW自然解码/ME时长、真实压缩存档或新进程。合成producer报告仅供门测试，不能登记实际执行。成功链之外持续核I/O/提取失败、无效文档、非0返回、错误状态、写盘失败、不完整producer、hash/input/slot/存档字节变化、回放重复写及Continue改档；未持有同轮producer16全过/exit0/无fatal/冻结包核同不得启动consumer。旧2f单轮10过/1失败/6未运行、consumer未启和所有早期失败保留。
