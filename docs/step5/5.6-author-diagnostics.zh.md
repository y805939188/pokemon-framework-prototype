# 5.6 WP07：作者事件参数定位

本批补齐 `PS_Management` 的 `ShowChoices`、`ShowNumber`、`ShowTextInput` 三个作者入口。参数错误仍交给宿主停止执行，新增测试模式下的定位信息；正常命令与原生 MZ 事件的行为保持。

## 已有诊断盘点

| 消费入口 | 已有输出与调用前提 | 本批处理 |
| --- | --- | --- |
| 内容 CLI `build/check` | `file + JSON path + message`；坏 JSON、缺输入、schema、字段、来源门和旧产物均会失败。构建失败会按原合同使旧 compiled output 失效 | 复用，不增加文件层 |
| `loadCompiled/assembleContent` → `PSFlow.content()` | 校验错误含来源文件与字段；加载失败抛错，禁止退到 fixture；assembly 按记录/字段报告。宿主自己的内容读失败可含本机路径 | 保留原合同；本批不承诺全部宿主错误都已净化 |
| `ClaimGrant/HealParty`、各业务 UI | 既有拒绝结果、结果变量、局部 console 输出；具体调用前提不同，不能推导全模式统一诊断 | 不重写业务处理 |
| `PSFlow.logger` 与显式 debug/test 入口 | 战斗日志为 500 条内存环，写入时裁剪与家目录路径脱敏；`tail()` 显式读取。测试开关与失败注入已有消费者 | 不新建全局日志或上报；原脱敏不是凭据过滤保证 |
| 三个 WP17 作者命令 | 原来抛参数错误或 `JSON.parse` 异常；没有地图/事件/命令位置，坏 JSON 可能进入原异常文本 | 补本批诊断 |

依据：净化规格 `wp07-diagnostics-files-http.md` §5.1–5.3、§6 的受众与调用前提；工作区计划 5.6 的“作者可见的错误定位”子集。没有复制参考日志落盘、I/O 或 HTTP 行为。

## 作者如何找到并更正

1. 在 MZ 测试模式复现错误，按 F8 打开开发者工具，在 Console 查找 `PS_Management author command`。该输出只在宿主 `Utils.isOptionValid('test')` 为真时生成。
2. 读取 `command`、`field` 和 `hint`。定位用 `mapId`、`eventId`、`page`、`commandNumber`；页号和命令序号从 1 开始，命令序号包含宿主内部事件指令，应结合插件命令名查找。页号只在解释器列表与当前地图页列表同一对象时给出。
3. `commonEventId` 非空时打开数据库中的该公共事件。`eventId` 在公共事件里可以是继承的调用者 ID，不能据它认定错误在地图页。无法确认来源或缺少解释器位置时，相应字段记为 `null`，不猜来源；已有且有效的解释器位置仍会报告，不因脚本调用而一律置空。
4. 在事件插件命令里修正对应字段，重新测试。例如：`choicesZh` 使用 `["是","否"]`；`defaultIndex` 使用当前语言列表内从 0 开始的下标；`settings[0].value` 的 digits 操作使用 1–15；`maxLength` 使用 1–32；结果变量选择已有的非零变量 ID。`settings[n]` 的下标从 0 开始。

作者诊断只含固定插件/命令名、数值位置、固定参数字段和修改提示，不包含原始参数、玩家状态、原异常、堆栈或路径。每次失败只输出一条作者诊断；宿主仍打印一次固定安全错误并停止当前执行。普通运行只得到 `WP07-EVENT`（参数）或 `WP07-HOST`（入口宿主故障）和固定双语提示。未知宿主异常不伪装成参数错误。

三个命令之外的未捕获异常仍按各自现有合同处理。本批不挂接全局异常处理，不改变标题、新游戏/继续、任何存档、持久化配置、回程、计时或 5.5。

## 验证入口与边界

新增 `experiments/step5/6/test-author-diagnostics.cjs`，并前加到显式 regular 清单。它加载完整构建的 `PS_Management`，通过正式 Reactor `Game_Interpreter` → `PluginManager` 命令消费者及正式 `SceneManager.catchException/catchNormalError`，检查地图第二页第二指令、公共事件、未知脚本来源、JSON/范围错误、普通模式、未知宿主故障与正确输入。DOM、位图、设备和调度由夹具控制；这是 Node 宿主方法体消费证据，NW 窗口未执行。

定位信息只在失败分支读取。正确命令和后续空闲帧若读取诊断模式、地图页或公共事件数据库，反例会直接抛错；正常高频路径没有新增诊断扫描、文件写入、上报或每帧轮询。不是计时、尾延迟或 NW 帧率结论。
