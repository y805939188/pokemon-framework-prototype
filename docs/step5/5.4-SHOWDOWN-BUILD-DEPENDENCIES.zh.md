# 固定 Showdown 的构建依赖与类型门

固定上游仍为 `scripts/showdown.env` 的 Gen8 引擎提交，不修改其业务源码或锁。
`scripts/build-showdown.sh` 保持 `npm ci --omit=optional`，避免为了类型声明安装
SQLite 等服务器原生模块。现有必需的 esbuild 安装行为保留；构建工具不安装全部 optional。

上游 `lib/sql.ts` 的类型声明引用 `sql-template-strings`。私有构建清单
`scripts/showdown-build-deps/` 只锁定这一包的精确版本、官方 registry URL 与 SHA-512。
`prepare-showdown-build-deps.cjs` 在联网前核对实际 Git revision、仓库 pin、上游完整锁哈希
及两份锁的条目；不匹配立即拒绝，升级引擎时必须明确更新并复审这些绑定。

辅助清单在源码目录的同级临时目录安装，npm cache 也限定该临时目录，使用
`npm ci --ignore-scripts`。安装后拒绝额外依赖、生命周期脚本、链接或缺失声明，
再把单包复制到受控源码的 `node_modules`，不修改上游 package.json/package-lock.json，
不把临时 node_modules 分发到游戏或 SDK。只清理本次创建的临时目录。

正式脚本随后执行完整 `tsc --noEmit --incremental false`，通过才运行强制构建。
上游构建自身可能捕获声明错误，不能把它的 exit0 当作类型通过。
框架扩展缺失、tracked 源码被修改、npm/补包失败、类型检查或构建失败，均在替换旧 stage
之前停止。stage 复制过程仍沿用既有实现，本批不声明文件系统暂存替换具备事务原子性。

正常入口仍是先 `pnpm --dir src build:engine`，再 `scripts/build-showdown.sh`。
独立验证应设置自己的 `SHOWDOWN_SRC`，并用 `npm_config_cache` 指定独立缓存；
不要在别人正在复审或构建的源码/依赖/stage 上并发写入。

`node --test scripts/tests/showdown-build.test.cjs` 覆盖锁漂移、安装失败、缺包、链接、
重复准备，以及真实 shell/helper 的顺序和失败后旧 stage 保留。shell 组合测试使用
明确标注的受控 subprocess，不能代替真实 fresh-install。该套件已登记到 headless CI。
本批作者真实 fresh-install、重复构建、原始日志与运行包身份在工作区交接记录链接的证据目录，
其限定结论不预签独立 ultra、远端 CI、Windows 宿主、完整 C 或后两批。
