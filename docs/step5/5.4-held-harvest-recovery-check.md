# Harvest / Recycle 定向运行核对

最初 fec4e19 定向候选只新增测试并得到训练家 Harvest 写回反例；父端独立确认 HCHECK-01 后授权此局部修复。生产仅修改 held-tracker.ts 与 held-facts.ts，区分两种恢复语义并同步验证。README、全量测试清单、默认持物门、冻结 v1、一次安装和重放入口不改。原始产品基线 a4dc03c8e976467c78e9fa0d2e85189642ead10b，Showdown7244／Gen8。实际命令／结果／最终 H 在独立修复证据目录，不由本文预签。

已核现有 `test-held-engine.cjs` 只有真实 Recycle 的野生／训练家比较（seedState＋诊断 tie），`test-held-facts.cjs` 的 recycle 为构造数据；不存在直接 Harvest 用例。本新增不是用 Recycle 代替 Harvest，也不重复整个旧专项。

预期分别来自正式净化 WP49 §7 的 Harvest 与 WP47-B §5.2 的 RestoreUserConsumedItem。前者成功时空 I 补物，没有野生限定；后者仅野生战补空 I。WP20 §6.4 的普通消耗清相同 I，终局对玩家留队成员按可变 I 恢复。推导期望不是原版实际执行。

六案见 `experiments/step5/4/held-harvest-recovery-plan.json`：训练家／野生 Harvest、无 Harvest 消耗、Harvest 未消费、训练家／野生 Recycle。原生 Exeggutor 的隐藏 Harvest／普通 Chlorophyll 槽经实际组装数据验证。显式作者测试招式集合和低等级 Splash 对手不宣称自然学会表或真实游戏数据等价。

初始 HP 仅比满值少 1，随后真实 Rest 造成睡眠、Lum Berry 实际消费并治愈；Harvest 路径先真实 Sunny Day，排除概率重跑；最后 Psychic 真实击倒对手，不用 seedState、私有引擎写、诊断 tie 或结果注入。正常 required 工厂独立向 App 提供事实；测试终局读取的诊断事实副本从不提交给 App，不授予来源权限。验证提交前完整状态零写、一次安装与精确重放，再按冻结 WP 预期比较 I 和实际安装物。

最初反例与完整合成观察／失败 TAP 保留，六案机器输入及 WP 预期不改。本修复将真实 Harvest 恢复记为内部 `harvest` reason：取回对应 R 到空 C，清 R，空 I 在训练家／野生均补；非空 I 保留。`recycle` reason 继续仅野生补空 I。验证器按同一规则核对事件链，不以最终 C 兜底替换 I，也不重解释旧已安装账本。

新增 `test-held-harvest-facts.cjs` 验证恢复原因、非空 I、再次消费、错链拒绝及配对身份；实际 App 相邻 HG05 为 Trick 后取得／消费外来树果再 Harvest，保留自己的 Leftovers I；HG06 为 Harvest 后真实终局 Fling 再消费，物品不复活；HG07 为零写安装失败后原事实重试、一次安装及 handle/raw 精确重放。原六案及旧 HF／引擎／Store 回归共同验证，不为修复放宽其它变化族。

新持物源码改变运行包 hash／共享 chunk 名。完整无窗口回归首轮的状态磁盘四案、败战磁盘三案在旧产物身份门前失败，尚未执行对应业务；旧日志完整保留。两个专属 contracts JSON 只重绑 product／runtime 到本修复源提交的实际九产物，其它业务字段逐对象不变，worker 和断言不改。新绑定仍逐文件校验精确产物，不移除身份门。

本候选不涉及 NW、对照线、原版／私有数据、真实存档、依赖安装、远端 CI 或 main；独立复核前不得正式接受或推送。

首轮 2d6b3ee 的六案实际全部通过普通 Psychic 击倒，但作者误要求 `Session.currentRequest()` 在终局为 null，在 App finish／目标 I 预期前全部提前失败。生产 session.ts:420 只返回最后缓存请求，不保证终局清空。后继仅将这条辅助断言改为 driver ended＋真实对手 HP0＋终局轮无后继 request；计划输入、六案序列和 WP 还原／安装预期逐字保持。首轮完整 TAP／观察／源码身份保留，不当作六个产品缺陷。
