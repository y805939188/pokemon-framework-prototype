# Illusion participation identity correction

The former Session growth ledger inferred stable member IDs from public switch/faint nicknames. Illusion deliberately disguises those names; a legal Zoroark battle could award EXP/EV to the unused disguise or omit rewards for an opposing Zoroark.

Gateway now captures Pokemon identity synchronously at the pinned engine add call for switch, drag, replace and faint. Nested split-channel add calls are treated as one event. It pairs the resulting public events in order with this unbounded control stream and retains identities in a private WeakMap, not in event JSON. It does not reconstruct earlier identities from the final active roster. A mismatched source fails rather than silently assigning rewards to another member. The instance interception is non-enumerable and rebuilt on restore; checkpoint copies preserve queued bindings and pending facts.

Session uses that control identity for participation and faint rewards. A replace reveal does not start a new encounter or reset participants. Scripted drivers without the optional capability retain their existing explicit public-ID contract. Trainer AI and presentation still receive the original masked public events.

Validation: real App/Session/engine tests cover player and opponent Illusion, actual damage revealing Illusion, switch out/back, checkpoint restore, simultaneous opposing switches with queued-event restore, no public event metadata, abort zero installation and normal finish single installation. These are authored synthetic content tests, not original Ruby comparison or NW/input/audio/performance acceptance.

Author verification: 53 relevant Node tests passed (6 new Illusion cases plus existing Session and trainer-AI integration tests); framework typecheck, engine build and import boundaries passed. Independent review and integrated/full CI validation remain separate gates.
