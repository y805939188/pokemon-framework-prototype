# 5.4 Switch取消与败北策略一致性窄修

基于已独立限定接受且已正常发布的d96，先修普通玩家正常路径AUD-1：Switch提议Yes进入成员列表后，确认底部Cancel必须与BACK一样解析当前提议为No、继续对手派出、恢复有效行动请求；成员命令子菜单Cancel仍只返回成员列表。共用cancelPartyList承接原BACK逻辑，保留首次update确认防穿透、旧owner和输入锁，不修无独立证据的_bagRetry或重写控制器。

另修公开开发者入口R2的一致性：PSFlow.openBattle接受调用者对象；已有begin会复制请求传给App，App在首次外部回调/await前捕获canLose，宿主原来却在败北完成时重读可变对象。现在begin从同一个sessionRequest同步捕获布尔策略到该operation，宿主终局只读这份值，与App统计/治疗规则一致；不原地freeze/克隆替换调用者对象，request别名和storageFull既有写入保持。调用者在begin之前修改策略仍由双方按实际begin值捕获；begin之后改原对象或公开PSFlow.request不会改变已开战策略。App持久规则、v1、保存schema未改。本合同只处理已证实canLose消费，不泛化为全部请求字段不可变。

两个问题分别提交实现，同一插件单写者串行；反例测试在产品修改前固定eddbff8。原11项为4过7业务红：中英normal显式取消与首update三红、调用者/公开别名两方向策略变更四红；不变策略、普通MZ原args与begin前变更四正控。修后同11项通过。永久取消控制含原BACK/No/Set/强制替补、重复输入和一次最终安装；败北控制用真实App/Gen8和编译Scene，宿主窗口/音频/输入/转移端口受控，无NW/实际转移断言。

捕获ME旧headless当前源码hash精确重绑，不改原15计划/APP或弱化严格相等；不以此补历史实机。AUD-2的跨经验开关音乐现象已独审确认，但“无经验配置”与“因每战门未增长”的补曲合同未定，按用户默认音频优先级登记DEFERRED/OPEN，本批不改胜利曲条件或声称关闭。
