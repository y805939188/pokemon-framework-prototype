## A 定稿

1. **T7 兼容默认**：未知的获得时间、地点和方式显示“未知”。旧成员 Owner 显示保留的旧 `ot`（缺失才为 `player`）与公开 ID `00000`，注明“兼容默认，非历史记录”。不以今天或当前地图填历史。T7、方案 §3.2/§8.2 的冲突以此补充为准。P51-04/17 固定相同断言。
2. **接收呈现故障**：只有宿主明确报告 `scene-aborted` 或 `rebuild-failed` 才能触发同代次的兜底；时间流逝、重试次数、失焦均不能触发。正常询问档优先入队，否则送盒；强制入队档复用合法目标或从末位向前选合法替换，不能改成送走新成员。仍无合法计划时保持 pending 和保存锁。兜底的提交回执保留去向，下一次正常呈现通知具体成员及目标盒名/队伍；重试通知不再提交。P51-14 覆盖触发负例、强制档和通知。
3. **公开 API 兼容收窄**：带 `captured` 的 `GameApplication.commitResult` / `PSFlow.commit` 必须有同战斗、同代次、同成员 ID 的完整模板；缺失返回 `no-template`，全状态不变。旧无交互调用者缺接收决定时返回 `pending`；自动策略必须由调用者显式提供。原同步调用的真实测试须补模板/策略，不能跳过。API 文档和宿主例子在 E/H 同步。
4. **友好度**：存储及初始值保持 `0..Number.MAX_SAFE_INTEGER`，包括 256；本期不凭空增加上限。诊断可以报告内容实际最大初值，但不是拒绝阈值。引擎边界变换必须单独记录，不能覆盖持久值；256 往返探针不通过则停止该边界定稿。
5. **实体 ID**：保留全部既有 ID；新建使用 `M` 加 `nextMemberOrdinal` 的 base36 表示，18 字符上限、全成员碰撞检查；计数为规范十进制字符串。迁移扫描旧 ID 的所有十进制数字段，取最大值加一。模板预留只在内存，随接收提交推进计数。开发树/包测试改用实际 setup 返回的 ID，不依赖 `W1-1`。冻结协议、夹具、矩阵基线保持原字节。

## 数据与兼容合同

schema 5 只保存一份权威成员集合：有序 `party` 和 `storage`（40 盒，每盒 30 个 `Member|null` 固定槽）。旧扁平 `boxes` 迁移后删除。顶层新增 `player`、`nextMemberOrdinal`；保留 bag/money/dex/appliedBattles/claims/stats/steps。`MAX_PARTY_SIZE` 仍为 1–6，旧队伍超过配置但不超过 6 时保留，只拒绝新增。

`Member.id` 是唯一实体键；`species+form` 是内容键；`personalID` 为可碰撞 uint32。新增 Owner、独立的 `ownerCompatibilityDefault` 标注、来源、自然/隐藏选择槽及有效槽、异色状态、首招、标记、缎带和存放/放生守卫字段。新增资料经显式持久构造保留；战斗投影及捕获结果采用独立白名单，不扩冻结 v1 的 18 字段。schema 5 Owner 为权威，`ot` 只在旧档输入和战斗投影存在。

旧档只补缺项；PID 使用纯 SHA-256 `legacy-personal-id-v1` 域及成员原文确定生成，不使用位置、时钟或随机。既有可信性格/性别/特性保留；旧档缺异色补 false。玩家兼容默认为 `{id:0,name:'player',gender:2,language:2}`。4→5 依赖当前内容，不能以空对象替代缺失内容。迁移先在副本操作，失败不安装副本或写任意存档槽。

T1：超过 1200 只旧盒成员整次拒绝，返回 `capacity-exceeded` 与版本/partyCount/boxMemberCount/limit/路径，保留原文并阻断所有槽保存；该档本期不能继续游玩，本期没有恢复工具。恢复/导出只登记未来候选。T10：5.0 曾支持 `NUM_STORAGE_BOXES=1..1000`；本期内容编译和加载分别拒绝非 40，报告实际值及旧范围，CLI 失败退出，不半应用。修改配置不能绕过 T1。

整理链只记录 ID、权威来源位置、虚拟位置和预期目标，不保存成员副本。提交以最新状态复检后一次 replace；取消只丢弃移动意图。切盒/改名/墙纸/标记/持物/招式及缎带排序各自立即提交；P51-10a 必须证明放下、取消和复检失败均保留这些编辑。不增加普通操作的持久回执；有界内存 token 受代次限制，换档失效。待接收/暂持时阻断保存。

非持久能力 `allowHeldItemSources` 与 `allowExperimentalHeldItemBattle` 独立默认 false，四组合均测试，不进入玩家设置或存档。旧档持物保留且可取下；来源关闭时不能给予/新建带物，入战关闭时所有开战路径先拒绝带物。实验战斗开战/结果提示“战后持物写回未完成”，隔离测试目录，仍不实现持物真实写回。
