既有 Battle Style／Battle Effects 的 Options、makeData／applyData 和每战捕获已有受控回归，但配置保存尚未实际写文件。新测试编译本树 PS_BattleFlow、PS_SaveState、PS_SaveLocation，在受控 Options 外壳中执行安装宿主的原 ConfigManager、StorageManager、JsonEx、Window_Options 和 Scene_Options.terminate 方法。使用安装的 pako 压缩库和真实 fs，在每案新建的临时目录中保存 `config.rmmzsave`；再启动独立 Node 进程加载文件，检查两项战斗设置及原有选项／音量。

正常覆盖：中英选项切换 Set／Effects Off、关闭时恰好一次保存、第二次保存经原生备份替换、重新加载；无文件默认 Switch／On 且不创建文件；旧字段缺失及旧 battleEffects 字段迁移；损坏文件原生完成加载／保留默认且不改原字节。另一个受控 ENOSPC 在真实部分写入后抛出，核实际备份回滚、原拒绝值和新进程恢复旧配置，不冒称实际磁盘满或系统权限故障。

目录由编译 PS_SaveLocation 的 `--ps-save-dir` 路径选择产生。fs 观察器只允许该案目录和固定 config／backup 两文件，转调真实 fs；所有新临时目录由本套件释放，不访问项目 save、用户配置或玩家存档。ConfigManager 原有 fire-and-forget 返回值不改；测试在 PS_SaveState 安装完成后观察最外层 StorageManager promise，保留拒绝并显式等待。

参考 WP65-C 分离即时选项、游戏状态和落盘；这里遵循已登记的框架宿主差异：保留 MZ 原生 Options.terminate 配置保存责任，不把它宣称成原版选项退出落盘规则，也不新增游戏状态保存。与 WP65 全主导航无关。
