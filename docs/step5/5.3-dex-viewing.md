# 5.3 普通获得 Info、recent 与显式观看（E/F 核心接点）

基线：已接收 PR17/main80f622e 的获得登记。依据批准 r3 §5.2/§8.1，WP26 获得展示、WP31 §5.2 成功步骤8→9、WP62 与 WP66-B 的显式观看写入。本批不做正式 G/H 界面、M1 签收或实体键鼠测试。compiled3/author1/save7 和冻结 v1 不变。

## 主要结果与观看所有权

`PokedexOperation` 是有界、瞬态的图鉴专用操作，不是通用事务框架。没有第二份持久成员集合、工作流、派生可访问列表或新日志总线。`pendingPokedex.source` 固定为 installed；交换仍由原 TradeOperation 使用 trade-draft 投影，不能调用本入口提前写全局图鉴。

赠送/领取在主写前预留先前拥有、展示资格和精确 recent 外观。捕获将已接受完整模板的 capture intent 保留在同一私有 prepared plan；不能装入 owned 后再猜此前是否拥有。来源是合法主接收，不是敌队 seen 或新观测。普通进化在身体提交前捕获目标先前拥有，并在身体已完整安装后、学习之前保留后置屏障。额外体继续依既有原子提交登记；WP31 §5.3 只规定其登记，不凭空增加另一条 Info 提示。

预留阶段不暴露页面，仍持保存锁；主安装证明后才进入 message。宿主正常显示消息后显式提交 message-complete：只更新本实际个体的 lastSeen，然后进入 entry（Info）阶段。原 seen/owned/forms、捕获/击败/进化计数、经验、claim/资源不重做。close-entry 才处理下一条或恢复战后进化/学习。静默来源不展示；外来不问名但保留新种页资格；capture 不依赖 more-often 开关。

同 token/revision、操作对象与 generation 校验贯穿所有外部读写；resolve 互斥，迟到或重复答案拒绝。source owner 在主要安装→消息→recent→Info→学习之间连续存在。观察到内容改变后旧展示计划永久失效，A→B→A 不复活；内容暂不可读可以重试。这里的语义指纹仅绑定私有展示/编辑内容，**不提供任何战斗辅助事实权威**。

## 小写入与技术失败

观看写入保留完整 before/next，并校验实际写出的同一 next。零写只能 pending/retry；完整 next 已安装（包括写后抛错、失读后恢复）先于内容读取确认，不重复更新或消费。当前既非 before 也非 next 时保持锁要求读档；不能回装旧 before。

技术终止只能丢未安装观看意图，或承认完整 next 后结束；部分/不明不放锁。已获得成员、已提交战果/成长/进化身体都保留。源为进化时终止相同父后续，不能借确认身体自动学招；源为捕获时不自动启动尚未激活的战后进化。正常 close-entry 则继续原学习/后继。一旦消息已正常完成并写了 recent，退出不回滚 recent。

`updatePokedex` 仅四种显式命令：entitlement、unlock、view（region/mode/cursor/searchResults）、form。域由既有 F 纯规则负责；非法值零写。Forms 选择须真实可访问 species、内容性别规则和宿主明确提供的前图相等事实；多项首次打开/移动按正式规则写 false 异色 recent，单项不推导写入。BACK 或 render 不回滚。`pokedexSnapshot` 只读，返回分离的 dex/catalog/access/menu，不登记物种或改观看状态。搜索模式与结果游标的持久分叉保持 F 既定合同，不在本批重造搜索 UI。
