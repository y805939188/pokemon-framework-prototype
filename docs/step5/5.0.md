## 3. 做了什么

### 3.1 持久物种键（D5-3）

- **两种身份**：
  - **持久身份**：存档、图鉴、领取用“内容 ID＋形态号”（`Member.species` = 内容 ID，`Member.form` = 形态号）。
  - **战斗身份**：会话、引擎、冻结协议 v1 继续用 Showdown 名。
- **映射**：映射放在内容层。组装时生成两张表，`Content.forms`（内容 ID → 形态号 → Showdown 名）和反向的 `Content.speciesKeys`（`flow/content-runtime.ts`）。
  - 一个形态内容里没有时，回退基础形态（WP03 §3.2 Species）。
  - 夹具内容没有映射表：它的内容 ID 就是 Showdown 名，形态 0。
- **边界转换**（`app/game-application.ts`）：
  - **开战**：会话拿到“战斗视图”（`battleView`：成员换成 Showdown 名、去掉形态，图鉴换成各物种所有形态的 Showdown 名），存档对象不给会话。
  - **提交**：结果经内容映射写回（`applyBattleResult(..., keys)`）。捕获成员和图鉴记成内容 ID＋形态，名字映射不到时整个结果拒绝。
  - **协议**：协议 v1、矩阵基线、`custom-formats` 产物都没变。
- **幂等账本**：哈希按收到的原始结果计算，所以 schema 4 之前提交过的结果迁移后仍能识别（重复提交 `already-applied`，不同结果拒绝）。
- **内容形态记录**：`species.json` 的记录可以带 `form`：
  - （ID, 形态）唯一；
  - 每个 ID 必须有形态 0；
  - overlay 用 `species/<id>/<form>` 指向某个形态。
- **本批没做形态功能**：创建时形态、动态形态等在 5.1 及以后（计划 r3 5.1）。

### 3.2 存档 schema 4（`rules/save-schema.ts`）

- **新增字段**：
  - 成员 `form`（0–999）；
  - 图鉴记内容 ID；
  - `stats`：WP06 的 74 个字段。`gym_leader_attempts` 是 50 个 0，`times_to_get_badges` 是空数组，其余为 0；秒数字段可以带小数。
  - `steps`：0 到 2³¹−1。
- **3 → 4 迁移**：需要当前内容的物种映射。
  - **没有映射**：拒绝，代码 `needs-content`。
  - **名字映射不到内容 ID**：整次拒绝，代码 `unmapped-species`，列出每个位置（队伍、盒子、图鉴）。
  - 两种拒绝都不改输入，调用方保留原档。迁移成功时，统计和步数从 0 开始，并写进迁移说明。
- **插件**（`PS_SaveState`）：
  - **读档**：从 schema < 4 迁移时才取内容映射，内容读不了时拒绝并附上原因。
  - **拒绝时**：原始框架状态原样保留；再存档时写回的仍是原样，不会被覆盖。恢复界面在 5.6。

### 3.3 统计与计步（WP06 子集）

- **战斗统计**：
  - 在 `finishBattle` 的同一次提交里计数。
  - 重复提交不计；写入失败不计；没有战斗操作的直接提交（`commitResult`）不知道战斗种类，所以不计。
  - `canLose` 来自开战请求（插件传入）。
- **计步**：
  - `GameApplication.recordSteps(n)`：战斗进行中或状态不可用时拒绝。
  - 插件挂在 `Game_Player.increaseSteps` 上：先执行 MZ 自己的计步；强制移动路线或事件运行中不计。
  - 拒绝时每种原因只记一次警告。

### 3.4 数据来源（D5-2）

- **使用前核对门**（`content/compile.ts`）：
  - `sources.json` 的条目可以带 `usageCheck`，内容为核对日期、核对者、使用条件，以及决定（`use-allowed` / `internal-use` / `not-allowed`）。
  - 物种或领取记录引用的来源必须有核对记录，且决定不是 `not-allowed`。
  - 明确标为作者占位的来源不受阻塞；只登记、还没核对的来源可以列着，但不能被引用。
- **Showdown 条目**：已补核对记录，决定为 `internal-use`（开发与内部测试；能否分发在第七步按分发清单定）。这是项目流程记录，不是法律结论。
- **PBS 导入子集**（`content/pbs-import.ts`，命令见 [commands.md](commands.md)）：
  - **读取规则**（WP04 §4.2 子集）：
    - 首列 `#` 和空白行跳过；
    - 其他行删掉第一个 `#` 及之后的内容再修剪，所以缩进的注释在节内是非法行；
    - 节前出现属性报错；节 ID 重复拒绝；
    - 同名属性后值覆盖前值；
    - 带引号的值不在本子集内，直接拒绝。
  - **导入的字段**：GrowthRate、BaseExp、EVs（WP03 §5.3 具名对）、CatchRate（省略时取 255，WP03 §4.3）、Moves。
  - **报告里列出的字段**（每条记录分别列）：
    - Showdown 提供的字段；
    - 后续批次的字段，并标出批次；
    - schema 外的键（不消费，WP04 §4.2）；
    - 被覆盖的字段、采用的缺省。
  - **不臆造缺省**：其余字段缺失时报错，不臆造缺省值。
  - **CLI**：来源没有允许使用的核对记录时拒绝，什么都不写。
- **分发清单**：骨架见 [distribution.md](distribution.md)，从本批起同步更新，第七步发布前确认。

### 3.5 规则配置档（WP02 子集，`rules/config.ts`）

- **默认档**：Gen 8 默认档。作者在内容的可选 `settings.json` 里覆盖，编译时校验并定位到 `settings.json`；没有这个文件时，内容输入哈希不变。
- **校验范围**：
  - `MECHANICS_GENERATION` 只能是 8；
  - `MAX_PARTY_SIZE` 1–6；
  - 其他是框架自己支持的整数范围。
- **插件**：容量由配置档得出（`limitsOf`：盒子数 × 30）。内容加载失败时容量用默认值，好让新游戏仍能建立状态；战斗和领取会因为内容错误照常拒绝。
