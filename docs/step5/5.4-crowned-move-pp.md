# Crowned-form opening move PP repair

Scope: the pinned Gen 8 engine replaces Zacian's Iron Head with Behemoth Blade, and Zamazenta's Iron Head with Behemoth Bash, on battle start when holding the matching Rusted item. The upstream replacement also refills PP and changes the engine's permanent slot ID. Imported zero/low PP was therefore lost, item targeting by Iron Head failed, and the session could not write spent PP back.

## Contract and implementation

The clean specification `pokemon-rules/wp21-dynamic-forms-and-display.md`, §4.2 (battle-specific move changes and table F), requires preserving PP Up count and clamping current PP to the replacement's total. For Iron Head this means persistent caps 15/18/21/24, battle caps 5/6/7/8. Battle end returns the original identity with the remaining PP, not a refill.

The RPG format records only matching native opening candidates during `onBegin`. Persistent seeding updates that pending PP value. After the native species hook has actually replaced the slot, `onBattleStart` clamps PP and labels that permanent slot with its original identity before entry effects. The pending opening record is consumed. The marker stays with the slot through native serialization and switching; replacing the slot through learning discards it. No upstream code, global Dex data, save schema, or frozen result-v1 field changes.

The gateway uses that identity for state reads, PP-item lookup, seeding and identity-based learning replacement. It never infers a permanent identity from a transformed or Mimic live copy. The optional internal `MemberState.ppMax` carries battle caps for item eligibility only when an opening alias exists. Persistent individual caps and PP Up metadata remain unchanged, including Summary reordering and final writeback.

## Follow-up: growth keeps three species identities separate

The prior PP regression intentionally disabled EXP. A later independent review found a separate pre-existing omission: native Crowned startup replaces both `species` and `baseSpecies`, so neither remains the stored base-form identity. With EXP enabled, the first KO caused an attack/defense `stat mismatch`, for both same-level EV/EXP and level-up growth.

The gateway now derives the permanent growth basis from the original input `set.species` (including an explicitly authored Crowned input). The engine's `baseSpecies` remains the natural battle forme for switch-back and cached native stats, while `species` remains the current battle or Transform copy. Permanent stat projection and HP growth use the stored basis; displayed details keep the native base battle forme. This does not modify the original set, native form transitions, PP mapping, result schema, or copied Transform stats.

`test-crowned-growth.cjs` adds real App tests for both species, same-level/level-up growth, ordinary and Transformed battle states, Summary reorder plus PP items, checkpoint and switch-back, two-KO finish and idempotent commit, disabled EXP/abort, explicit Crowned input and growth without Iron Head. Existing Stance Change, Illusion, Transform and PP suites remain required affected checks. Runtime-bound integration fixture plans need their ordinary identity rebind for a newly built candidate before a full regular-suite acceptance; this code fix does not relabel old artifacts.
