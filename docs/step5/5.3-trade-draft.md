# 5.3 脚本交换草稿与观看提交（有限应用批次）

依据已批准r3 §5.3/§7.3/§8.1与正式WP26§4、WP32§6、WP67-B§5；与参考前缀失败不同的全草稿/最终一次提交已由D53-03批准，不重开选择。

- `beginTrade(requestId,intent)`先占owner后读state。outgoing按稳定ID与原位置、蛋/Shadow/cannotTrade及可选物种过滤共同谓词复核；cannotRelease不替代cannotTrade。前置offer可取消；正式演出及交换进化不可普通取消，技术结束独立表示。
- 收到物种以送出者等级创建；模板保留原等级/招式/PID，按来源合同改外来Owner、直接给定昵称（不套外来赠送截断）、获得方式2、当前首招。新的持物来源仍需既有开发门，不开放5.4。
- incoming的`draftKey`、纯成员、dex及学习历史只在应用私有草稿。view有`source:trade-draft`，普通全局图鉴仍读已安装state，view深拷贝只读。两个新种Info保存此前未拥有事实；消息确认后的open-entry仅在草稿写recent，收到者Info→交换进化→新种Info→学招→ready。普通进化器增加可选deferLearning内部后置屏障，只对本草稿启用，不制造战斗上下文。
- 交换族只扫一次，TradeSpecies沿已批自身种比较异常；party条件读原实队伍，不能把incoming偷加成队员。unknown/invalid可选进化事实只跳当前族并诊断，不失主交换；不晚补机会。
- 最终复核content/generation/送出ID位置/资源，incoming和所有额外体的私有标识映射全新实体ID，ordinal从实state推进，成本/body/dex/统计/旧槽替换一次安装。旧成员不送盒。最终前不预耗全局ordinal、不改实dex/库存或旧成员；双收尾不重复业务。
- 零写可重试同prepared next；完整写后抛错或失读回可证明后确认，不重抽RNG/编号/统计；部分写无法证明前后状态时保持锁要求读档。未写草稿可技术结束0新写，世代切换失效旧答复且不清新锁。完成回执在本应用代次内有界256，超过界限安全拒绝、不丢幂等凭据；新游戏/读档清代次。
- 根应用互斥包含独立学习、交换与正在准备的赠送/领取；背包在首读前保留进入期owner。所有进入期保留绑定generation，读档使旧回调失效，旧finally不能释放新owner；这只修复已复现的入口冲突，不重造通用流程框架。赠送/领取完整F登记及主安装证明仍按M1缺口继续接。
- MZ仅程序化桥与严格`psTrade`等待，菜单及直接保存读同一saveBlocked；正式G交换屏/图鉴页属于M1后。本批测试是实际领域答案/真实MZ自动化，不声称实体键鼠或正式UI完成。普通grant/捕获/进化的全局观看接点另在既定M1缺口表继续补齐。
