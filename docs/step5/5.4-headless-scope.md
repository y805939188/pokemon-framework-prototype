# 5.4 常规 headless 与发布验证范围

常规 CI、本轮发布验证和 `test-quick.sh` 使用 `test-headless.sh` 的 **regular** 清单。旧 `experiments/step3/test-growth-differential.cjs` 明确列入 `EXCLUDED_SUITES`，不进入 Node 测试循环。没有环境开关或自动入口参数可以启用该回放；未知范围／额外参数直接拒绝。runner 也会在构建前拒绝清单与排除项重叠。

排除不是测试内的 skip，更不是通过。日志单独打印 `EXCLUDED (NOT RUN)`；原测试、冻结输入、历史成功／失败记录和范围偏差记录保持。历史运行不得据此重写成未执行，历史技术绿也不能抵消越界。本改动不增加原版执行或对照覆盖。

## 清单与验证入口

以下两个命令仅列出路径，在引擎、依赖检查和任何测试之前退出：

```sh
bash scripts/test-headless.sh --list
bash scripts/test-headless.sh --list-exclusions
```

独立复审接受本候选且执行范围逐项核准后，常规发布验证入口为 `PF_NO_SKIP=1 bash scripts/test-headless.sh --scope=regular`；CI 使用同一显式参数。无参数本地入口等价。本作者批次只执行下列已审源码的合成控制，**没有执行完整 headless、产品套件、旧回放、NW 或对照业务**：

```sh
node --test --test-reporter=tap scripts/tests/headless-scope.test.cjs
bash -n scripts/test-headless.sh
```

新增控制只使用 Node 内置模块、读取 runner／workflow 文本、在自有临时目录运行 shell 替身。替身从不委派真实 Node／pnpm，清单中的套件仅记作字符串。它证明默认／显式范围选择、排除项防重入、无依赖列单、参数拒绝、构建前门和原失败门。它不证明产品套件通过或 Ubuntu CI 已执行。

原 `node --test` 循环及 exit、fail、cancelled 和 `PF_NO_SKIP=1` 检查保持原字节；正常选中测试的错误仍导致整个入口失败。除新控制登记和明确排除项外，既有清单顺序与条目保持。CI 的两个 job、依赖准备、构建步骤和禁止跳测条件保持。
