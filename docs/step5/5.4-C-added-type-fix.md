# 5.4 C：合法附加属性修复

审查基线为 `a4dc03c8e976467c78e9fa0d2e85189642ead10b`，固定 Showdown 为 `7244fe8e28fa8bc4d0809ae30d183c608b62bb2b`。本批只修正训练家 AI 的三属性快照和对手公开属性追踪，不变更锁定回合守卫、策略评分公式、招式效果、持久状态 schema 或协议 v1。

## 问题与修复

固定引擎的 `getTypes()` 包含基础属性和一个可替换的附加属性。森林诅咒或万圣夜命中双属性 NPC 后，实际会产生三个属性。旧 AI 快照校验最多接受两个，导致下一次普通 Session 行动抛出 `trainer-ai-invalid-public-snapshot`。反向由 NPC 对玩家使用这两招时，旧公开追踪截取末两个属性，丢掉第一个基础属性，可能错误计算免疫或倍率。

己方 `types` 与对手 `shownTypes` 现在允许 1–3 个合法且不重复的属性，精确 `???` 哨兵继续保持中性和无本属性加成语义。四属性、空列表、重复属性及未知值继续拒绝。评分仍使用原公式，对全部当前属性求倍率，本属性加成也包含合法第三属性。

公开追踪只从公开物种、`typechange` 和 `typeadd` 日志构造。内部将公开基础属性与当前附加属性分开保存；后一次 `typeadd` 替换前一次附加属性，`typechange` 清掉旧附加属性，换人重新建立公开物种属性。此内部状态随同源不透明检查点复制和恢复，不读取对手的真实属性、隐藏队伍或当前选择，不新增公开 DTO 字段或存档字段。

## 回归入口

既有 `experiments/step5/4/test-trainer-ai-remediation.cjs` 新增 17 项 `C-D2` 回归，沿用原测试清单，不更改 CI 或测试调度脚本：

- 两招分别经真实 App → Session → 固定引擎命中双属性 NPC，再执行下一次普通行动；
- NPC 反向施加两招后，公开属性保留两个基础属性及附加属性，暗影球仍尊重一般属性免疫；
- 双方连续替换附加属性、浸水改变基础属性、随后再次附加属性；
- 第三属性参与本属性加成；
- 玩家换出再换回时清除临时类型，并按新出场身份重建；
- 在普通基础类型和浸水后基础类型下恢复检查点，再执行替换，验证快照、引擎及 AI 重放一致；
- 诊断采集在对手私有 `getTypes()` 抛错时仍取得相同公开快照；
- 双方空列表、四属性、重复属性和未知属性在策略随机抽样前被拒绝。
