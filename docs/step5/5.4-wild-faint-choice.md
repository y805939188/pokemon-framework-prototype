# 野生单打倒下后的继续／逃跑接点

依据正式 D2、WP67-A §6.3 和 WP41 §5.1／7.1–7.2。基于已限定接受的 Encore 只读后继 0eaf；不依赖在审新学 PP 修复，不把该修复冒充已合入。

玩家场上成员实际倒下且有后备时，野生单打先问「使用下一只宝可梦吗？」。Yes 进入既有强制替补，根不能取消，成员命令与摘要仍可返回。No／BACK 尝试一次本次确认的替补逃跑；成功后走原结束确认与一次写回，确认前游戏文档不变。问题显示首 update 不接受同帧残留输入，忙碌与失效 owner 不再提交。

替补逃跑保留野生／禁逃门，跳过幽灵／必逃能力道具／束缚整组，使用当前未经速度修正的战斗副本速度及既有尝试数，不递增命令逃跑计数。复用原 escapeRate 和战斗 PRNG，不进入招式回合或让对手额外攻击。失败／禁逃重新发布同一强制替补请求，接着强制选人，不重复本次问题。训练家倒下及存活 U-turn 等仍直接选人。

Driver 新增可选 runAfterFaint(side)，true 表示已判定而非保证逃脱，不支持则拒绝。Session 复用 run 的可选 duringReplacement 参数。桥接只调用自有 custom-formats 扩展；限玩家单席、真实倒下、switch 请求且有后备，不改锁定上游或存档／结果 schema。

测试走真实 Gateway／Gen8／App／编译 Scene，覆盖中英 Yes／No、禁逃 BACK、强制取消、保存一次、训练家和 owner 对照，及累计尝试数、幽灵数值判定、无额外回合／PP。原强制替补测试先选新 Yes，原业务断言不改。幽灵控制只证明本次走数值计算，不宣称全部概率合同。

窗口／输入／字形／时钟／音频受控，无 APP／NW／真实字体／实体输入或整场 normal 证明。训练家换人风格提议、多席 UI、调试结局、完整 D2／E／5.4／P-4 与既有 LOW／WARN／UNKNOWN 均另验；PP 修复独审和后继整合继续独立。
