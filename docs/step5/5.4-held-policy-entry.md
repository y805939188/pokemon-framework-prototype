# 5.4 held-item admission consistency (N4)

## Defect and scope

At integration baseline `6eea4a3`, an author could mark a natively supported item such as `leftovers` as `Unholdable` and still compile/assemble a grant or trainer carrying it. Default acquisition correctly refused that item. An existing structurally valid saved holder could enter battle, temporarily transfer the item with Trick, and reach a capture whose strict final receipt then aborted. This is an admission mismatch, not permission to weaken capture settlement.

## Correction

- The pure compiler rejects known author-forbidden held references in grants and trainer parties, with the source file and item field.
- Runtime assembly, default item descriptors, and battle admission share the canonical native-item check narrowed by author rules. `Unholdable`, `Mail`, `KeyItem`, TM/HM flags and TM/HM field use remain forbidden, including case-insensitive flags. An author cannot make an unsupported native item holdable.
- Older saves remain loadable and unchanged. A forbidden saved holder is refused before creating a battle session. Management Take can return the item to the bag, preserving it and allowing battle again. No automatic deletion, schema migration, or save rewrite is introduced.
- Captured-member source validation and the existing player-item conservation settlement are unchanged. A permission change after battle admission can still abort final reception without a state write.

## Regression

`node --test experiments/step5/4/test-held-policy-entry.cjs` covers 30 synthetic Node tests: eight author restrictions at compiler and assembly entry, all eight old-save refusal/Take/reuse paths, default gift/grant refusal, changed trainer content, ordinary legal sources, actual Gen8 Trick/capture conservation, a still-strict final receipt, and canonical/native descriptors. The suite is registered in `scripts/test-headless.sh`.

The fixture uses authored synthetic content, default production application/session composition, isolated memory state, and the pinned installed engine. It does not launch NW, use player saves or private original source, or establish original-runtime equivalence. Author self-checks are not independent acceptance, CI, UI, or release approval.
