# H3 nonzero money through compressed MZ saves

This test-only addition is based on published 3c080ff / CI281. It does not change product code, the closed ordinary held-item gate, existing H3 cases, runtime contracts or shared test registration.

The existing independent pair chain covers money facts false/false/0. Existing B PD6 cases cover real nonzero money, two-stage capping and a JSON SaveStore. This addition connects two narrowly frozen nonzero-money cases to actual DataManager/StorageManager/JsonEx/pako and PS_SaveState compressed ordinary slots, a fresh Node process, a second real App/Gen8 trainer battle, and another save.

Both cases use an explicitly authored Snorlax level50 with Amulet Coin, Happy Hour then Pay Day, against one level5 Pidgey using Splash. No reference learning-set equivalence is claimed. Normal actual knockout, the unchanged authenticated required-facts factory and one App installation are used, without debug termination, seeded mid-battle expected states, or synthetic result injection. Read-only journal observation is not a new authority source.

Independent money expectations: trainer base20 × highest level5 × AmuletCoin2 × HappyHour2 =400; one successful Pay Day at level50 creates250, multiplied once to1000. The ordinary case starts at0 with cap5000 and ends at1400 then2800. The capped case starts at900 with cap1000: the trainer stage adds100, Pay Day adds0; the next battle adds0 in both stages. Statistics count actual positive income only, and zero Pay Day does not emit a gain notice. The first ledger is unchanged by the next battle and duplicate finish never adds money or a second install.

The independent existing H3 oracle uses Node crypto and its own canonical serializer. Both real battle facts/raw results, installed pairs, decoded compressed documents and first fresh loaded document are checked. Six detached-observation negative controls per case detect wrong nonzero facts, installed pair, decoded amount, loaded amount, next statistic and slot identity. These controls are not extra gameplay scenarios.

Use only explicit existing host/product roots and a new empty evidence directory, with the bound Node22.21.1:

  node experiments/step5/4/h3-money-slot-chain/run.cjs HOST_ROOT PRODUCT_ROOT EMPTY_EVIDENCE_DIRECTORY

The runner is serial and fail-stop, preserves each child's stdout/stderr/exit and its own synthetic saves, and does not retry, build, install, start NW or clean unrelated processes. Default capabilities are checked false before and after. Development capabilities are explicit solely for this controlled held-item test.

Boundaries: minimal nonrendering Game_* host objects, direct actual loadGame rather than rendered Title/Continue; no Boot/Map/Scene_Load lifecycle, pixel/font/audio/physical input, full stats/dex/evolution or final B-3/5.4 acceptance. No original comparison, private materials, real player saves, main merge or publication. The new test candidate must be frozen before execution and independently reviewed; actual results belong to the external versioned receipt, not this design note.
