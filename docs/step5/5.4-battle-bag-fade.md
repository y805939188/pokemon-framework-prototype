# 5.4 战斗背包正常画面过渡

本批继承已独立代码／受控Scene接受的训练家派出排序 `09ebc80c92f193e2f4910324a57d38c34b68429e`。依据冻结D2及WP67-A §5.1–5.2，补正常战斗背包画面隐藏／恢复：战斗→背包、背包→成员选择等目标层、目标取消→同一背包、关闭背包→战斗。物品Use/Cancel仍属于原背包层，不额外播放过渡；成员与招式子层沿原返回链。

默认使用简洁黑场过渡，每半程150ms（该项规格未规定精确时长）：旧画面淡出到全黑时才换画面，再淡入新画面。采用原已审私有遮罩资源适配器，覆盖实际画布宽高；只新建一个1×1私有Bitmap及其Sprite，不使用共享图片缓存，不改全局fade、音频或renderer。控制器拥有整个visual step；中途绘制新菜单时继续保持messages忙态和deactivate，队列结束后才重新开放相应菜单，原菜单与BattleBagSelection不重建。

每个Scene.update序号仅推进一次，重复采样不跳过后继阶段；帧时钟按现有performance.now。正常输入在整个过渡期间被现有controller拒绝，且原Use/Cancel首帧守卫保留。Battle Effects开关不取消菜单过渡；明确测试fast保留原零过渡合同，不作为正常时序或新性能证据。目标实际提交成功由原行动消息／动画接管，不新增一次“返回背包”或业务等待。

退出时恢复原战斗节点的visible值；遮罩本身不进入待隐藏节点。结束、取消、换档、终止或换画面异常释放本步的私有遮罩，过期步骤不能挂到后继场景；不吞原换画面失败。原资格查询、实际登记／消费、退款、库存／Session／持久结果合同不变。

真实App／Gen8 Session＋编译生产Scene回归覆盖：中英正常开关、半程可观察opacity、全黑才隐藏战斗、输入锁、同菜单／模型、单update重复采样、私有Bitmap单次释放、成员目标取消回原选中物品、真实用药单次消费、三种owner取消（含淡入期间终止）及渲染失败清理。绘制／时钟／输入仍是受控宿主，不声明新NW、原生像素／字体／实体输入或听感。

本批不实现完整对方目标高亮／战斗目标窗口、非内部入口、缺失move/direct实际效果、共享队伍／摘要完整入口或完整WP67§5。新APP、CI、实机、最终D2／E／5.4／P4仍须分别验收；原GC WARN、U51 UNKNOWN、旧FAIL/DEFER及93f发布拒绝HOLD保留。不修改既有冻结包／输入／旧证据，不合main或更新总进度网页。
