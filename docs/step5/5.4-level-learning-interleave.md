# 连续升级与对应等级学招交错

依据已冻结 WP67-A §7.1–7.2 及本轮 D2 成长范围：连续升级时，先完成该等级经验／升级文字及六维窗口，再处理该等级学招，之后继续后续等级。基线 `11af83f` 会先应用所有等级，等全部窗口后才处理所有学招；本批修复该正常流程。

保留原经验／EV／六维／HP 公式，先计算完整分配结果；将应用结果按有学招的等级分段放入既有 Session 成长队列。在当前等级应用后发布其只读投影，再进行对应学招。满槽决定未完成时，后续等级、HP 和能力尚不应用；恢复后保留已学习招式及其 PP，不用旧成员快照覆盖。空槽与已会分支沿用原处理，消息按等级交错；队列作为普通数据进入原 checkpoint／rollback。

GrowthDisplay 增加可选只读 experienceGained，用于跨决定分段时只宣布一次完整经验增量；旧投影无此字段仍用原差值。协议 v1 消息字段、BattleResult、保存 schema、AI／Switch 后继边界不变。持续游戏状态在最终 Continue 前仍不写入，结束只提交一次。

回归用合法初始等级和经验、真实 Gen8 击倒、编译生产 Scene 的中英 5→6→7 流程：第6级 Rest 替换 Growl 后，第7级可以重新学习 Growl；检查数据／原生能力同步、显示顺序、新招PP和单次安装。另覆盖拒绝、空槽、checkpoint 和 owner 中止。原不一致 EXP 的投影控制继续保留零长度区间，不为追绿改成员成长公式。

本批不补空槽消息前后两份招式写入时点、完整共享遗忘演出、升级公共动画／音效或新实机包。低影响视觉遗留保持原记录；完整成长／D2／5.4／E／P4、CI／NW及 GC WARN／U51 UNKNOWN 仍开放。E680 比较层整合不在本分支，不修改冻结来源或旧证据。
