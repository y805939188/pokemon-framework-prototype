# 5.3 获得登记与安装证明（E3 有限批）

本批将 F 的来源规则接到普通/静默/仅队伍/仅队伍静默/外来赠送及一次性领取，并为这些操作增加完整状态安装证明。不是完整 E3、M1 或 G/H 界面验收。

依据：批准整体 r3 §5.2、§8，正式 WP26 获得来源与 WP62 图鉴登记；5.1 已批准方案 §6.1 明确“仅队伍不自动改送仓库”的项目政策继续保留。两项持物门保持默认关闭。没有改变 compiled3、author1、save7 或冻结战斗协议 v1。

## 来源与身份

`rules/acquisition-dex.ts` 只生成分离的图鉴副本与每成员的首次拥有/页面资格意图，不安装状态或显示页面。普通、静默、外来接收用 receive，仅队伍交互用 party-gift，仅队伍静默用 party-silent，领取用 grant。GiftRequest 新增可选 seeForm（默认 true）；非布尔值在创建/随机前拒绝。领取固定登记形态。

普通/静默/仅队伍/外来会 seen+owned；party-silent 且 seeForm=false 只 owned。seeForm=true 使用 F 的命名形态/PokedexForm/无性别与异色规范化，完整 seenForms 和缺省 lastSeenForm 与成员同次安装。赠送不增加捕获或击败计数；没有历史的旧档不虚构历史。已有 lastSeen 不因普通登记而覆盖。

每成员在登记前捕获 previouslyOwned，并保留单独的 recent 外观（无性别可为 2）；同物种多成员只有首次可能给新页意图。该意图还需消息、seeForm、hasDex、已解锁地区匹配及 SHOW_NEW_SPECIES_POKEDEX_ENTRY_MORE_OFTEN。**意图不是页面已展示**。实际普通 Info/观看与展示时 recent 更新由后续有限批完成；本批不能签该项。

## 原子安装与恢复

应用在第一次外部读取前占有 acquisition 所有权并复制请求/选项；内容定义与生成成员私有保留。收集选择期间没有主写入；确认后以当时最新状态生成一个完整 next（成员/位置/ordinal/图鉴，以及领取资源/claim）。同时保存 before 和确定的选择摘要。prepared next 形成后不能改选或重新生成成员；重试不重抽随机。

原有接收失败反例：StatePort 已写入再抛错后，重复接收会 member-id-taken/丢失 applied 结果；StatePort 无声零写会错误报告 applied。本批以原始状态端口读取完整 before/next 身份，校验与实际安装均用同一私有 next：

| 观测 | 行为 |
| --- | --- |
| 完整 next 已安装，包括写后抛错或前次读回丢失 | 确认原 applied 结果，不再次接收/领取；此确认先于内容读取 |
| 当前仍精确 before，未实际安装 | 保持 pending、保存锁和同一 next，可重试；不报告 applied |
| 当前既非 before 也非 next，或读回不可得 | 保持锁，不能写旧 before 或补偿资源；明确等待恢复/读档 |
| 主机换档/新游戏导致 generation 改变 | 旧操作拒绝，不重新挂起旧接收、覆盖新档或清掉新所有者 |

内容语义指纹只绑定此私有获得计划，**不能作为战斗辅助事实可信身份的回退**。提交前重核内容和 before；实际观察到定义改变会永久废弃旧计划，即使 A→B→A。内容暂时不可读可重试。完整 next 已安装时仍能确认主要结果，不能因观测缺失丢掉领取或成员。

`terminateAcquisition(token)` 仅适用于当前获得接收：未尝试写或明确仍 before 可以技术终止，零写释放；已经完整 next 则确认安装、返回 already-installed；部分/不明返回 reload-required 并保持锁。同 token 的 resolve/terminate 在外部读取回调期间互斥，嵌套调用返回 reception-busy 且不释放保存锁；不存在返回 aborted 后旧栈继续安装。它不撤销正常获得、不退款，不终止战斗接收。PSFlow 只有薄桥接，没有正式 G 失败画面。
