## 内容与纯规则

`rules/item-families.ts` 把正式规格身份显式绑定到 family/parameters，不按显示名推断。省略 items 时的兼容目录增加规格派生的场外物品、真实 Premier/BoxLink 记录；名称 Unnamed、经济价格0是作者缺省，不能当原版价格。显式 items（包括空目录）仍完整覆盖，不暗补别名/赠品。WING 只在目录有记录时可用；21种薄荷默认身份引用25性格公式。重要物品有效不消费，普通 consumable=false 成功也不消费，仍需库存。

`content/item-input.ts` 在 JSON/compiled 两边校验已支持族参数的类型、必要值与枚举，先于 Dex；未知族保留不透明数据，ready=false，不能变成成功入口。没有扩大 PBS 为完整转换器。

`rules/item-effects.ts` 的 `itemUseLimit` / `planItemUse` 只读输入，返回 pending/cancelled 或完整副本计划。覆盖治疗/对症/全治/复活/全队圣灰、五种主动PP、PP提升、六项维生素/羽毛/WING/降EV树果、薄荷、胶囊/药膏、稀有与五档经验糖果。

- 药量配置及 Sitrus 动态向下取整；HP药/状态药不治疗濒死者，复活资格相反。圣灰只治疗主队伍濒死非蛋，不动盒子。
- 主动PP允许战外濒死成员，保持HP0；选招或全部招式实际无回复则不消费。提升记录随招式，0–3，当前PP按既有派生规则保持/钳至上限，不因提升补满。
- 培养按单项252/总510的增量额度，旧可信255不截断；维生素配置关100阈值，羽毛+1。每成功份友好；树果EV一次合并减少，友好逐份，数量取EV与含地图/球/铃模拟所需份数较大值。超出合法数量整次拒绝。
- 友好仅实现本批需要的方法；正增量先地图+1、豪华球+1、安抚铃×1.5向下取整、可选179软上限（evberry例外），负增量不套正修正。超界可信初值不修小；不能定义正常档位时拒绝该次效果。
- 薄荷确认后只写计算性格，表现性格/个人号/HP不改；以后糖果、战斗视图使用计算性格。特性效果的结果分别给 `candidate/requestedIndex/resolved/effectiveIndex`，不把提示候选等同实际解析。
- 稀有仅安全整数q1，两种多量配置均不开放q>1；一次L+1设置、经验下界、一次vitamin、扣1。经验糖果单位100/800/3000/10000/30000，数量上限向上折算至满级，合并一次EXP设置、共q次vitamin，支持同级增量。不计战斗EXP/机器教学统计。
- 道具HP B只在道具路径：存活按Δ保留至少1，濒死仅Δ>0恢复差量；稀有实际升级且基础HP1强制1，经验无此例外。HP培养按自身重算，不把普通非HP培养变成复活。
- TM/HM/TR、进化、世界/形态/融合等未就绪族返回not-ready/资格unknown、直调零消费。L100稀有返回evolution-not-ready，普通糖果不触发进化。真实通用学习/进化5.3，世界5.5，成员持物战斗门不变。

## 用药与最小学招

应用入口：`beginInventoryOperation('bag')` 或 `'item'`；队伍菜单使用 `'item',{token:managementToken,memberId}` 子操作。子操作绑定主队伍稳定ID及打开时的位置；移位/入盒/蛋/换档后拒绝，不能以旧下标写另一人。普通用药/丢弃/学招pending禁存；父操作暂停，关闭子操作只释放自己的锁。

`queryItemUse(token,itemId,q,memberId?)` 分开 ready 与 eligible/ineligible/unknown。已实现但尚未选目标返回 ready=true/unknown/target-required；已实现且目标合法返回 eligible，必要时 selection-required；机器等返回 ready=false/unknown/not-ready。查询在副本试算，不写资源、无RNG。

正式请求为 `inventoryRequest(token,requestId,{kind:'use-item',itemId,quantity,memberId?,ticket?,answers?},present?)`：

| 待选择 | answers 与返回 |
|---|---|
| 薄荷/特性确认 | confirmed:true继续，false取消；缺省返回kind:confirm |
| 单招PP/提升 | moveIndex为当前招式0起索引；缺省返回kind:move及只读副本 |
| 等级学招 | learning数组按answerIndex顺序；replace/slot0..3，或decline/giveUp |
| 取消遗忘选择 | G将BACK/第5新招映射decline；无giveUp返回kind:give-up；false重选同一招，true仅放弃此招继续队列 |
| HM | 来源于目录HM的move身份或可信世界端口；拒选返回hm-protected及同一answerIndex，名称与ID规范化后比较 |

按旧L<候选等级≤新L、内容顺序处理，每次检查**当前模拟招式**，因此先遗忘再重学同ID有效。空槽直接加入、PP满/提升0；保留其它旧记录。所有候选结束才一次replace，成长/HP/友好/招式/扣物同批安装。pending只存请求身份、修订及必要呈现信息，不保留整份GameState待回装。

每次答复重新读取最新状态、内容、世界和目标。队伍/库存修订或map/Shadow/Hyper/HM上下文改变时拒绝旧选择；钱等无关最新数据不被旧副本覆盖。普通学习循环不能用cancelled或confirmed:false跳过整队列；技术性关闭/换档清理可以终止未提交意图。正常放弃只针对一招。

`ItemWorldContext` 是应用持有的非持久只读端口：mapId、shadowIds、hyperIds、hmMoves。当前MZ组合仅提供当前map；没有新造Shadow/Hyper存档字段或开放其玩法，调用者不得把这些保护字段当可任意提交的请求答案。道具规划不使用RNG。

同会话相同requestId只缓存完成后的完整请求语义（包含最终answers），重呈现须重发同一完整请求。pending阶段允许答案变化但基础意图固定；成功后不同答案为request-conflict。安装失败不记成功，可重试；安装后呈现失败返回committed/failed，不重执行。256条内存回执、代次/ABA、关闭重开与claims/战果账本沿M1，没有普通持久回执。

## 钱店、选择与丢弃

`beginMoneyShop({shopId})` 从目录复制会话stock；或 `{stock,allowSell?}` 接管调用者普通可变数组。两者不能同时指定；allowSell显式参数优先。进入/购买成功后原地删除已持有的重要物品，退出不恢复；复用已删数组不会补回，全新数组才会重新包含。外部不得冻结/改坏已转交数组；安装前可发现的错误拒绝，安装后宿主破坏返回committed/failed并保留回执。

`shopView/ shopQuote` 只给副本和当前报价。`setShopPrices(token,id,buy,sell?)`：正买写买槽；显式非负卖写2×参数；否则正买令卖槽同买；其它条件保持旧槽。`clearShopPrices`显式清除；结束/换档自动清全部覆盖。买覆盖>0才用；卖覆盖≥0使用且0禁售。卖参数不是最终卖价，不能再隐含除2。

`inventoryRequest` 的 buy/sell 提交q与confirmed，可带 expectedPrice/expectedRevision。每次重检当前价格/资金/持有量/容量；未确认pending，false取消。普通买上限为余额/价与每槽上限取小，免费取每槽上限；重要固定1，已持有拒绝。G数量窗口初值1，出售不默认全卖。拒绝/取消/容量/replace故障无钱物统计部分写。

主商品完整规划后再算赠品空间；买球≥10且目录真实有Premier，慷慨开floor(q/10)，关仅普通球1。按实际赠品计数，主商品满袋不产生赠品，赠品不足不撤主交易。钱/物/花费/收入/件数/赠品统计同一次安装。提交后购买及赠品反馈失败不能回滚/重复交易。高初值出售的唯一暂停边界见EF-DEC-01；普通临cap出售如999950+100按49计收入。

`beginItemSelection(token,filter?,variableId?)` / `itemSelectionView` / `browseItemSelection` / `finishItemSelection` 提供普通及必要过滤只读选择。给谓词从选择游标1/0开始，不给沿持久原游标；移动只写运行选择游标，结束/取消不改原浏览状态。谓词收到深副本且必须同步返回boolean；调用期间拒绝重入资源写/结束owner。过滤后全空仍可取消。

选中返回selected/itemId，取消返回cancelled/空串；可选MZ变量为1..实际变量表最大有效编号，预检/写前均核对，未指定不写。变量端口失败可重试，不缓存虚假完成；旧变量回调不得清新会话选择。不仿真参考NONE/0/false/>5000怪癖，无PC/登记/专用列表/成对转换。

`tossItems(token,requestId,id,q,ticket,confirmed,before,present?)` 先查普通可丢弃、累计库存与票据；before正常返回/await完成后再次查最新票据、数量及代次，再一次删除。before失败不删，重要物品不丢；安装后present失败仍committed，重复不再显示前置成功消息或再删。异步期间阻止同owner资源操作；关闭后旧回调不影响新owner。

现有 `inventoryRequest` 的 add/remove-items、change-money、set-badge 与只读 queryBadges(index?) 是F作者用例的正式应用接口，普通add/remove无跨重启幂等承诺；一次剧情发放显式claimId或既有claimGrant。BoxLink走实际重要物品库存，非held来源；查询继续AND原开关35/地图/模式门。正式MZ命令/解释器等待和地图事件仍归G，不能把Node接口测试算宿主演示完成。
