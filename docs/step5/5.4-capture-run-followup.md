# 投球／逃跑后继整改（2026-11-13）

本批基于已按批准范围收尾的 `714b674`，是独立后继开发候选，不改写旧验收或历史失败，不合并 main。只处理普通玩家操作或合理作者配置可达的三个已核实问题；作者自测不等于独立接受。

## 范围与依据

- **A1 / P2：硬锁回合仍能登记背包、球或必逃。** 正式 WP40 的强制动作不能选择命令。固定 Gen8 Showdown 的已发布请求用唯一 `{move,id}`、无 PP／target 且 `trapped=true` 表达硬锁。网关资格查询与 RPG 动作登记共同读取这一事实；登记预检在清除原 choice／pending 之前完成，拒绝不能取消已暂存的合法续招。查询不运行 `getLockedMove`、`LockMove` 或 RNG 事件。普通单招受困、Struggle 与 Encore 不被当成硬锁。Session 在道具预留前拒绝；球／逃跑沿现有查询拒绝；Scene 主菜单入口经既有 controller 所有者和 `automatic-move` phase 自动提交合法续招。没有改协议 v1、快照宽合同或双打 UI。
- **B1 / P3：三种球已提供，但引擎未接上现有条件。** 正式 WP38 §4、WP48 §6：梦境球读取真实睡眠，或真实种族为 Komala 且持有 Comatose 的“视为睡眠”。冰冻不计该球专属倍率；Comatose 的真实空状态不会额外获得睡眠状态 ×2.5。甜蜜球读取己方场上未倒下成员的稳定种族族与真实性别，必须同种异性且双方有性别，后备不计；形态归同一 baseSpecies 规则族，不使用 Illusion 显示或 Transform 借来的种族。潜水球读取现有 `initialField.environment=underwater`。这三项引擎事实优先于调用者可选上下文，不新增世界 provider，不改球倍率或捕获公式。
- **C1 / P3：脱壳壳配野生黑色目光时，菜单放行逃跑但执行拒绝，白耗回合。** Run 查询补查现有 `volatiles.trapped`，与执行集合一致；Ghost／Run Away／Smoke Ball 仍在普通拘束判断前，脱壳壳不会变为必逃。

## 本轮复核修正与版本分层

- 初版新增自动入口还存在真实实现缺陷：从 `messages` 直接调用 `act` 会被 controller 的 `canChoose` 拒绝，可能软卡。本轮已按既有自动 Struggle 接缝先进入 `automatic-move` phase；不是把该缺陷归为资源或夹具错误。有效 Scene 回归覆盖从真实消息结束进入自动续招。
- 预检索引曾把“活位的 null spec”当成已登记动作，可能检查错座位。新增 null 前缀红测 32 项中 4 项失败，修成与实际登记一样只有动作 spec 才递增索引。非锁道具提示只做本轮硬锁守卫，保留既有目标／无效果／无请求登记拒绝和退款路径；协议冻结文件及其断言不改。
- 首个固定候选 `27d596e` 的 regular 全量真实 `exit=1`，280 套统计为 4988 通过、55 失败、取消／跳过均 0。若干文件在模块前置门停止，不能把该总数当成完整用例分母。缺现成 `js/libs` 资源、旧 Scene 手选硬锁 oracle、历史运行时／当前源 pin 和上述道具拒绝路径变化已分别定位；此结果原样保留，不回填成通过。
- 最后产品源码固定在 `5a41caf`，`src` 树 `7c52b29035f4170df493570c3a5d5e88eb1faaad`。后继测试使用独立的 `capture-run-current-headless-runtime.json`，静态绑定该源树、固定 Showdown、9 个引擎包、4 个当前插件及变更后的 support helper。测试不以实际值填充 expected，缺字段／哈希不符即失败；disk 与 H3 还核当前源树及暂存扩展。原有 plan、种子、用例、业务公式、旧运行时哈希及历史 native 绑定原字节保留，未变化的条目继续原门。当前 headless 源／插件适用不代表旧 15 场 native 被重新验收。
- 旧 cant／e1 测试改为观察实际 setup＋自动后继两轮。逐个消息 owner 仍要求整份 live 状态与动作计数在打字／停留期间不变，按键不能额外登记；每轮 cant 的真实打字和一秒停留、原始 protocol、全部描述顺序、PP、伤害、恢复完整招表及最终一次保存断言保留，没有删案或跳过。
