# 5.4 训练家替补提议：生产端口层

本批是SSO-v1的必要生产接点，不是Switch风格功能整体完成。基线d1c8bf7；PP c44、逃脱039、E914、复活a878另行冻结待审，未混入。

composition的`replacementOffers: true`是内部接线能力开关，仅正式单打训练家工厂可启用，启动捕获，默认false；现有Scene没有消费者时保持原自动替补流程。它不是玩家Switch/Set偏好，不意味着默认Switch/每战规则/玩家选项已接通。此后须在默认Scene接线批落实这些设置。

- 原生对方forceSwitch、己方wait时，在成长/学习处理完成后准备并固定原AI的一个后备选择，挂起真正提交；不是从UI重选或反复推理。仍用原source票据、策略版本、1000ms异步/取消边界和journal。
- 资格只读当前真实单打成员：首席存活、本轮未换入、有后备且无原生Outrage/Thrash/Petal Dance共有lockedmove。一般束缚不拦出提议；实际可选资格在隔离引擎副本重算native TrapPokemon，拒绝不修改原引擎/PRNG/choices。
- 公告在隔离副本执行原生switchIn前缀后读取公开物种，包括Illusion；不在未激活后备上直接调用会被忽略的能力事件，不暴露真实稳定ID。现有显示字典/完整身份桥和特殊交互仍由后继Scene整合验证。
- 伴随API `readTrainerReplacement`返回复制的投影和失效输入序号；`readTrainerReplacementTarget`查询实际换出/换入；`resolveTrainerReplacement(session, offerId, memberId|null)`提交Yes目标或No/列表取消。原Session公共prototype和协议消息/原因码不增。权限仍由私有source令牌和当前请求状态校验，序号不是来源权威；提交期间不暴露交互投影。
- 真正提交以受控原生instaswitch在已选对方替补之前执行，保留原生退场/登场及后续隐患处理，不手工改HP/active/PP。No不加己方动作。canSwitch=false仍能看到投影，但不能提交可选换人，可以No。
- checkpoint恢复已准备计划而不再推理；恢复后生成新的输入序号，旧输入/其它会话序号拒绝。提交失败沿Session原子回滚恢复私有队列与准备权利；abort/load等工厂退役取消旧owner/迟到AI，不碰新owner。普通`Session.cancel()`仍仅撤销普通暂存命令，不等同本提议的No。

测试用真实正式App/AI/Gen8，不覆写自动替补方法、不向队列注入测试动作；覆盖Yes/No到一次最终安装、只读重复查询、实际Ingrain/Outrage/同轮换人、默认关闭、无后备、Illusion、过期/跨会话、checkpoint、真实内容端口提交失败回滚与异步取消。原SSO-v1的测试shim仅是旧可行性证据，未搬入产品消费者。

当前仍未接默认Scene的中英确认/队伍Summary/渲染等待、规则与玩家选项；没有APP/NW/实体输入/完整normal/P4/CI或完整D2结论。独立代码复核和之后组合/NW另行门控，不把端口绿写成玩家功能已完成。保留全部历史FAIL/LOW/DEFER/GC WARN/U51 UNKNOWN。
