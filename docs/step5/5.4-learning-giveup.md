# 5.4 满槽学招的取消与放弃确认

本增量独立继承1943edb，依据冻结D-2与WP67-A §7.2的遗忘画面取消分支。复用当前默认招式选择器，不依赖摘要或状态框后继分支，不声称完成整个学招界面。

在满槽学招列表按BACK，或选择原“不学习”行，都先显示“是否放弃学习”的中英问题。沿用已有逐字brief与controller输入锁，文字全显后才开放Yes／No，初始Yes；显示问题的同一次Scene.update不能顺带接受答案。No／BACK返回原招式列表及游标，可反复选择；这期间不调用decideLearn，不改工作个体、引擎招式或持久状态。确认Yes才经原controller.run调用decideLearn(null)，显示未学会消息后继续既有成长／结算。直接选旧招仍走既有真实替换，固定Gen8 PP不改。

问题保存当前pending对象及所选行，不保存／恢复新的业务状态。owner取消、换档、terminate沿既有controller与brief生命周期清理，旧答案不能提交后继任务。只有战末原Continue实际提交主战果，不能把确认放弃当成存档提交。没有新增事务、协议v1字段、Session方法、RNG或领域规则。

当前通用测试驱动明确操作新确认，不把等待等同于自动放弃；原历史a612 helper夹具及其哈希保持。新编译Scene测试覆盖中英取消／No／BACK反复、默认Yes、同帧输入、保留学习与实际替换、确认放弃后的单次最终安装、取消／换档／terminate及正常逐字期间输入锁。Window／输入／绘制／时钟受控，不是NW／实体按键／字体像素。

满槽初始“是否遗忘来学习”的确认、共享摘要遗忘界面、HM守卫、逐级学习交错与完整消息／成长演出仍OPEN，不把本取消分支宣称为完整WP67-A §7。其它摘要／状态框组合、完整队伍、canSwitch显示门、替补提议、野生继续逃跑、D2/E/5.4/P4、GC WARN／U51 UNKNOWN与旧FAIL／DEFER保持。默认轻微UI差异不扩大打磨；无新APP、NW或网页更新，不合main。
