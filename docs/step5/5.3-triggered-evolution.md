# 5.3 E3 糖果、进化石和编号事件：有限应用批次

基于已接收 EggMoves compiled3 / author1 / save7；不改变冻结战斗协议，不含交换、观看、正式 G/H 屏幕或完整 M1。

- `GameApplication.beginEvolutionItem(parentToken, requestId, {itemId,memberId,quantity})` 需要真实 Bag/Party 背包父令牌；同父最多256次请求，重复相同请求回原结果，冲突拒绝，不用持久流程账本。
- 普通糖果先完成全部升级学招问答，再一次安装成长、友好度和消耗。随后只扫描升级族；缺失/非法事实跳过这次进化而保留已提交成长，重复请求不补发机会。
- 满级稀有糖果只有配置允许、数量1且升级族有合法目标时才进入；unknown/invalid/无目标零消耗、不启动进化。进入后消耗1，普通取消不返还，不改变经验或友好度。
- 石头用明确 `evolution` 空参数效果族或 EvolutionStone flag；普通取消拒绝。道具消耗和完整进化提交同一次安装；技术失败或终止不伪装普通取消。预检与实际写入均先计石头消耗，再计算额外成员资源，保证两个阶段语义一致。
- 编号事件全队先快照非蛋且HP>0成员ID；单体入口不额外加濒死门。编号可以再次使用，matched与evolved分开返回。逐成员读取当前队伍，每个原ID只处理一次，不对刚进化的成员或额外成员连锁重扫；各成员独立子令牌，迟到回答不能作用于下一成员。
- 糖果全部升级问题复用已接收C学习队列：只放弃本招、HM不可替换、重新选择与彻底放弃分别处理。Held/ball作者别名以目录battleId解析 Everstone、Soothe Bell及Luxury Ball的规则事实，保留持久内容ID，不开启5.4持物战斗门。
- 内部 SelectedEvolutionSeed 只供拥有者保留单个真实目标，绝不伪造战斗上下文。共享进化提交/学招/取消/可控技术终止保持已有合同；读取回调前占有动作锁，成长到演进之间连续禁存。零写可重试，完整写后抛错仍按已安装处理，部分写或无法证明前/后状态时保持锁要求读档，世代切换清旧所有者。
- MZ桥提供同名程序化入口和严格令牌绑定 `psEvolutionAction` 等待；正式图形交互与旧5.2背包Use分派的全量替换属于G，在M1前不把API自动化标成正式UI验收。
