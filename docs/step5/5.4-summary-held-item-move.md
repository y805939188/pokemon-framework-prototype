# Summary held-item move routing

Claude F-2 identified a real menu no-op: Summary → Item → Move stored the
selection on the summary view, although only party/box/panel views consume it.

The move now returns to that summary's owning target list, retaining the stable
member reference and expected item. Existing list cursor restoration and input
boundary handling are reused. A standalone summary has no target list, so it
does not offer Move; Give and Take remain available. No item transaction occurs
until target confirmation. No battle, persistence, or item rule is changed.

The existing compiled production management-menu suite now covers summary and
direct routes for party, box and deposit panel, each with an empty-handed and an
already-equipped target. It checks cancellation, declined confirmation, the
stable source, unchanged inventory, and a single successful install. The suite
is already registered in test-headless.sh.

Author verification on Node 22.21.1: focused menu suite 14/14; existing management
rules/input/query/UI suites 71/71; complete plugin/framework typecheck passed.
The initial pre-fix menu run failed all seven summary cases. An intermediate
test used down instead of right in the two-column panel and was corrected;
that intermediate failure was not a product fix. Initial direct tsc with a
symlinked vendor dependency duplicated DOM declarations; independent vendor
copy plus the normal typecheck preparation passed.

This is a compiled-plugin simulated-host test, not NW or physical-input
acceptance. No complete 5.4 acceptance or publication is claimed.
