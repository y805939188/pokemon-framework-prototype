## 已发布物品口袋的兼容建议与只读诊断

同ID物品的`pocket`既决定新获得物品落袋，也决定默认袋数量、删除/使用/战斗投影。已有存档行保持其原袋。合法`replaceItemId`本来就允许新ID留在原袋，不能把所有非默认袋行一律拒绝或搬回去。

**本轮推荐**：对已有玩家存档的发行版，保持已发布物品ID的默认口袋稳定；修改前先比较发布时保留的显式`items.json`。如果确需改变，先另行评审兼容策略。本轮没有批准读档拒绝或自动迁移；旧档依旧按当前合同可读，原行不动。已有旧袋数量在新默认袋不可消费这一限制仍在，只读警告不会“修复”玩家存档；需要迁移/转换时另作决定，不能伪称本轮已解决所有历史兼容问题。

构建后的工具（不启动MZ）：

```bash
node js/engine/build/content-cli.cjs check-item-pockets --src=content/sample --previous-items=/absolute/path/to/published-items.json
```

- `--previous-items`必须是旧发行版明确保存的物品JSON数组，不是玩家存档；不能从缺失旧目录推断历史口袋。旧字段省略按既有目录默认规则规范化。
- 当前输入先经现有完整内容/来源门校验；旧文件只用于元数据比较，不作为内容导入或游戏输入。
- 同时存在于两版目录、同ID且口袋变化时输出`WARNING item-pocket-changed`，含ID、旧/新口袋和路径；stdout为JSON。正常比较退出0（包括有警告），错误输入退出1，缺少必需参数退出2。
- 工具只读，不创建/改写编译输出、基线或存档，不触发自动迁移、排序或截断；现有`build/check`行为不变。
- 改名/价格/行序变化不会冒充口袋变化；新增或移除的ID、别名映射、无旧目录的历史及具体存档兼容性不在该比较的证明范围内。没有警告不等于存档全面兼容。使用旧版fallback目录时，应先保留那一版的显式有效物品目录快照。
