状态：作者观测与假适配器提案，**不是正式写回实现**。正常持物战斗在5.4完成写回验收前保持关闭。`allowHeldItemSources`与`allowExperimentalHeldItemBattle`为两个独立、非持久、默认false的开发者能力，不进正式插件配置。实验战斗显著提示“战后持物写回未完成”。

## 固定引擎观察

`experiments/step5/1/probes/held-P2.cjs`先核对样例来源许可，再启动固定Showdown构建、gen8rpgcustomgame、seed[1,2,3,4]，只在工具内使用私有oracle交叉核对。本期准备原始记录在workspace `.verify/step5-1-G-preparation/P2-observed-3.json`，有精确引擎SHA、工作树状态与完整事件；正式固定候选还要重跑并记新SHA。

| 场景 | 原始事件判据 | 次回合公开request | 观察结论 |
|---|---|---|---|
| Snorlax腹鼓触发Sitrus | `-enditem ... [eat]` | item为空 | 可辨认消耗 |
| Knock Off | `-enditem ... [from] move: Knock Off` | 目标item为空 | 可与消耗区分 |
| 野生Thief | `-enditem`及`-item ... [from] move: Thief` | 双方item变化 | 可辨认转移及来源 |
| Trick | 双方`-item ... [from] move: Trick` | 两方持物交换 | 可观察交换，不能单凭事件决定RPG永久归属 |
| Fling | `-enditem ... [from] move: Fling` | 使用者item为空 | 可辨认主动失去 |

公开`readState`没有item；`awaitingChoice(side).side.pokemon[].item`只在有request时可用。终局没有下一request，不能把缺查询当成空物品。未来适配器需在每次变化和终局保存受控item快照，并证明完整覆盖。现有flow/UI不访问私有引擎，不把工具oracle升级为生产端口。本观测不声称所有道具/能力/换位事件都已覆盖。

首轮探针先遗漏team preview，后Sitrus夹具奇数HP在腹鼓后高于半血，均为探针设置错误。改为先选队、4HP EV得到偶数HP后成功，保留准备日志；没有改引擎阈值来获得绿灯。

## 建议的独立结果能力（不改v1）

建议未来通过显式协商的独立扩展`heldItems`，而非给冻结BattleResult v1悄加item字段：

- 每成员按稳定`memberId`保存`initialItem`、`currentItem`、`restoreItem`，不能以当时队伍索引寻址。
- 变化记录`eventId/memberId/previous/current/reason/sourceId?/targetId?/turn/sequence`，reason至少区分消耗、主动失去、暂时打落、野生获得、转移。未知reason或身份缺失整次拒绝；不从“当前为空”推断消耗。
- 吃掉初始树果：current清空，匹配恢复项同时清空；Knock Off：current清空，原恢复项保留；野生偷得物：current/restore按明确RPG规则更新。Fling主动失去按明确损失处理。
- Trick/交换可观测，但永久归属、训练师偷窃、能力交换等长尾仍须逐项对WP50正式规格建表。假模型对未定转移**明确拒绝**，本期不擅定所有交换永久性。遇三大类无法区分才按D5-14上报停止契约定稿；当前样例三类可以区分，长尾和终局仍是5.4的进入条件。
- 捕获入队后注册该新成员的恢复资格；捕获送盒、满队换出老成员时先写各自当时current，随后移除该ID的队伍恢复资格，不能写到替换槽的新成员。
- 核心准备完整next-state后一次安装；背包/成员/持物一起校验，未知ID/重复eventId/过期previous/不支持能力整次拒绝。结果按battleId幂等，重复结果不重复消耗/获得，安装失败可重试原结果。
- 老消费者只接受冻结v1，不消费未协商扩展；缺扩展时持物来源和正常带物战斗继续关，不以空对象兜底。旧档可信已有持物可以取下安全回包。
