# P-4强制替补来源：建议冻结的最小实施合同

本附件是独立审查给中央的技术建议，随本报告限域接受为计划；不是已实现接口或实际发生证据。固定产品`c6ce3e63f7946d396ad6d3fac168a648c6593367`。第一批只需支持当前Gen8单打的**p1强制替补请求**，不扩为所有请求的通用平台。中央采纳本附件后，可直接实施这一小seam并交独立复验，无需另起大方案轮次。

## 1. 真实发生与重发

在每个实际Battle实例上、`setPlayer`前装配私有来源跟踪；恢复出的新实例同样重新装配且每实例只装一次。可用的具体接点是固定Showdown `Battle.makeRequest`成功完成后：只有调用来自真实引擎推进，并且新activeRequest确为p1的`forceSwitch.some(Boolean)`，才创建新发生。该方法的真实switch调用位于本次固定`dist/sim/battle.js:2398`，不是消息`seq`或呈现菜单。不修改上游源码或共享prototype；元数据放适配器私有状态，包装原方法须保持返回值、this、异常和调用次数。

网关`refreshRequests`本身也会调用`makeRequest`，故必须有**网关私有、同步、finally复位的technical-refresh范围**，使这一路径只沿用已知同一pending发生，不分配新号。不能从payload字段或调用者传入JSON来声明“真实发生”。没有旧可信来源、或刷新后不再是该强制请求，来源明确不可用，不能补造。该范围内不执行额外引擎推进或用户回调。

`Side.emitRequest`、`sendUpdates`、安全拒绝后的updatedRequest、普通读取和菜单显示仅为发送或观察；它们不铸号。一次真实新请求即使与前次payload/turn相同也换号；同一pending强制替补在成长刷新、失败逃跑刷新或错误提示后保号。转为普通move/team/wait、请求清除、完成选择、终局或关闭时，不再公开“当前可选择”的强制来源；撤回/重新打开同一选择也不虚构新的引擎发生，旧本地承接应退休，重新建立实际相邻选择证据。

推荐可选内部头，而非Showdown业务payload的新字段：

```text
source?: {
  version: 'player-forced-choice-source-v1',
  side: 'p1',
  occurrenceId: string
}
```

`occurrenceId`由受信适配器私有来源域和计数组成，可用进程内独立计数，不使用战斗RNG、时间、seq、turn、payload hash或对象地址。只要求本轮会话/恢复生命周期的可追溯唯一性，不增加跨进程持久身份承诺。恢复后旧checkpoint occurrence原样保留；后续真实新发生须用不会与废弃分支新发生碰撞的分配域/计数（例如新Gateway分配域）。诊断delivery标签可选，不承担发生身份。

## 2. 检查点和恢复代际

不透明driver checkpoint以私有companion保存当前逻辑来源，和对应request/queue一致；不从原始snapshot字符串重建来源。旧/外来snapshot没有该companion时，来源不可用，直到后来真实引擎创建新请求。旧队列消息必须重绑到这次Session视图，不能带回旧观察权限。

Session另有**不可被checkpoint回滚的`requestViewEpoch`及来源可用状态**。不得复用每动作都变化、内部rollback又可能不变化的`_operationEpoch`。通过现有只读checkpoint/owner预检并决定实际进入restore后，在首次状态变更或await之前：增加view epoch，置RESTORING，退休所有旧normal observer/forced-selection承接。无效token在只读预检即拒绝，不必破坏仍合法观察。

只有引擎、Session、AI、replacement/presentation等现有恢复步骤全部成功，才原子发布“checkpoint原逻辑occurrence + 新view epoch”。恢复失败保持UNAVAILABLE；不能因为`finally`清了`_restoring`就重露旧来源。同token多次恢复也换视图代际。可回滚的session state不得覆盖epoch或失败状态。这里不改变持久存档schema，也不宣称任意旧snapshot有来源能力。

## 3. Session到Scene原子所有权

request业务payload及可选source必须来自**同一条实际driver消息**，经过held、growth refresh、out和最终requests选取时成对保留。保留旧`currentRequest()`payload API；增加一次只读context查询（具体命名可定）原子返回`{request, source, requestViewEpoch}`，或明确none/unavailable及原因。查询不发事件、不消耗RNG、不铸号、不改变choice；不能让消费者分两次查询自行拼接。

Scene normal观察器仅在同一实际Scene、root operation、App/stateGeneration、Session和view epoch下公开当前source。App读档/新游戏、根操作退休、Scene退出、Session替换或内部restore，均退休旧观察和承接；仅Scene/App对象相同不代表恢复前后同一owner。可序列化ownerToken表达这一真实寿命映射，不能冒充引擎发生源。

第二层确认只接受真实相邻ready快照的`party-forced → party-command`，同case/intent/owner/source/epoch且选中实际合法P1；离开对应菜单路径、撤回或来源缺失就清承接。同一成员/同一payload本身不证明这次选择。按键、source查询和确认成功均不推进业务intent，仍由实际事件/状态oracle推进。

legacy/fake driver没有来源头时维持原游戏合同；只拒绝需要可追溯来源的normal P-4 driver接管，明确BLOCKED/UNAVAILABLE。不要要求所有旧fake伪造来源，不把缺观察能力变成全游戏动作失败。

## 4. 有限实施验收

一次小实施/复验覆盖以下正常且关键路径即可，不增加无边界对抗矩阵：

1. 真实引擎创建的两次相同payload强制请求（含同turn）身份不同；同pending的读取/重复发送/成长刷新/安全拒绝/失败逃跑保号。
2. 普通、wait、清除及终局不残留可用forced token；实际选择提交/撤回的可用状态正确，包装不额外调用引擎规则。
3. 显式恢复和动作故障的内部rollback：成功保逻辑来源而换view；反复恢复、恢复失败及旧queued消息都不能复活旧承接。
4. held/growth/out/current全链payload-source不串配；真实App/Session→编译Scene的合法两层替补可推进，旧/错owner/source拒绝；输入本身不推进intent。
5. 旧fake/无来源的普通操作不退化；实际钩子只装一次，消息业务投影/顺序/seq、PRNG、PP、引擎状态、AI硬锁守卫和结果写集不变。

这些是**后继实现的验收义务**，本次5项纯控制没有执行上述真实产品流程。第一小批可先交seam与定向验证；专属早期normal route、正式fixture、打包数据、完整trace/时限、OS后端和P-4正式接收仍按原门逐步实施，不要求当前为冻结此合同先建完所有后继能力。
