## 玩家流程与所有权

- `PS_Inventory` 在 `PS_Management` 之后载入。普通菜单 Bag 打开独立场景；背包、钱店和选择均由当前 `GameApplication` 拥有根 token，UI只保存投影、稳定ID、票据与答案。
- 队伍 Item→Use 仅主队伍非蛋可用；嵌入现有管理窗口，保留父 management token、绑定成员ID并取得 item 子 token，不跳新管理场景。父窗口不更新输入；子关闭只释放自身，刷新后恢复父焦点。摘要/盒中用药未开放。
- 普通袋左右经过空袋；过滤袋跳空袋，Close始终存在。数量显示当前槽，持有总量另列；重要物品遵循showQuantity。普通游标运行时维护，在进入物品操作或离开时写回访问袋索引和lastPocket，避免导航耗尽256条完成回执；选择游标从不覆盖原浏览位置。手动排序每步仍立即提交，Back只恢复该次顺序。
- 每行保留投影外层的实际口袋及过滤前原始index；替换ID后合法保留原袋，不把目录默认袋当位置。普通菜单、脚本初票据与丢弃fallback均使用此坐标。使用、丢弃保留初次选择行票据，经过目标/数量/确认不能静默重取新票据；消费仍按同ID累计库存的确定槽序。一次效果提交后，新的目标选择属于新的独立意图，后续取消不回滚之前成功。
- 队伍目标是稳定ID。PP、确认与逐级学习使用E/F结构化pending；学习Back/第5新招只放弃当前招，No重新选择，HM拒选保留同answerIndex。已实现的普通糖果实际生效；稀有仅q1，经验糖果保留数量规则。机器/进化继续未就绪，不显示假ABLE。
- 商店按内容greetingKey/farewellKey（或中英默认）问候/告别，数量画面显示单价/总价/余额；可选告别在自身窗口呈现，不把未处理的消息留给下一UI；告别呈现故障仍释放自身且不回滚旧交易。商店逐行处理禁售物品，不能因一个重要物品/零价物品而中断整张列表。数量初值1，确认前保留报价身份，提交重检价格/余额/容量；赠品、统计及用户①出售收入规则完全沿M2。取消/安装故障不部分写。
- Give仅显式既有持物来源能力开启且物品可持有时出现。选中后复检原行票据，再技术关闭背包根，保留当前UI等待，转现有管理根选择稳定目标并原子give，结束再开背包根；不并发持有两个根。默认能力仍关闭，未开放成员持物战斗。只读`heldItemSourcesEnabled()`避免为了查一个能力标志构造1200成员投影。

## 输入、保存与清理

共享数量：Back→Use→Up→Down→Left→Right；商店数量：Left→Right→Up→Down→Use→Back。方向±1回绕、±10钳位，取消返回0。确认默认Yes，Back为No。

新UI复用5.1的DOM/服务/虚拟手柄释放来源；额外合并同帧DOM边沿，避免MZ单一latestButton吞掉同轮仲裁。每帧缓存采样，键盘别名按物理键维护，所有来源释放才解锁；首ready帧只采样，下一帧新键有效。忙消息门独立于数量优先级。输入日志最多256条，不保存成员/游戏快照。

选物后的目标/数量、确认、学习及异步丢弃会话屏蔽保存，接入既有`PSFlow.operationPending`，因此菜单与直接保存共用守卫。纯浏览不保存UI对象。等待句柄和结果留在WeakMap，解释器仅保存等待模式字符串；`_psInventoryOutcome`为非枚举的运行时投影，不是持久回执。恢复后的旧等待没有句柄时只结束自身并返回stale-operation，不能绑定当前另一操作。API返回的Handle也只用于当前进程，内部应用/代次不参与枚举或序列化。

根入口在切场景前复检已有根、消息与ready边界；变量写故障可重试或技术关闭，事件clear/terminate仅中断自身句柄。完成回调等待父场景真正started且消息空闲，不用固定延时；换代丢弃旧回调。提交后的绘制/技术退出保留committed/failed，不将已消费误报未提交。

初始化/附着失败会完成自身句柄、释放所有权、销毁未被父图拥有的窗口并给诊断；正常附着窗口由场景图拥有，嵌入窗口由管理父场景拥有。读档换代关闭旧UI，不回装旧状态或结束新等待。旧回调、重复按键及保存/序列化均有VM反例；这不等于真实MZ存档文件与跨进程验证。

行文本按实际宽度裁剪/换行；袋行名称只占剩余区域，槽数量、商店单价/持有量、禁售理由各有测量宽度的独立区域，交易确认数量/单价/合计另列，不把关键数字拼到长名后整体截断。名字、说明、数量、价格、余额、状态和错误分开显示；en/zh键保持同占位符。占位图形以绝对运行时钟取相：导航8×0.1秒、暂停4×0.15秒、48格道具图一周1秒。未使用新建时刻重置相位；尚无真实窗口/内存证据，不能称无泄漏。

## 作者命令一页表

所有命令属于`PS_Inventory`；价格/例子为人工内容，非原Demo恢复。交互命令等待自己的Handle；同一事件中命令结束后、事件尚未终止时可读取`this._psInventoryOutcome`的副本，普通命令不承诺跨进程幂等。

| 命令 | 参数 | 结果/约束 |
|---|---|---|
| ShowBag | 无 | 浏览/用药/丢弃；最后路径返回，不用累计bool代表成功 |
| SelectItem | itemIds可选JSON字符串数组，variableId可选 | selected/itemId或cancelled/空串；有效变量1..实际表范围；不填不写变量 |
| UseItemOnMember | itemId、主队伍memberId、quantity默认1 | pending由UI继续；最终committed/cancelled/refused；不能绕过资格/库存/就绪/锁 |
| OpenShop | shopId或stock JSON数组；allowSell；prices可选JSON数组 | 会话结束清覆盖；prices项为itemId/buy/sell，显式sell参数仍按E/F×2槽合同 |
| GiveItems | itemId、正整数quantity、可选claimId | 统一增库存；显式claim用于剧情一次发放，普通重复就是再次发放 |
| RemoveItems | itemId、正整数quantity | 累计库存原子删除，重要物品也可供作者剧情移除 |
| ChangeMoney | 安全整数amount，可负 | 当前cap规则一次写回，不截断载入旧值 |
| SetBadge | 零基index、owned布尔 | 位与获得秒时间同次提交，重复/撤销沿D合同 |
| QueryBadge | 可选零基index、可选variableId | count或owned；不写资源，指定变量才写MZ结果 |

脚本API：`PSInventory.showBag(done?)`、`selectItem(filter?,variableId?,done?)`、`openShop({stock|shopId,allowSell?},prices?,done?)`、`useItem(itemId,memberId,quantity?,done?)`返回仅会话内Handle。不要把Handle或函数写进存档。来源不合法、未就绪、旧身份及端口失败分别报告refused。
