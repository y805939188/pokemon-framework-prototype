# 5.3 B：内容与持久数据接缝

本批实现内容编译、PBS 导入、存档 7 迁移、个体元数据桥及宿主保存门。它不接战斗伴随事实的持久消费、进化扫描/演出、教学、交换或图鉴 UI；这些后继不能因本批存在数据字段而标成完成。正式范围以工作区封印的 `step5-3-06ac-B-plan-r3-20261025T183416Z` 为准，该子方案已通过独立 sol ultra 与 Kimi r3 合同审。

## 版本与身份

作者 manifest 仍为 1，编译缓存为 2，持久状态为 7，公开战斗协议仍为冻结 v1。旧缓存 1 明确要求重建。`inputsHash` 只包含实际作者输入，省略新的可选文件不展开默认值；显式空输入仍参与 hash。`contentIdentity` 绑定编译语义 2、原输入 hash 和固定 Showdown SHA。静态 pin 与 `scripts/showdown.env` 有一致性测试；正常 build 在发布缓存前做来源和实际目录校验。空作者目录保持不读外部 Dex 的来源边界。

`registrationOrder` 保留物种/形态输入次序。全国表缺省取基础记录注册序，地区数字 ID 连续。`regional-dex.json` 为地区唯一作者入口；`map-metadata.json` 只含 region、flags、darkMap，不扩为完整世界系统。名字 key、source、转换描述参与普通输入身份，但不进入只识别有序物种表的 `layoutIdentity`。

64 个进化方法静态登记参数类型、家族和后置属性，不执行条件。30 个整数方法采用已净化接收的 PBS `u` 规则和 referenceR 两拼写/缺参阶段；不复制发行 v21.1 的形态缺参漏校验。框架按主协调接受的 `DEVIATION-PBS-INT-01` 明确拒绝超过 9007199254740991 的值，不舍入，也不称为参考上限；不另加等级、次数、Beauty 或进化 Location/Region 的目录限制。所有参考补证仍为静态资料，不是原版运行通过。

## 作者输入与 PBS

进化条目保留目标 content ID/形态、方法和参数；导师招式、等级 0 招式、完整类型/自然及隐藏能力目录、空槽、默认/展示形态与图鉴展示数据均保留。形态继承在 overlay 前完成：缺席值继承，显式空集合保空，learnset/evolutions 的空表例外整表继承；overlay 最终空表不再隐式补回。默认形态仅由 `DefaultForm_N` flags 派生。

`importPbsSpecies` 保持独立文本提案/逐条诊断接口；有序多文件 bundle 按基础、形态、地区处理且整次拒绝失败提案。source 门在 lazy reader 前。PBS 表意空缺按各字段原子规则检查，不把空属性统一当 JSON `[]`。Category/Pokedex 文本形成可审阅翻译提案，不写翻译源。

CLI 的 `import-pbs` 支持重复 `--base-file`、`--form-file`；非零形态必须由 `--form-id=SYMBOL,N:showdownid` 显式指定映射，不从形态号猜 Showdown 名。`import-pbs-regional` 以明确基础 PBS 文件取得原始符号身份，用重复 `--region-name=0:region.sample` 提供地区翻译 key。缺名、重复、未知映射及坏 source 均拒绝，不猜名称或默默覆盖。作者明确选择导入提案后再交正常编译，导入器不改原 PBS/JSON；独立物种提案不与旧 grants/settings 等无关世界数据混合校验。

`content/examples/progression/` 为最小作者样例：Charmander→Charizard、导师 Growl、地区与地图元数据，全部为作者占位测试内容，**不是完整或权威游戏数据**。正常 sample 原五个输入保留；新增可选地区/地图例。例子只验证数据路径，不意味进化/教学消费者已接。

```sh
node js/engine/build/content-cli.cjs build --src=content/examples/progression --out=data/framework/progression-example.json
```

## 存档与个体

schema7 所有队伍/40×30 盒槽成员要求 `cannotTrade` 与 `evolutionReadiness`；R 为 false 时可信度必须 known，true/unknown 可持久保存。6→7 保 R 原值并补 known，不编造历史濒死；保 null 特性槽、友好度 256、PID、位置、钱、物、账本及统计。首招表可长于四项并保顺序/重复，当前招式仍原 0..4 合同。1–5 沿原迁移链到 7，原输入不变。

普通完整治疗清 R 双字段，preserve 模式同时保留；蛋遵循原不治疗语义。复制保所有持久字段且不重随机。公开 captured/memberPatch/protocolMember 白名单不增加新字段。新字段不作为战斗事实记录，也不保存 K/D/L0 或待演出队列。

图鉴保 seen/owned 原集合，不推导历史形态/捕获次数；新游戏和旧空档/有记录旧档的 hasDex/解锁真值分别定义。当前7必须经过结构、内容引用和布局校验，缺内容不能安装/保存。纯 `newGame` 无内容入口仅为显式空全国测试夹具；正常 app 新游戏始终读取已装配内容。

布局变更只在加载迁移发生：从当前 Content 中选择恰好一条 from/to 匹配的一跳 transitions，先核完整 oldLayout hash 与映射，再按稳定 baseId 重定位游标。全国固定 −1→−1，保留地区一对一，新地区锁定；缺描述/歧义/坏旧索引拒绝。保存和安装不会自动迁移或修坏布局。翻译名变化不搬动玩家索引。

## 保存硬门与验证边界

`PS_SaveState.beforeSave` 是同步检查，不修复、不迁移。`DataManager.saveGame` 在 base 前拒绝坏结构/失效引用/布局失配/内容不可用；`makeSaveContents` 在 baseMake 前复验。菜单与 autosave 走同门。恢复合法内存可重试；校验失败保证零存储调用，不承诺进入 MZ base 后任意磁盘故障的多文件回滚。

Node `SaveStore.save` 同样只保存当前、已验证内容状态；不拿加载迁移结果偷偷转换布局再写旧对象。MZ 的实际磁盘持久性仍属 MZ，未增加通用日志/备份框架。

新增测试分为 content7、pbs7、migration7、member-bridges7、save-gates7。VM 测试可数准 baseSaveGame/baseMake，实际 NW 场景则验证真实宿主入口、序列化/存储调用与文件字节。`progression-data` 正式 runner mode 与 `verify-save` 独立新进程共享已记录的 expected/SHA，隔离 profile/save，只收拾自有 PID。测试用 DOM/服务调用不等同 OS 物理键鼠；FINAL-INPUT-01 后置决定不变。

本地完整回归、NW 和独立固定候选代码审的实际结果另由本批交接证据记录。该文档不预填通过数量，也不签 G53-B/M1、完整 C/E/F 或整个 5.3。
