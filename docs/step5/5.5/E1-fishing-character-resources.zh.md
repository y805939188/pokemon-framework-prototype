# E1 默认钓鱼行走图资源

PS_World 的默认抛竿表现使用作者提供的 MZ character sheet；框架不附带最终钓鱼美术。普通鱼竿背包与登记快捷入口共用此配置。

| PS_World 参数 | JSON 示例 | 用途 |
|---|---|---|
| `FishingCharacter` | `{"name":"MyFishing[f4]","index":0}` | 步行钓鱼 |
| `SurfFishingCharacter` | `{"name":"MySurfFishing[f4]","index":0}` | 框架冲浪中的钓鱼 |
| `SurfCharacter` | `{"name":"MySurf","index":0}` | 冲浪钓鱼后的正常冲浪显示；沿用场外招式既有参数 |

默认开始或默认结束需要 Reactor 的四帧能力：作者项目 `data/System.json` 须显式启用 `rrMultiFrames: true`，两个钓鱼资源名使用 `[f4]`，每方向四列（大图为 4 列，8 人图为 16 列）。框架只读取此项目能力，不在运行时或安装目录打开它；能力缺失、三帧资源名或非四帧资源会返回已有本地化不可用反馈。当前仓库的原始 `System.json` 没有该键，不能据测试夹具的启用状态宣称实际工程已配置完毕。有效 BEGIN 和 END 公共事件均自行替代时不强制默认资源；任一对应内置阶段实际执行时都独立核验能力及资源。

name 是 `img/characters` 下不含扩展名的文件名，不能包含目录、控制字符或 `.`/`..`；index 为 0–7 的安全整数。支持 MZ 的 `$`／`!` 文件名前缀。参数默认留空，让作者明确选择资源；空白、无效 JSON、非法名称／索引、缺加载能力、加载失败和 Reactor 降级空白都返回失败，保留合法原图。不会把继续显示步行图当作完成钓鱼图切换。正在加载的图以钓鱼的可暂停经过时间等待，5 秒仍未就绪则失败；此上限是本项目的资源失败策略，不是参考随机或输入窗口规则。

默认开始先等待选中的 Bitmap 真正 loaded 且 `isReady()`，并检查 `isError()` 和 `_degradedToBlank`，再调用原生 `setImage(name,index)`；冲浪时同时验证正常 Surf 图，避免成功切图后才发现无法正常收尾。步行使用钓鱼图，冲浪使用冲浪钓鱼图，不打开 MZ 原生载具。抛竿帧为 3→2→1→0，收竿为 0→1→2→3，各名义 50ms；原钓鱼时钟、失焦暂停、消息和输入顺序继续有效。

正常没咬钩、提前取消、跑掉、钓到及自动收竿都进入共同收尾，恢复步行原图或已验证的 Surf 图，并恢复该会话自有的原生动画字段。正常站立输入恢复站立帧；会话进入前已有方向锁和其它作者设置按既有字段所有权保留。有效普通物品 BEGIN／END 公共事件分别替代各自的默认表现；负 ID 或缺记录分别回退。公共事件脚本及本会话自有的原生强制移动路线所写的图片也由同一图像租约收尾；其它作者后来写入的图片不归旧会话清理。

图名与索引、原生 setter 身份、写入序号和会话共同决定图片所有权。作者后来 `refresh`／`setImage`，即使写回相同的 name/index，也会撤销旧图像租约。旧取消、重复 dispose、晚消息／资源回执不能覆盖 successor。加载、原生图片调用和 Bitmap hook 前后继续检查原有 App owner、generation、Content 与原生 player/map/Scene；不新增业务状态、随机抽样、步数或物品消耗。

正式状态替换先同步释放仍有效的当前钓鱼表现。若直接 App 换代或外部原生 hook 在调用中使旧图片滞留，由当前地图初始化／帧泵根据当前业务状态重新投影；旧 continuation 只能登记其确切自有写入，不借旧 owner 修改新会话。没有可验证的当前源时保留诊断，不能冒称恢复成功。

无头测试使用 `FixtureFishing[f4]`／`FixtureSurfFishing[f4]`／`FixtureSurf` 受控资源，消费固定 Reactor 的 ImageManager、Bitmap 就绪接口、原生 `Game_CharacterBase.setImage`、后置 `[fN]` pattern 链与 `Sprite_Character` 后置四列裁切链；内置阶段还以自有租约阻止原生自动改帧，合法外部图片／方法变化会撤销旧租约。这是图片接口与生命周期证据；真实图片文件、PIXI 像素渲染、NW、实体键盘、声音和真实失焦另行验收。插件发布前仍需检查 NW `window.require` 的实际属性形态与 Node detector 可用性。

替换 `setImage`、`characterName` 或 `characterIndex` 方法本身不代表写入新图片。当前调用验证最新方法及严格值，并以实际原生图片写入序号决定租约；真正外部写图（含相同图名与索引）仍优先。失败的恢复不会逐帧重发；只有合法方法替换、当前源变化或正式新恢复机会可以再尝试。图片清理失败仍释放当前会话确实拥有的动画字段，保留原失败及后继作者的字段。
