# 5.5 世界与遭遇：A 合同合并终稿（r4＋r5）

本合同合并 r4 主体与 r5 五项修订，形成 2026-11-15 的 5.5 方案记录。[方案说明](README.md)列出来源、条款变化和独立静态审查的范围。

历史复核确认 S1–S5 的方案问题已解决。本文登记仍须在实施批次中细化的测试与随机数要求，功能交付和验证归属各自的候选。

## 已批准的七项产品决定

1. 保留 MZ 直接移动手感：普通移动完成后才检查普通遭遇。原地转向和撞墙不计普通步、不额外遇敌；不引入参考式 75ms 转身延迟。登记为有意偏离。
2. 世界时段默认现实日历时间，可注入；钓鱼使用可暂停的单调经过时间，失焦暂停，不默认截断聚焦时的卡顿时间。
3. 保留作者常用地图连接、标准转移，以及事件伙伴注册、解除、跟随、转移和恢复的最小闭环；复杂无缝拼接和复杂剧情跟随编排延期。事件伙伴不是 MZ 队伍跟随者。
4. 宝可梦病毒的生成、传播、日期变化及 EV 效果整条链延期；不加无消费者字段，不消费该链随机数。
5. 纳入最小快捷登记与调用、Fly 已解锁目的地列表和共享地区数据；不做完整地图编辑器。这里“已解锁”仅指由已访问地图及合格区域点记录派生的可选目的地，不存在独立的持久解锁集合（r5 修补 1；r5 报告 §2）。
6. Headbutt、Dive、Waterfall 暂缓。
7. 黄昏球按真实时段／洞穴业务事实判断，不受纯视觉昼夜着色开关控制，登记与参考行为的差异。

这些决定不要重新要求用户投票。若合同无法实现某项，说明原因和最小必要取舍，不要擅自缩小范围。

本期主体包括正式遭遇表和版本、队首／道具／哨子修正、驱虫及续用、野生生成与持物、三种鱼竿、步行友好、可配置野外中毒、Cut／Rock Smash／Strength／Surf／Flash／Fly／Dig／Teleport／Sweet Scent、地图与伙伴批准子集、败北／野外全灭回程、世界事实与战斗／捕获／图鉴／进化接线、旧档兼容和正式入口验收。哨子未被延期，不能漏掉。保留当前单打约束；Gen8 默认关闭野外中毒，作者开启时要有完整行为和测试。

领域层不直接访问 MZ 全局、DOM、文件、系统时钟或 Showdown 实例；Application 负责唯一状态写入、操作代次、等待、取消、恢复与幂等；MZ 层负责采集和表现。复用已有状态仓库，不建设万能上下文或过度通用框架。新增核心和公开 API 避免显式／隐式 any；外部输入用 unknown 并严格验证收窄，不用双重断言伪装安全。将来跨语言迁移仍须重写和验证数值、序列化与异步语义，不能承诺只改适配层。

## 一、字段权威、迁移与恢复合同（S1）

以下是逻辑字段合同，不强制代码命名；已有等价字段必须复用。请依据规格检查作用域、默认值及进出地图语义，发现不准确时给最小修订。

字段、权威及保存／恢复规则：

- 成员、背包、金钱、已有统计：沿用框架既有状态和 Application；迁移不得覆盖。
- 全局步数：框架唯一完成步操作写入，不能在移动开始和完成时各写一次；复用既有字段。
- 驱虫剩余步数：框架道具／步后操作持久化；旧档默认 0，本步保护使用本步开始的快照。
- 四个黑／白笛局部标志与 Strength 局部标志：真实跨图（显式跨图传送、边缘连接）及 WP11 所列两种正常读档进入时清除；同图显式传送保留。可采用运行期状态，但新游戏／读档必须重置，不能残留上一游戏运行态（r5 修补 2；r5 报告 §3.3）。
- flashUsed：框架持久业务状态；有效遮罩存在、前置演出和文本正常完成时先写 true 与次数，再展开光圈。无有效遮罩则失败且不写；展开过程中异常不回滚已提交值。进入或恢复非黑暗地图时清除；黑暗地图间切换、黑暗地图读档时保留。显示层重建按同一规则幂等处理。黑暗事实不可用时不清除、不建遮罩并诊断；可用元数据中无该地图条目才按未标黑暗处理。旧档默认、无效输入及恢复顺序须在 B 迁移表落实，不在归档时猜填（r5 修补 2；r5 报告 §3.2）。
- 世界天气业务意图：候选由框架持有完整业务值并持久化，宿主屏幕作单向表现投影；不能从淡出中的旧显示类型反推意图。旧档按已验证的旧宿主天气映射初始化；未知输入拒绝或明确诊断，不凭空猜测。
- encounterVersion：框架业务状态，旧档默认 0；非法版本拒绝，内容查找／回退按正式合同。
- 遭遇宽限和累加：框架运行状态；分别明确新游戏、读档、真正进图、战斗、冲浪、版本变化的重置／保留，不笼统全部清零。持久与否及用户体验必须有明确测试。
- visitedMaps：框架记录成功进入／恢复的合法当前地图；旧档缺记录时只通过正式进入／恢复通知补记当前地图，不推断其它历史访问。Fly 目的地是派生结果，不建立独立持久解锁集合或作者事件解锁系统：同一地区地图格只取首条点记录，检查完整治疗／飞行三元组、其中目的地地图已访问及开关可见性；首条隐藏或不完整时不回退后续记录。没有开关字段则可见；带开关字段且开关号 ≤0 则隐藏；其它情况对应开关必须为开。只列当前所在区域的目的地，按当前地图区域定位元数据确定，缺定位时区域为 0。当前图已访问不等于无条件可飞。地区数据由 Fly 与图鉴各取窄投影，不造两套真相（r5 修补 1；r5 报告 §3.1 的 E3 精度修订；三元组目的地地图解释仍是该报告注明的静态推断）。
- 最近治疗中心、Teleport 返回点、Dig／逃脱点、静态家：分别定义来源、持久性、优先级、消费及清除；不能混成一个位置。
- 快捷登记：框架持久的有序道具列表；自动列出的队伍场外招式是派生结果，不持久缓存，执行时重新验资格。
- 多名有序事件伙伴链：框架持久，稳定原地图／事件身份；重复注册去重，来源无效应诊断且有恢复策略。
- Surf 业务模式：唯一业务权威和宿主通行／姿态单向投影；非法恢复位置必须明确处理。
- cycling／diving：仅在确知未骑行／未潜水时给 false；事实读取失败仍为不可用或非法，不能伪装 false。
- pending blackout return：只持久化确需恢复的身份、目的地、已完成阶段及结算标识；不得重复扣钱、治疗或统计。
- 实际地图、坐标、朝向和作者的 MZ 跟随者显示意图：宿主权威；框架不保存另一套可随意独立改写的位置。
- MZ 遇敌允许开关：宿主已有作者开关，框架遭遇模式必须读取并尊重，不建立可独立冲突的镜像。
- 操作令牌、函数回调及临时锁：运行期，不序列化；读档／新游戏更换代次，使旧回调失效。

单一整合者管理 schema，按实施时版本升级，避免多批次抢版本；坏档、未知版本、关键迁移失败须保留原档并阻止半恢复继续，不静默创建新状态。等待 UI 答复或正在执行转移期间，正式保存明确拒绝。

特别检查：现有保存门可能对 operationPending 一律禁存。必须区分“正在执行、不能保存”和“失败后稳定、可恢复的回程检查点”，或设计其他可靠落盘方式；不能仅声称 pendingReturn 可持久化。要求覆盖转移预定成功不等于抵达完成，以及失败→保存→新进程 Continue→只执行未完成步骤。

MZ 命令 236 的适配要保持原有战斗中行为、duration、wait 和返回语义；业务意图与视觉淡出分别处理。请核实该命令的完整合同，不能只复制天气类型而丢失等待。

**B/D 读档进入接线（r5 报告 §3.3）**：MZ 正常读档后直接进入地图场景，不会发出框架需要的进入通知；适配器必须合成一次“读档进入”，用于重置局部运行态、补记当前已访问地图及适用的回程目的地处理。`reloadMapIfUpdated` 登记的同图转移归入读档重建分支，不能误当成保留局部标志的同图显式传送；同图天气不重掷。以上是实施合同，尚无本批动态证据。

**236 完整兼容合同（r4 报告 §3.2）**：战斗中整段跳过，不改天气且不等待；非战斗中沿用原 `changeWeather(type,power,duration)`，仅等待标志为真时按原 duration 帧数等待，总是返回 true。none 加淡出时业务天气立即为 None，显示可继续淡出；不要拦截 `Game_Screen.changeWeather` 造成框架自身投影回环。业务强度换算和迁移输入边界待 B 的实施细化表，不由本次归档编造。

## 二、移动入口矩阵与遭遇开关（S2）

入口、计步／被动及遭遇规则：

- 直行完成、换向后完成：每个实际完成步一次；每步至多一次遭遇。
- 原地转向、撞墙：不计普通步、不额外遭遇。
- 点击／触摸目的地：逐格完成各计一次；遭遇时清除旧目的地，防止战后自动续走。
- 到达事件格：该步的适用被动仍执行；到达事件被处理后不普通遭遇。
- 地图连接边界：跨边动作只计一次；使用正确的目标落点事实，若事件／转移阻断则不遭遇。不得原图和目标图各记一次。
- 伙伴自身移动：不触发玩家计步或遭遇。
- Surf 上下水跳跃：能力专用操作，不伪造普通步；之后正常移动按实际步处理。
- 强制路线／解释器移动／跳跃：按各自专用规格分类，不默认当普通玩家输入。
- 普通传送、读档恢复：不计额外普通步。
- 钓鱼、Sweet Scent、Rock Smash：各走主动入口，不套普通移动概率。

MZ 命令 136（Change Encounter）在 framework 模式必须控制适用的普通随机遭遇，不能被新触发器忽略；其原生计数重置不得在框架模式额外消费不需要的原生 RNG。legacy 和 native 模式保留自身计数语义。作者显式事件战和随机遭遇开关的关系须分别定义，不能笼统禁止所有战斗。

**计数入口清单（r5 修补 3；r5 报告 §3.4）**：实施前在固定候选重新检索所有生产调用；参考基线 MZ 为 1 个定义、5 个调用（locate、executeEncounter、下载具、命令 136、命令 301），框架另有旧备注路径和战前重置 2 个调用。统一在 `makeEncounterCount` 按当前地图模式分派：framework 不抽原生计数 RNG、不另开原生敌群战；legacy-note／mz-native 保持各自旧行为；none 不触发两种随机遭遇。不能只修 136，也不能凭“战后调用”字样虚构不存在的调用点。参考宿主 `performTransfer` 先 setup 新图、再 locate，落位计数看到新图模式；这是报告的静态核对，实施候选仍须复核。遇敌开关只约束适用随机遭遇，作者显式事件战不受它禁止。

## 三、步进顺序与等待终态

唯一完成身份 → 锁存本步位置、地形、适用队伍和起始驱虫有效性 → 提交计步、适用友好及驱虫递减等前缀 → 必要时在同一父操作内询问续用并打开过滤背包 → 检查操作代次、地图和相关状态后继续毒伤／全灭 → 与到达事件串行调度 → 仅在事件及其他门未处理时进入普通遭遇。

驱虫从 1 降到 0，本步仍受起始快照保护；续用成功只扣一次，取消不撤销已经完成的步数。续用和到达事件不得争抢消息窗，也不能静默丢弃询问。事件或外部操作若改变地图、读档代次或队伍，必须验证是否允许继续，不能盲用旧快照。

终态：

- 重复答复只接受一次；旧代次回调无效。
- 读档／新游戏使旧操作失效；不能对新状态写入。
- 等待期正式保存明确拒绝，不只依赖菜单不可见。
- 场景关闭或宿主异常：保留已提交前缀，停止未提交部分，释放本操作自己的锁。
- 开战失败：不重复计步、不自动生成另一只；给出明确可处理终态。
- 地图目标加载失败：不越界、不覆盖当前地图数据，允许明确重试或取消。
- 回程传送失败：只重试未完成阶段，不重复已结算部分。
- 不虚称整个跨 UI 流程能单次原子回滚；逐阶段记录提交边界。

## 四、四种遭遇模式与随机合同（S2）

- framework：正式表和框架触发是唯一权威，MZ 原生敌群不能另开战；原生计数不参与触发。
- legacy-note：旧 PSEncounter 备注按既有兼容路径运行，记录新规则不适用之处；不得冒称完整 WP36。
- mz-native：保留宿主原生路径及计数。
- none：两种随机遭遇路径都关闭。
- 同图正式表和旧备注冲突给清晰诊断，不叠加；框架恢复失败时不静默回退到原生战斗。各模式的计数和重置逐一验证，不能要求四种模式的原生计数都不变。

按规格核实普通遭遇各阶段：机会／类型与触发 → 候选物种及等级 → 允许门（含适用驱虫等）→ 单打约束／双打门 → 开战及完整个体生成。队首、道具、哨子修正分属正确阶段，不能集中成泛化修正。被驱虫拒绝时不得提前生成完整个体或消费生成专用随机数；本期强制单打在双打概率抽取之前返回，不抽不使用的随机数。

RNG 消费目录至少列触发、候选、等级、允许门、生成、钓鱼、场外效果、视觉及延期病毒：各自列抽取条件、范围、次序、早退不抽的条件。用途可注入并可重放；如果声称独立随机流，须有独立状态或明确派生，多个函数各自调用同一 Math.random 不算独立流。具体概率、范围和修正顺序必须追溯净化规格；不得为合同完整而编造数值。

## 五、天气、捕获及旧行为兼容

5.4 旧事件命令已公开“天气留空表示 none，不从世界推导”。候选兼容策略：
- 旧事件命令空白：保留 none。
- 显式 none：覆盖世界值。
- 新 5.5 遭遇入口：可按合同使用世界默认。
- 新增显式 inherit：采用该操作锁存的世界事实。
- 非法值：明确拒绝，不当作空白。

weather、terrain、environment 分别处理，且从 MZ 最早参数解析开始保留三态。不要复制两套核心规则。请核对旧入口及新入口完整调用链；如认为必须改变旧空白语义，明确作者可见影响和迁移，而不是声称这是无影响重构。

洞穴判断使用地图业务元数据而不是洞穴遭遇表；诱饵球依据实际钓鱼来源；黄昏球使用已批准的实际时段／洞穴事实。战斗开始锁存来源、环境与时段，捕获时不重新读取当前世界。晴天进化提供明确 value:“None”；不可用不能当 absent 或 false，从而错误跳过有序进化条目。

事件野生战的“物种+等级生成入口”与“已经构造的个体入口”分开：前者适用哪些生成修正、对旧事件有何兼容影响需明确；后者不得重新随机生成已给定个体。世界天气、战斗天气及显示天气映射必须按规格逐项核实。

C 的补充接线要求来自 r4 报告 §3.1／§5.3：世界天气按类别映射，HeavyRain → rain，不能据名字误映射为 primordialsea；Storm／Fog 派生地形受 `OVERWORLD_WEATHER_SETS_BATTLE_TERRAIN` 控制（报告引用 WP39 的 Gen8 默认开启）。`battleTime` 只用于背景图像时段，不作为捕获时段。旧事件参数需在 `initialFieldMZ` 之前区分空白／none／inherit／具体值／非法，共用解析规则后才进入现有规范化；战斗核心只接收锁存的具体值。上述映射和兼容仍须定向测试，不代表已接线。

## 六、快捷、伙伴、连接与回程（S3–S5）

快捷菜单由已登记道具和按当前队伍自动列出的场外招式组成；背包补齐无成员目标道具→交还地图的正式链。队伍界面的场外招式入口要有明确负责批次。E1 可交付快捷底座和钓鱼，但完整快捷验收须等相关 E2／E3 能力接入。

事件伙伴支持多名有序链、稳定身份、注册去重、解除、跨图落位、读档重建及来源失效诊断。伙伴与 MZ 队伍跟随的共存策略在 A 冻结。若采用“有事件伙伴时遮罩 MZ 跟随者”，应保留作者当前显示意图，以有效显示派生，不改写持久作者开关；伙伴移除后尊重作者期间的新设置，不强制 show。伙伴清理不等于删除 actor 队伍；MZ gather 等待也不能因错误纳入事件伙伴而卡住。

地图连接应有方向、偏移、目标及落点／通行校验；邻图可预取或受控异步等待，不强制大型缓存框架。目标未就绪或失败不得非法越界、覆盖当前数据或永久静默表现为不可通行。跨边、Surf、伙伴及进图事实应一致。

回程分开战斗败北结算与野外全灭：野外不能复用战斗扣钱。按 WP61 和各入口分支明确治疗、取消载具／下车、清事件伙伴、starting-over 开关、目的地与转移；不能将某分支的行为无差别套到所有入口。注意现有战败链可能已经治疗、扣钱及累计 blacked-out 统计，新回程要复用结算标记，避免重复执行。F 的最终整合依赖 E2/E3，但纯规则和 fake-host 测试可并行。

### 回程抵达与保存前置合同（r5 修补 4；r5 报告 §3.5）

- 战败入口复用已有结算凭证；野外全灭自己幂等处理，不扣战败钱。治疗、统计、载具／伙伴等副作用按适用分支在预定转移前、至多一次提交，不重复现有战败结算；保留 5.4 lateHeal／战败后进化与回程顺序。
- `reserveTransfer` 成功只表示预定；只有 `performTransfer` 实际成功并确认目标地图及坐标后，才能同步确认抵达、清检查点并释放阻止保存的操作。此确认必须早于 `onTransferEnd` 自动保存。不能笼统要求“所有 GameState 写入在转移前”。
- 预定后尚未落位不能标记完成；异常／失败保留稳定可恢复检查点。活动转移期间禁存；失败后的稳定状态必须可以保存，或有经证明的可靠落盘方案。重试只做未完成阶段，不重复结算，不静默改目标；失败和恢复可见。
- 冷 Continue 恢复须等地图场景就绪、且 MZ 没有待执行转移（含 `reloadMapIfUpdated`），不能叠加两个转移。
- **5.4 战败回程后的实际自动保存行为未核实**。r4 报告 §3.6 曾将其写作“正常发生”，r5 §3.5／§7 已明确撤回这一确定性；F 须记录 5.4 与 5.5 的实际行为，不能把旧推断当基线或验收通过。
