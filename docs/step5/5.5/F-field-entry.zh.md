# F 野外全灭入场与直接检查

WP61 §5.3 与已批准 A 合同要求：零个可战成员时，先显示全队失能与眼前一黑消息，淡出 BGM/BGS 和画面，再进入已有失败回程。单个成员濒死而仍有可战成员时不进入 F。直接检查也包含合法空队伍；Gen8 默认关闭野外毒伤的决定不变。

真实完成步仍由 D 提交前缀、反馈毒伤和个体濒死，再以原私 permit 注册 F。F 同步取得原有 owner 和保存屏障；新的运行期入场阶段等待两条消息和 24 帧原生淡出。入场成功后才执行原 prime，将治疗、计数和 schema11 已结算检查点一次安装。等待期间没有未结算检查点，正式保存拒绝。战斗入口与已有检查点恢复沿原顺序，不重复本入场或结算。野外不扣钱。

作者脚本有两个实际入口，均只接受本时间线内唯一的 1–128 字符请求 ID，不接受 owner、token、目的地或结算参数：

```js
// MZ 地图事件的“脚本”命令。等待自己的检查与回程后才继续本调用列表。
PSFlow.waitFieldBlackout(this, "chapter-3-field-check-1");

// 已有异步作者代码，可自行处理返回结果。
const result = await PSFlow.checkFieldBlackout("chapter-3-field-check-2");
```

原生 command355 不等待返回的 Promise，因此事件脚本使用第一种写法。桥接只认当前地图真实解释器及公共事件子链，绑定原列表和原生 clear/setup 代次，沿用已有 updateWaitMode 链。它只等自己的请求；其它管理、旅行、战斗或不相关等待保持原拒绝门。转图时原生列表清理继续有效，读档、新游戏、列表更换和迟到结果不改后继列表或等待模式。这里没有新增 357 命令。

App/World 用当前原子 game/content/source 观察判断零可战，包括空队伍。有可战成员返回 `not-required`；忙或无有效来源时明确拒绝。相同 ID 返回原请求结果，不再治疗、计数或重做 D 前缀。入场尚未结算就失败/取消时保留 D 前缀；需要再次检查时显式使用新 ID。已有稳定失败检查点则使用原 `recoverBlackoutReturn()`，只执行未完成部分。

原生呈现只持有自身画面与 BGM/BGS 请求的运行期 epoch。终态、取消及异常收尾恢复自己的淡出；后来的原生淡出/音频意图、其它 App 或新 screen 不被旧回执覆盖。实际 App 同步换代可退役仍匹配的旧呈现 epoch；异步 continuation 始终要求原 generation。回程结算后的呈现清理故障不吞原始终态/保存通知，显式 recovery 只重试清理。五条玩家消息由现有 translator 选择中/英文。

定向验证使用真实 GameApplication、正式 IIFE、固定原生解释器/地图/画面方法及无窗口资源、音频和存储 facade。调用计数和日志不代表真实播放、听感、实体键盘、真实失焦或 NW。原生 Game Over、捕虫和延期病毒不在本后继中；既有 T20 和其它失败证据保留，独立审查与必要精确整合回归另行记录。
