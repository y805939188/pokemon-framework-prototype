# 5.4：变身期间学招、恢复与临时招式菜单

本批从 `eef4d20403d518698609da9e66f432a15f2b912c` 独立修复变身成长的相邻问题，不改此前本体成长、HP、details 处理，也不改永久最多四招或战后一次提交规则。

## 正常路径与边界

合成作者内容给 Mew 配置 Transform 和正常升级学习表，经实际内容编译、App、Session 与固定 Gen8 引擎操作。不是默认投放或官方学习表声明，不直接修改引擎对象。

- 永久四招、复制一至三招时，原生反序列化按永久槽下标访问短复制列表。正常 Switch 模式击倒后的替补预览就会触发，不限于异常回滚；预览和回滚一起失败会使 Session broken。
- 永久四招、复制两招、非终结击倒后选择遗忘第四永久槽，旧赋值生成稀疏临时数组，下一请求更新失败。第三永久槽刚好在表尾，不产生空洞，但其短列表恢复仍受上一问题影响。
- 永久招式未满时，升级继续把新招加入临时列表。复制四招再学习一至三招会发布五至七招。真实引擎可以使用这些招式，但旧正式 Scene 的四格游标守卫会报错并中止战斗。

这些都是普通作者配置与玩家操作可以到达的路径。相关学招写入及固定引擎限制早于本批，不把此前所有 Transform 成长路径一概称为不可达。

## 保持的语义

正式规格 WP42 §4.3 要求空槽先写永久招式、提示后追加在场招式，替换则同步在场对应槽；WP47-B §4、§6 区分永久与变身临时 PP。不能为了菜单四格而删掉合法临时新招，也不能把它们写回永久招式表。

1. 对变身且永久表长于复制表的恢复，在适配层用原生引用解码器分别恢复永久列表，再重建派生请求。普通恢复路径不改变；不填入虚构可选招式，不改固定 Showdown 文件。Gateway 检查点与替补预览使用同一个适配入口。
2. 槽内替换保持原行为；不存在的复制槽以密集追加承接新虚拟招式。虚拟学招槽记录对应的永久招式身份，后续再遗忘这招时替换它自己的临时副本，不误删另一个复制招式或不断累积旧副本。若原永久索引已被另一条密集追加的新招占用，则继续追加，不覆盖那条仍然有效的临时副本。永久 PP 与临时 PP 继续分离，换下后只恢复永久表。
3. 招式菜单保留两列与原有四招操作，允许额外临时行使用原生窗口滚动；上下导航按实际行数移动，边缘和最后空格不绕行。主菜单仍限制四项。

## Copied-ID collision follow-up (2026-11-11)

A legal authored Mew with one permanent move can copy Splash/Seismic Toss and then
learn Seismic Toss through the normal level-up flow. Previously the temporary list
contained two Seismic Toss rows: selecting the new full-PP row still spent the
first copied row's PP because Showdown resolves actions by move ID.

Learning retains the existing replacement/append contract: install the new full-PP
virtual slot, replacing the selected old temporary slot when applicable. Then retire
any other copied row with the same move ID, so Showdown has a single unambiguous
selectable identity. The new row retains its learned identity for subsequent forgetting.
Permanent and temporary PP remain independent. The first candidate's preserve-copied-PP
approach was rejected in independent review; it is not the accepted semantics.

Real App/Session regression coverage includes automatic append, full-slot replacement,
all four full-table replacement slots, checkpoint restore, actual action PP deduction, subsequent re-learning, switch-back,
and once-only end-of-battle installation. These are headless authored-content tests,
not default sample, NW, original-engine parity or full 5.4 acceptance claims.
