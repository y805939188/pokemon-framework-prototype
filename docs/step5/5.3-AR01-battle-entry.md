# AR01：开战准入与初始化回调窄整改

基线为正式main c70d441（PR21，G1/G2a已接收）与固定A 954ecc3172fb4bf346df6f9e487ad412330966cf的本地正常合并。A的解释器receipt修复单独封存/审查；本树是唯一B写者，复用A，不修改其冻结树、原二审或G2c WIP。本批不是全面架构重构，也不签完整G/H/I/J或5.3。

应用开战先保留既有management/reception/inventory、重复battle、commit、evolution错误，再覆盖其余统一battleBusy owner。完成准入后、首次StatePort.read前，使用已有op(session:null)占有准备期；状态、内容、时钟、creationContext、可选itemWorld和随机回调后检查同一op及generation。random每次前后检查，失效后不继续下一次调用，已经发生的合法抽样不伪称零。普通可选itemWorld异常仍可开战，换代/owner失效在catch外检查，不能被吞。全准备及create失败只释放自己的op，旧拒绝/迟到session不能清新owner；无新公开战斗方法、message/result/memberPatch或schema字段。

宿主openBattle先检查running、组合后的operationPending及app.encounterBlocked，覆盖queued/reserved/active默认UI以及应用owner；不只检查app领域状态。同步opening identity只防止初始化重入，不成为第二份领域所有权/存档状态；外部held gate与performance回调后检查application/generation、组合owner，再安装_op/request/running并push。拒绝前不替换原_op、不push场景。stateReplaced使旧opening退休；旧finally仅清自己。idle held-item gate与无可用存档时的场景内诊断保留，tryOpenBattle原错误呈现/结果变量语义保留。

自动化分三组：正式持有者矩阵；代表性首次端口异常、重入、同battleId ABA/换档、random中途停止及迟到session；A×B交界（pending交换拒绝开战后仍最终一次提交、成功后合法开战保留receipt读取窗口、未启动尝试退休后开战不能复活旧结果）。不做无意义全笛卡尔积。VM使用实际应用与构建插件；正式battle-entry NW模式复用四个trade-ui场景并加入实际学习reservation/active与端口回调，再新进程读五个完整JsonEx。具体PASS须以固定SHA实际日志/独立报告为准，文档不预填结果。

静态Kimi报告未证明数据破坏。新probe确认了旧入口可放行和重入窗口，不外推真实玩家存档已经损坏。测试准备问题保留：初轮把无持物management的saveBlocked误设true，按原合同改为核encounterBlocked及token正常end；最初在可选itemWorld回调中直接assert会被旧catch吞，改为回调外核结果；中途随机测试最初替换了构造前ports对象的函数，而应用已浅复制配置，实际没有注入；改用真实已配置source的回调并给三个对手保证第三次到达，未修改生产随机规则。有效旧红、反向变异与新绿分开。
