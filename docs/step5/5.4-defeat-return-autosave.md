# Defeat return autosave timing

## Defect and contract

The real D3 acceptance attempt on baseline `95d945c25e42f0e47e3322fca83243a51b6c5742` timed out waiting for the return autosave. This remains failed execution evidence, not a completed defeat/Continue acceptance.

The ordinary Map transfer calls `requestAutosave` inside `Scene_Map.start`. The normal prebattle wrapper still owns `return-pending`/`return` at this point, so its save gate rejects that sole request. Completing the return cover previously did not retry it.

The host now retains that actual request during an owned return and invokes the original `requestAutosave` once after that return reaches `done` and a complete ordinary Map update has retired its waiting blackout event chain. It does not call `saveGame` directly, unlock saving, invent requests for battle ends, or retry failures. Original autosave and save gates are evaluated at delivery time. Scene termination, cancellation, a new operation, and scene/map/app/generation/operation identity changes retire the request. Consumption precedes callbacks to prevent duplicate delivery.

## Controlled evidence

`test-return-autosave.cjs` compiles the product prebattle host and uses the installed Reactor transfer/autosave methods with controlled scene and clock ports. The baseline has three failing tests; the repair passes all 20 cases. These cover delayed one-time delivery, the original gates, absent requests, ordinary requests, stale owners/maps/scenes, and duplicate/reentrant requests.

The prebattle wrapper/menu and save-gates suites pass 78 tests together; TypeScript `tsc --noEmit` passes. These are controlled tests, not rendered NW or cold-process Continue evidence. Real D3 must be rerun against a newly pinned product/package after independent review. Historical failure evidence is retained privately and not included in this repository.

## Independent review correction

Review identified that saving on the first `done` tick would still serialize the waiting battle interpreter: its base Map update had run while the return gate was closed. Delivery therefore waits for the following full ordinary update and rechecks ownership afterwards.

The compiled-plugin wrapper suite now includes an actual Reactor parent/child interpreter scheduling and serialization regression. A real engine battle is followed by an explicitly synthetic blackout outcome fixture. It verifies no save on the first done tick, one save after both event chains terminate, and no post-battle sentinel commands after deserializing with the outcome absent. The suite passes 19 tests; a same-tick-delivery mutation fails the new assertion as intended. This is controlled interpreter evidence, not real defeat, disk-slot, or fresh-process acceptance. Independent static review accepts the corrected product path without remaining blockers.
