# P-4 p1强制请求来源小接点

冻结合同见[5.4-P4-request-source-contract.md](5.4-P4-request-source-contract.md)，来自c6上的PASS_SCOPED_PLAN_ONLY独审。此实现候选待独立复验，不签正常F100 route/fixture、真实trace/时限、OS资格或P-4。旧CI266仅属于c6；本候选未推送、未触发CI、未合main。

`battle/request-source.ts`在每个实际Battle的setPlayer之前装一次非枚举实例makeRequest包装，保留原this/返回/异常/次数；无prototype或上游修改。实际Gen8单打p1强制请求成功创建才分配适配器私有域/计数ID；不使用RNG/时间/seq/turn/hash/对象地址。technical-refresh只在网关自身同步finally范围沿用已知pending；原生Side重发/拒绝/失败逃跑/成长刷新不铸号。普通、wait、清除、已选及终局不提供当前来源。checkpoint私有companion保存逻辑来源和队列；JSON snapshot不能恢复来源，新恢复实例使用新分配域防废弃分支碰撞。

内部可选`source`头为非枚举属性，另外用私有消息来源绑定验证，普通JSON/复制的同形头不是来源权限。Object.keys/JSON业务投影、原request payload、消息seq/顺序、BattleSession冻结原型及protocol-v1/持久schema不变。消息旁路只保留轻量authority对象，不因旧消息保留Gateway/引擎引用。

`flow/request-view.ts`私有保存同一条实际消息的payload/source及不可回滚view epoch。旧currentRequest不变；模块级`E.session.readSessionRequestContext(session)`单次返回detached request/source/epoch，或none/unavailable及原因。hold/growth/out/当前选择均成对传递；checkpoint的held/out头通过私有companion重绑。实际恢复在既有只读owner预检后、首次状态变更/await前换代并置restoring；全部旧恢复步骤成功后才发布，失败持续unavailable，不因finally复活。fake/legacy缺来源只关闭严格观察能力，不加玩家动作门。

Scene新增只读`requestObservationState()`，不改旧inputState。单次读取实际Session context和实际菜单字段，并在前后核同Scene/root op/App/stateGeneration/Session；ownerToken还包含本次view epoch寿命。`partySub`/selectedMemberId来自实际Scene，菜单token只识别实际菜单寿命，不承担引擎发生身份。正常玩家流程不调用或依赖此能力。

`flowtest/forced-request-observer.ts`是未注册、无输入/定时器/动作/原生许可的观察器。只有实际相邻ready的forced成员→command菜单、同case/intent/member/Scene/owner/source/epoch才产生确认承接。取消/离路/不可用、错context、新菜单但没观察首次选择均阻塞。查询/按键/确认不推进业务intent；真实业务oracle和完整normal route/fixture仍未接入。

新定向测试为`test-p4-request-source.cjs`、`test-p4-request-source-scene.cjs`，分别包含真实固定Gen8/Session链和编译Scene受控宿主；独立的方法范围模型控制明确标注为pure/direct-method controls，不充当业务trace。测试使用作者合成内容/初始状态与故障注入，没有F100或私有/原版对照。Scene帧、键、媒体与时钟由Node受控，不证明NW、物理输入、字体/音频/性能或真实时限。
