## 入口及所有权

正式`PS_Inventory.ShowBag`、队伍Item→Use、`UseItemOnMember(itemId,memberId?,quantity)`共用现有库存父token和PSEvolution附着控制器。经验糖果保留选择数量；稀有糖果沿原q1；满级稀有与石头先走实际资格／数量／库存检查，无目标、unknown/invalid、配置关、蛋／Shadow等拒绝零消费、不进入动画。脚本未指定成员时展示同一成员选择，返回结束此次尝试；Bag成员选择返回原Bag。默认示例原Bag可直接使用稀有糖果学习，真实石头需要作者配置本物种Item条目，不能给最终形态凭空编造自然进化。

应用仍拥有全部写集。跨级学招按原C队列，选择完成前不写成长／招式／扣量；中间反馈只说“选择已记录”，不是已安装。HM重选与give-up确认保持原问题，即使底层answerIndex因无效回答前进；确认该招成功／放弃后才展示反馈并进入下一招。普通成长一次安装后再显示成长结果／接可取消进化，取消保留原成长和扣量。满级稀有取消时成本＋取消统计一次写；石头Back不能取消，只有成功caption ACK后成本＋身体提交。之后Info／recent／进化学招沿G2a，不重演身体。

`TriggeredResult.primaryCommitted`及只读view中的intent/itemResult/primaryCommitted只是应用结果与呈现信息，不进入GameState或冻结BattleResult。它区别正常无用、未安装技术终止和已经确认的成长／身体；不能把后者回报为未消耗。UI持续持有parent/child保存与遭遇屏障直到最后反馈ACK，关闭最多一次done/end。原生场景顶部Back转交附着的进化／学习子界面，不以父场景terminate绕过石头不可取消规则；真正goto/换档仍走技术终止，旧代不动新owner。

零写故障提供原请求重试／技术结束；重试只安装预备写集，不重复动画、随机或扣物。确认安装后的演出失败回报committed＋presentation failed；丢失readback后恢复证实完整安装也一样保留。partial／无法证实安装必须保留应用屏障与最后完整档恢复，不谎称安全退款。普通成长已提交后中断进化不能误退款或记玩家取消。

## SOL-FINAL-01 r3：领域技术终态与呈现技术退出分开

ultra r2指出可靠Terminate遗漏属实：正式领域`technically-terminated`可表示完整before未写或完整next已写，不能按状态名将它当未知partial。最终反馈ACK必须允许该终态走同一精确死亡父清理。`terminalItem`要求同item owner的真实领域终态token；不以primaryCommitted真假决定是否释放，零写before也须结束死亡owner。
