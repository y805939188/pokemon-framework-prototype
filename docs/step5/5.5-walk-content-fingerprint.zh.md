# 5.5–5.6 普通步行的内容快照与指纹

正式的 `PS_BattleFlow` 通过 `PSFlow.content()` 读取运行时拥有的深冻结快照。首次装载从编译内容构造独立副本，再递归冻结并缓存指纹。运行时消费者以只读方式使用快照，深冻结阻止原地修改。重建并重新装载会生成新快照。测试夹具和外部传入的可变内容仍逐次计算指纹。

5.6 的 `ownedImmutableSnapshot` 保留装配后对象的键枚举顺序，语义指纹继续按键名规范化。正式编译产物中的 grant `items` 键早已按键名排序。5.6 保留编译器现有行为，作者输入的键顺序不属于接口合同。

在固定 5.6 候选的隔离实机采样中，空队与领取初始宝可梦后，落点之后的帧间隔有差异。这项观察限于落点后的帧间隔，样本不足以判定跨落点掉帧或其原因。用户在 5.6 最终版手动走路时未复现原卡顿，反馈是「感觉好像没什么问题」。该结果适用于受测路线，其他场景的性能仍待验证。见 [5.6 验收范围](README.md#56-菜单标题与存档流程)。
