# H3 capture-source fixture after held-item conservation repair

The old capture-party/box setup used the player's Lum Berry with Trick and
expected the captured member to retain it while the original owner recovered
it. That expectation relied on the duplication fixed by F1. The initial
integrated consumer run therefore failed 8 of 53 checks; this was not a hash
failure and is retained in local integration evidence.

The normal-production fixture now uses a supported authored scenario: Snorlax
uses Fling with its Lum Berry, an initially empty-handed Meowth with native
Pickup collects it at the end of the turn, then the player uses a Master Ball.
No capability override, live state injection, or unsupported `foes.item` field
is used. This does not claim support for wild initial held-item author data
(the PBS wild-item fields remain a 5.5 boundary).

New assertions require actual Fling removal and Pickup receipt events, the
captured Lum, an empty-handed original player, and exactly one held Lum across
party and boxes. Existing captured-source placement, next trainer battle Rest
consumption, commit/abort/zero-write retry, complete state/dex/stat checks and
compiled-host checks remain. Reception-cancellation uses the same authored
species. The full dex oracle now distinguishes captured Meowth from the seen
player Snorlax; neither is inferred by copying the actual result.

Seven runtime/host consumer files pass 53/53 on Node 22.21.1 after explicit
runtime/helper rebinding. Intermediate new-test mistakes (old flat boxes path,
then missing player Snorlax in the seen oracle) are preserved as failures and
were corrected without product changes. This is simulated-host/headless
coverage, not NW, physical input, native audio or full 5.4 acceptance.
