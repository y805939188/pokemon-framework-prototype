# C 策略边界第二批：异步调度与场内实际决策重放

本批以 `13b9db0`（构建修复、C 第一批五项整改）为基线。它扩展第一批的同步端口；第一批文档中的 Promise 拒绝、活动流提前消耗和可回滚决定仅描述历史版本。本批待固定候选的独立 ultra 接收，不代表完整 C、第三批、真实 Mac/Windows 宿主、模型接入或精确 CI 已完成。构建基线另有精确 CI173 双 job 通过记录，不冒作本批 CI。

`decide` 可返回 `DecisionPlan | Promise<DecisionPlan>`。composition 仍只接收受信注册，开战固定实际实例/方法、版本、参数和目录身份，active 更新只影响下次开战；可选 `isAvailable()` 是受信后端生命周期探针，不是作者参数、代码哈希认证或模型平台。没有路径加载、模型权重、IPC、主动换人或跨进程战中存档。端口只给 detached 深冻公开 DTO、参数及本次 AI random，不给 driver、ticket、App/Store 或玩家秘密选择。普通对象意图按数据描述符复制；非原生 Promise 的 thenable 不执行。原生 Promise 自有 then getter 不被读取。同进程受信 JS 不是恶意代码沙箱，宿主原型/Promise species 篡改不在安全承诺内。

调度预算是 1000ms，随机回调上限 256 次，均是技术保护而非 NPC 智能配置。测试可注入绑定 receiver 的单调时钟/计时器。同步卡死 JS 无法被 setTimeout 抢占；同步返回或异步落定时再次检查时间，已过期而尚未执行的 timer 也不能接受结果。无模型推理实现，未来独立后端仍须自己处理取消。

每次推理使用私有单调 epoch 和 RNG 副本。取消、App 中止/换代、合法 restore 关闭旧能力；迟到 resolve/reject 被消费但不写活动随机、记录、库存或提交，也不释放 successor。普通同源 request/resource revision 最多重建一次；失效尝试的随机副本丢弃。basic 正常路径仍保留 n/value 次序、独立 seed 与原评分/自疗规则。world/engine 随机不参与策略 random。

只有策略异常、拒绝、超时、非法意图，且真正来源及当前请求仍有效时，才记录故障并零抽样回退首个真实合法 move 或强制 switch。Struggle 必须由引擎提供，不捏造动作、不回退到治疗物品。collector/来源/终局失效、未知执行效果及恢复失败仍是错误屏障；safe no-effect 拒绝可沿原同票据合法顺序有界后备，不重新推理。严格 testing inspector 仍拒非法意图；run 模式的受控回退与历史 batch1 报错分别测试。

场内 immutable journal 上限 4096。key 在私有 owner/lineage 内由真实请求序号/修订及资源修订产生，公开 DTO 或同形 JSON 不产生权限。记录固定规范化 plan、策略 binding 摘要、公开快照摘要及 RNG before/after、回退原因；在首个 driver 回调之前存入，执行成功 candidate 另记，不充当新执行权限。记录不会随 checkpoint 回滚；同一真正逻辑请求重放装载原决定，不再次调用交替/非种子策略。执行权、attempted/submitted、库存及 RNG 仍随合法 checkpoint 恢复。缺记录、摘要冲突、RNG 不一致或容量满受控拒绝；不静默淘汰或换 basic。

restore 的只读 preflight 在 B 的实际 restorer/engine/Session 写回之前检查真实 opaque token、owner/lineage、实际 pin 与记录。无效 checkpoint 不取消合法 pending。有效恢复才退休旧 epoch，Session operation 的 finally 只释放自身代次。推理等待及实际提交/库存登记未知的整个 AI gate 均禁止 checkpoint。B 原有受控恢复工厂保持权威，调用者替换公开工厂不能接管恢复。

新增 `test-trainer-ai-async.cjs` 用真实 Session/Gen8 Showdown、可控时钟及少量明确的 driver/内部故障探针验证 X2–X8/N1–N3；测试工具的 journal/fault/async inspector 不进入生产命名空间。旧纯132/C接线30/策略27/五修31、B/友好度/Store/SDK/协议和 golden 继续纳入 full quick，不把这些计数相加冒充唯一覆盖。历史 batch1 随机断言的变化明确为：双失效修订从活动 draws2 改为0；单次失效后成功从2改为1；正常 rule1保持。来源错误名保持旧门的 stale-generation/checkpoint-owner-mismatch；增加检查次数不改变重入零动作/零额外抽样断言。

本批不接触原 Ruby、私有 raw 或旧双端映射，真实 Ruby5066 历史 FAIL/WARN 及限定观察结果均不改。未跑的真实 NW/Windows、完整 C 与第三批保持 OPEN，不能用本批作者测试代替独立复审。

## C2 独立复审窄修：回调后的所有权检查

C2-ULTRA-01/02 发现真实内容或可用性端口可同步调用取消/恢复。来源资格通过不代表回调返回后仍拥有原操作：本批将 source 检查包在 gate 前后复核之间，决定发布前再核 attempt epoch、取消状态及真正请求；时钟返回后同样复核。取消前尚未合法发布的决定不得写 journal/RNG/cache，重试须新推理。已经合法发布且后续执行故障回滚的记录继续保留，不以清空日志消除差异。

Session 恢复在只读 preflight 进入时捕获操作 epoch 和 driver；全部资格回调返回后再核恢复互斥及原 owner。若回调已开始更新的恢复或操作，外层旧恢复受控拒绝，不再进实际 restorer，不清理新 owner；foreign/缺记录/冲突/不可用 pin 的失败预检仍不提前退休 pending。没有新增全局状态机、持久 schema 或策略能力。

`test-trainer-ai-c2-remediation.cjs` 保留旧60fb上的7个红例和5个邻接正控，覆盖同步/异步、正常/回退发布、内容/可用性/时钟/清理回调取消，以及实际B/Showdown恢复重入、正常恢复、嵌套错误预检和正常操作抢先。新候选自测及独立复验分别登记于外部证据，文档不自行关闭 C2、C3、宿主或 CI。
