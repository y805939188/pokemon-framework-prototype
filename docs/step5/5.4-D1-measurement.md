# D1 桥接、控制器和 F100 测量

本入口落实已审 D1 measurement-v1 合同。批准材料与独立方案报告位于工作区 `.verify/step5-4-D1-measurement-contract-20261031T0318Z/` 和 `.independent-reviews/step5-4-D1-measurement-plan-ultra-20261031/`。方案通过不等于代码、P-4或D2验收。D2演出和精美UI未启动。

控制版本必须完整继承已审 carried-faint 修复1b68471，再加与候选相同的 driver、输入、配置、seed及采样接缝。它是有新SHA的桥接文字场景，不是原2ff字节，修复收益不算控制器收益。候选只在这个基线上接最小宿主控制器。两者仍用同一Session/App及锁定Gen8 Showdown作为规则/战斗状态权威。

## 输入与运行

`experiments/step5/4/d1/f100-v1.json`逐条给出100个唯一ID、固定顺序、请求、seed、初始化/补给和预期。25轮各含野生胜、野生捕获、训练家胜、训练家败/D3；单进程不额外预跑战斗，不每场重启、清缓存或重置整档。初始2成员、后续捕获/账本/统计保留。正常治疗可能返回healed或合法unchanged，驱动同时验证实际HP/异常/PP完整恢复，不能将无须治疗误记失败。

第1个训练家胜利真实覆盖玩家用药、NPC FullRestore、挡球、主动换人、学招以及持物消费/暂时打落后恢复。作者给出的招式、低HP/濒死前置和开发来源能力是显式测试数据，不冒充官方合法配招或自然游玩。原输入未因试点失败换seed/删场景。最终固定输入与双版本源码/包指纹必须在正式运行前另行封存。

新驱动`flowtest/d1-benchmark.ts`同时支持旧文字场景语义桥接和候选的inputState端口。选择由真实MZ菜单handler执行，忙态/ready/终局/学习仍走实际Scene/Session。程序化菜单选择和快进是明确的测试输入，不能称实体键鼠。CommonJS模拟器的协议Date.now固定为输入clock以便完整状态比较；渲染器Date/单调performance/真实超时不改，原生Promise仍正常异步。

使用干净固定源码分别构建测试包后：

```sh
python3 scripts/run-d1-benchmark-mac.py /absolute/control.app /absolute/candidate.app /absolute/new-evidence
```

runner顺序为3对自然插桩、1对自然未插桩、1对GC诊断，**10进程/1000战**。GC与未插桩不混入三次自然中位数。每进程独立profile/测试存档及进程组，串行执行且不同时build/test其它GUI。原始失败全部保留，失败即停，不重复至绿或合并不同版本成功样本。`--groups ... --pilot-count N`仅资格试点，不成为正式P-4。

正式比较要求两个不同干净提交、相同完整payload（仅允许包自身元数据与PS_BattleFlow.js差异），同一测试plugin/实际engine/内容/素材。每场核实际resolved seed、ID顺序和结果，两个实现分别报告legacy或controller身份，十组完整最终框架状态hash必须一致，不以删字段/抹时间戳消差。实际包全文件前后hash和执行PID/exit/timeout封存；缺场次、空筛选、fatal、崩溃或包变化失败。

## 时钟与内存

updateMain和rAF保留独立原始t/dt/count；>33ms按严格33定义，并给p50/p95/p99、max及原始长帧。ready、输入、action、AI预算clock观察、准备提交/实际install/返回地图分段，D1不假造D2有意过渡。AI的首末timing.now是预算/调用窗口，不是纯评分CPU归因；driver/oracle和已有PSFlow.perf的开销明确留在报告。未插桩关闭新细粒度探针，保留语义输入、边界结果/hash检查及原有生产perf记录，不声称零观测开销。

自然组不expose-gc；GC诊断仅在初始、4/50/100及idle120游戏tick采样点显式调用并记录。Renderer RSS、Node heap、浏览器JS heap、整app RSS分列，raw bytes和MiB明确。managed计数仅是当前可达显示树中的texture/bitmap/window/event listener及root owner/barrier，不是全局分配、无泄漏证明或静默丢弃离树资源。

采样器只从本次Popen PID递归查直接子PID，并对这些PID读取RSS/可执行路径/父链；不全机ps、包名模糊相加或终止无关进程。采样失败/权限拒绝/部分树用null+UNKNOWN和准确原因，不用Renderer冒整app。前台、visibility、816×624、DPR2和实际原生版本留档，失焦保留并影响可比性，不筛掉或重跑。

旧 `perf-budget.json`的+20%与7.2MB仍是WARN；旧负载不等于新F100，缺同契约基线为NOT_COMPARABLE。记录桥接/候选原始分组与差异，不自动关闭旧RSS WARN、appRSS UNKNOWN、CPU/分配归因或实体输入专项。D1/P-4独立处置前不进入D2，Windows/Intel宿主、Linux延期和原Ruby历史状态保持各自边界。
