# D1 桥接、控制器和 F100 测量

本入口落实已审 D1 measurement-v1 合同。批准材料与独立方案报告位于工作区 `.verify/step5-4-D1-measurement-contract-20261031T0318Z/` 和 `.independent-reviews/step5-4-D1-measurement-plan-ultra-20261031/`。方案通过不等于代码、P-4或D2验收。D2演出和精美UI未启动。

控制版本必须完整继承已审 carried-faint 修复1b68471，再加与候选相同的 driver、输入、配置、seed及采样接缝。它是有新SHA的桥接文字场景，不是原2ff字节，修复收益不算控制器收益。候选只在这个基线上接最小宿主控制器。两者仍用同一Session/App及锁定Gen8 Showdown作为规则/战斗状态权威。

## 输入与运行

`experiments/step5/4/d1/f100-v1.json`逐条给出100个唯一ID、固定顺序、请求、seed、初始化/补给和预期。25轮各含野生胜、野生捕获、训练家胜、训练家败/D3；单进程不额外预跑战斗，不每场重启、清缓存或重置整档。初始2成员、后续捕获/账本/统计保留。正常治疗可能返回healed或合法unchanged，驱动同时验证实际HP/异常/PP完整恢复，不能将无须治疗误记失败。

第1个训练家胜利真实覆盖玩家用药、NPC FullRestore、挡球、主动换人、学招以及持物消费/暂时打落后恢复。作者给出的招式、低HP/濒死前置和开发来源能力是显式测试数据，不冒充官方合法配招或自然游玩。原输入未因试点失败换seed/删场景。最终固定输入与双版本源码/包指纹必须在正式运行前另行封存。

新驱动`flowtest/d1-benchmark.ts`同时支持旧文字场景语义桥接和候选的inputState端口。选择由真实MZ菜单handler执行，忙态/ready/终局/学习仍走实际Scene/Session。程序化菜单选择和快进是明确的测试输入，不能称实体键鼠。CommonJS模拟器的协议Date.now固定为输入clock以便完整状态比较；渲染器Date/单调performance/真实超时不改，原生Promise仍正常异步。

使用干净固定源码分别构建测试包后：

```sh
python3 scripts/run-d1-benchmark-mac.py /absolute/control.app /absolute/candidate.app /absolute/new-evidence
```

runner顺序为3对自然插桩、1对自然未插桩、1对GC诊断，**10进程/1000战**。GC与未插桩不混入三次自然中位数。每进程独立profile/测试存档及进程组，串行执行且不同时build/test其它GUI。原始失败全部保留，失败即停，不重复至绿或合并不同版本成功样本。`--groups ... --pilot-count N`仅资格试点，不成为正式P-4。

正式比较要求两个不同干净提交、相同完整payload（仅允许包自身元数据与PS_BattleFlow.js差异），同一测试plugin/实际engine/内容/素材。每场核实际resolved seed、ID顺序和结果，两个实现分别报告legacy或controller身份，十组完整最终框架状态hash必须一致，不以删字段/抹时间戳消差。实际包全文件前后hash和执行PID/exit/timeout封存；缺场次、空筛选、fatal、崩溃或包变化失败。

接收器必须独立验证原始报告中的完整 `input`、`initialState`、`finalState` 与各自hash，跨组只比较经过验证的初始/最终hash。`scripts/d1-report-hashes.cjs` 使用项目Node22+及内置crypto，按与原生驱动相同的ECMAScript `JSON.stringify` 序列化整个对象，不挑字段或使用Python浮点/属性排序代替。它要求非空对象和真实SHA256，拒绝数值溢出、下溢及不是原生JSON.stringify格式的数值别名；没有Node或验证失败立即停止。完整报告字节hash与验证结果另存 `HASH-VERIFICATION.json`。只篡改money却保留旧hash、缺状态或伪hash不能接收。

合成工具控制显式传 `--synthetic-controls`；即使跑完十组，也只能生成 `SYNTHETIC_TOOLING_NOT_NATIVE_NOT_P4` / `SYNTHETIC_CONTROLS_EXECUTED`、`totalBattles:0` 和单列 `syntheticCaseRecords`，不登记真实战斗或AUTHOR_EXECUTED。默认原生入口拒绝脚本启动器，要求Mach-O和本轮darwin/arm64运行标识；这只是避免把Python夹具当原生进程的入口检查，不是恶意宿主认证平台。合成单组也使用显式synthetic参数，仍走完整hash/输入/场次/采样拒绝门。可用 `python3 scripts/tests/d1-benchmark-runner.test.py` 复核工具控制。

## 时钟与内存

updateMain和rAF保留独立原始t/dt/count；>33ms按严格33定义，并给p50/p95/p99、max及原始长帧。ready、输入、action、AI预算clock观察、准备提交/实际install/返回地图分段，D1不假造D2有意过渡。AI的首末timing.now是预算/调用窗口，不是纯评分CPU归因；driver/oracle和已有PSFlow.perf的开销明确留在报告。未插桩关闭新细粒度探针，保留语义输入、边界结果/hash检查及原有生产perf记录，不声称零观测开销。

自然组不expose-gc；GC诊断仅在初始、4/50/100及idle120游戏tick采样点显式调用并记录。Renderer RSS、Node heap、浏览器JS heap、整app RSS分列，raw bytes和MiB明确。managed计数仅是当前可达显示树中的texture/bitmap/window/event listener及root owner/barrier，不是全局分配、无泄漏证明或静默丢弃离树资源。

采样器只从本次Popen PID递归查直接子PID，并对这些PID读取RSS/可执行路径/父链；不全机ps、包名模糊相加或终止无关进程。采样失败/权限拒绝/部分树用null+UNKNOWN和准确原因，不用Renderer冒整app。前台、visibility、816×624、DPR2和实际原生版本留档，失焦保留并影响可比性，不筛掉或重跑。

旧 `perf-budget.json`的+20%与7.2MB仍是WARN；旧负载不等于新F100，缺同契约基线为NOT_COMPARABLE。记录桥接/候选原始分组与差异，不自动关闭旧RSS WARN、appRSS UNKNOWN、CPU/分配归因或实体输入专项。D1/P-4独立处置前不进入D2，Windows/Intel宿主、Linux延期和原Ruby历史状态保持各自边界。

## 最小宿主控制器

`src/plugins/battleflow/controller.ts` 是只依赖ES2022的内部呈现控制器，拥有消息文本队列、等待tick、输入phase、busy/ready和一个动作的epoch。Session是opaque句柄；HP、PP、道具台账、AI、成长、持久提交继续由原Session/App负责。控制器不引用Window、Graphics、Node或battle私有对象，不导出到公共SDK，不新增D2演出或第二份业务状态。

正式Scene在initialize捕获root op及已有App/generation，打开前绑定新建App，跨Promise和每个可重入呈现端口后重新检查。dispose、换档、owner替换和finish-transfer使旧epoch失效；旧resolve/reject不能写后继菜单、perf、root或pop其场景。动作完成后仍在busy保留期内执行测量/格式化，再释放输入；重入和重复动作拒绝。消息fast-forward只推进原批次，渲染回调新加的文本留到下一tick，不形成无限循环。

Scene提供 `inputState()` 的分离DTO：phase、实际Window可交互且controller允许输入的ready、标量key/enable列表及实现身份 `d1-controller-v1`。MZ在调用OK/cancel handler之前会停用Window，因此handler以controller阶段/busy/队列守卫，DTO则额外观察Window实际active；不能把“scene对象存在”当ready。旧 `_mode/_busy/_queue/_wait/_ready/_failure/_session` 是同一控制器的兼容访问器，旧T编号及语义断言保留。

结束时原PSFlow.finish/abort及App仍是提交与保存/事件等待的权威。控制器先退役回调，接收/进化交接继续保持同一root owner；旧scene terminate不能中止接收者。提交后宿主消息错误沿用原hostErrors记录，不能撤销已提交战果。操作已被外部关闭时，本地控制器收尾而不重复中止后继；第二次错误呈现故障只能在仍拥有该scene时释放自身视图。

`experiments/step5/4/test-scene-controller.cjs` 编译实际纯模块（types=[]、lib=ES2022）和真实插件，使用受控呈现/Session端口验证迟到打开/动作、throw/reject、重入、App代际、换档、队列、菜单ready、终局学招、强制替补、接收/进化交接及保存/提交结果。它不冒充NW或实体输入。旧原生T1–T35（含T15b）、验证存档/空源及F100资格仍须实际运行并保存精确非空ID；controller候选和正式P-4各自独立复审，不能拿桥接通过代签。

## v2 接收门与共用宿主驱动

F100-v1的100条业务输入、顺序、seed、预期和时钟不变。修订驱动输出为 `D1-F100-output-v2` / `D1-driver-v2-port-order`，采集器拒绝旧输出作为新运行；两个比较包必须使用相同修订驱动和测试插件重新构建。原v1资格及历史失败原样保留，不转换成新正式样本。类型化 `flowtest/d1-timing.ts` 遵循 `after(milliseconds, callback)`，同步basic负载之外另用实际异步AI验证截止、取消timer和迟到结果不再次发布；这不等于F100已包含异步模型负载。

采集器记录并在每组退出后核对整个app（普通文件字节、权限、目录及内部链接目标），失败退出也保留前后清单与完整EXECUTION。配对宿主限定当前thin arm64 Mach-O：签名外字节、Frameworks、其余资源/链接相同；Info.plist仅允许CFBundleName/CFBundleDisplayName、package.json仅允许name不同。每包先通过codesign deep/strict；主程序CodeDirectory只排除Info.plist/CodeResources两个派生摘要，代码页、签名flags、requirements及entitlement blobs仍必须相同，不能豁免整份二进制或签名策略。未知格式拒绝，非跨平台宿主认证系统。所有组nw/node/chromium/v8/platform/arch一致，实际argv按自然/off/GC冻结模板分别留档。

报告中的appRSS逐ID/status/bytes/processes/reason绑定采集器实际采样；无对应样本不得标value。UNKNOWN不补零。完整初末状态先用实际包core的现有validateGame只读校验，要求当前schema；最终账本恰为本轮case ID且都有pairHash，逐行commit和battleId匹配、最后一行afterStateHash与完整最终状态同。中间afterStateHash只验证格式，未保存各场完整状态，不能宣称逐场独立重算。哈希验证器记录Node和脚本/core身份。

退出后再次查fatal；TERM/HUP进入统一FAIL_STOP并只清理本次自有进程组。原始失败与清理失败分别记录，不能用清理EPERM遮掉fatal。新控制器每次真实Scene.update都检查自有操作关闭，main/pending不能被phase/busy挡住；迟到reject也不能重复调用应用abort。

共用旧宿主夹具版本为D1-host-driver-v2：T9用当前schema+1；T11注入真实session恢复接缝；T30从实际Session得到合法结果后核首次提交和__proto__重放；U51-14白名单构造schema4；空源通过正式compiler构造并在冷boot也使用自洽空文档。保留全部原ID及业务断言，旧红报告不改。`--ps-flow-test=d1-lifecycle`另有四条真实宿主生命周期控制，须观察真实update/DOM结束输入，不把直接updateQueue当补证。

测量是披露的测试App组合：不含正式logger及部分world/variables/creation/limits端口开销，timing使用renderer适配；菜单直接调用已注册handler，绕过processOk的deactivate/音效。对比双方公平，但绝对耗时不代表完整正式组合或实体输入。新Node测试验证正式deactivated handler兼容，不能因此补计这些测量开销。GitHub headless新增两组Python采集器合成控制；它们明确不运行NW、不计算真实战数，也不代表P-4。精确新SHA CI结果仍需另行取得。
