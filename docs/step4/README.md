## 1. 已确认的决定

- **D1 满队捕获/接收**：队伍未满入队；队伍满而盒子未满入盒；队伍和盒子都满才拒绝投球（经冻结协议已有的 `noBall` → `ballsdisabled`，B 批）。领取同样先队伍后盒子，放不下整笔拒绝。没有盒子界面：入盒会明确提示“本版暂不能取出”。
- **D2 持久物种键**：沿用 `Member.species` = 固定 Showdown 版本的物种名。作者内容用小写内容 ID（`charmander`），组装时映射到持久键（`Content.speciesIds`，`resolveSpecies`）；存档不变。
- **D3 战败**：WP42 §6.1 + WP61 §7.2。败或平（结果码 4）时，扣 `min(余额, 队伍最高等级 × 8)`（本版无徽章状态，徽章恒 0，因子 8；插件参数 `noMoneyLoss` = NO_MONEY_LOSS），并全队完整治疗；这两项与战斗结果**在同一次状态替换里**提交，身份就是该结果的 `battleId` + 结果哈希（`appliedBattles`），所以重复结果 `already-applied` 时不会再扣钱或再治疗；冻结协议和 `BattleResult` 没有新增字段。提交之后，宿主把玩家送回配置的“家”（插件参数 `homeMapId/X/Y/Direction`；未配置则只治疗、不移动，同 WP61 §7.2“无有效家”）；事件战斗随即结束该事件。回程失败（例如转移报错）不撤销提交，记在 `PSFlow.pendingReturn`，`PSFlow.retryReturnHome()` 只做转移、不再结算。`StartBattle` 的 `canLose = true` 时不回程、事件拿到结果 4 继续（钱和治疗仍按 WP42 §6.1/§7.1 执行）。

## 3. 插件命令（C 批汇成一页总表）

| 命令 | 参数 | 前置条件 | 结果 | 是否等待 | 事件用法 |
|---|---|---|---|---|---|
| `ClaimGrant` | `grant`（内容 `grants.json` 的 ID）、`resultVariable`、`message`（默认 true） | 有框架状态（新游戏或读档） | 变量 1 = 本次发放；2 = 已领取过（不变）；0 = 拒绝（未知奖励、背包某项超过 999、队伍和盒子放不下、存档不可用；什么都不发、不写凭证） | 只在显示消息时等消息关闭 | NPC 对话里一条；按变量分支说不同台词 |
| `HealParty` | `resultVariable`、`message` | 同上 | 变量 1 = 已治疗或本来就满（重复调用安全）；0 = 拒绝 | 同上 | 护士/床 |
| `StartBattle` | `kind`、`foes`（`Species:Level`，物种可用内容 ID 或持久名）、`battleId`、`resultVariable`、**`canLose`**（默认 false） | 同上；至少一名可战斗成员 | 1 胜 2 捕获 3 逃跑 4 败/平 0 中止（不能开战也是 0）。败/平：扣钱 + 治疗；`canLose` 为 false 时回家并结束本事件 | 等战斗结束 | 沿用；**行为变化**：以前败北只回 4，现在默认按 D3 回家 |
| `ShowParty` | — | 同上 | 打开只读的队伍/盒子数量/背包/金钱界面（主菜单也有“Party/队伍”一项） | 界面关闭后继续 | 告示牌 |
| `ResetGame` | — | — | **测试辅助**：装入第二步的合成夹具队伍（三只 50 级），不要用于正式游戏 | 否 | 仅测试 |

插件参数（`PS_BattleFlow`）：`startMoney`（新游戏金钱，默认 3000，WP24 StartMoney）、`noMoneyLoss`（默认 false）、`homeMapId`/`homeX`/`homeY`/`homeDirection`（战败回程点；本工程设为 Map005 (8,9)）、`contentSource`、`language`。

### 地图遭遇

在地图备注里写一个标签（只在插件里解析，应用层收到的是普通数据并做校验）：

```
<PSEncounter:regions=1;pidgey,60,2-4;caterpie,40,2-4>
```

`regions=`（可省略，省略 = 整张地图）后面每段是 `物种,权重,最低-最高等级`；物种用内容 ID 或持久名。**何时**触发沿用 MZ 自己的步数计数（地图设置里的“遇敌步数”，本切片 20）；触发时由应用层按 WP36 §5.1 选物种和等级、从内容生成个体并开战。事件执行中、已有战斗打开时不触发；没有可战斗成员时不触发；备注格式或数值不合法时不触发并在控制台说明原因。战后重新抽步数，不会立即再触发。

### 保存守卫

开战时记录 `$gameSystem.isSaveEnabled()` 并禁存，结束或失败时恢复为原值（事件原本禁存就保持禁存）。菜单存档、自动存档看的是同一个开关；直接调用 `DataManager.saveGame` 在战斗中被拒绝。被拒或写入失败的保存记录在 `PSState.lastSaveError`（`battle-running` / `write-failed`，含槽位与时间），成功保存后清空。`commitResult` 是同步的，没有“提交中”的窗口。

## 4. 新游戏与旧存档兼容策略

- 新游戏（`DataManager.setupNewGame`）由应用层装入**正式空状态**：schema 3、无成员、空背包、金钱 = `startMoney`、无凭证。成员只通过领取（或之后的捕获）获得。夹具队伍只能由测试显式选用（`ResetGame` / 测试驱动）。
- 读档时 `$gameSystem._psGame` 不存在（框架状态出现之前的存档，或从未用过它的存档）：装入正式空状态，**金钱 0**、无凭证，`_psSaveInfo.created = "empty"` 记录这一点；不伪造队伍或物品。
- schema 1/2 的存档迁移到 3（2→3 只加空的 `claims`），比本版新的 schema 仍拒绝并保持原样。
- 已有存档里超过阶段容量的数量（某物品 > 999、金钱 > 999999、盒子 > 1200）**不报错、不删减**；只有继续增加会被拒绝（领取整笔拒绝；金钱不再增加但不会被扣到上限）。
