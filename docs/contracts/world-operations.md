# 世界操作、移动与恢复

- 保留 MZ 直接移动手感：普通移动完成后才检查普通遭遇。原地转向和撞墙不计普通步、不额外遇敌；不引入参考式 75ms 转身延迟。登记为有意偏离。
- 世界时段默认现实日历时间，可注入；钓鱼使用可暂停的单调经过时间，失焦暂停，不默认截断聚焦时的卡顿时间。
- 保留作者常用地图连接、标准转移，以及事件伙伴注册、解除、跟随、转移和恢复的最小闭环；复杂无缝拼接和复杂剧情跟随编排延期。事件伙伴不是 MZ 队伍跟随者。
- 宝可梦病毒的生成、传播、日期变化及 EV 效果整条链延期；不加无消费者字段，不消费该链随机数。
- 纳入最小快捷登记与调用、Fly 已解锁目的地列表和共享地区数据；不做完整地图编辑器。这里“已解锁”仅指由已访问地图及合格区域点记录派生的可选目的地，不存在独立的持久解锁集合。
- Headbutt、Dive、Waterfall 暂缓。
- 黄昏球按真实时段／洞穴业务事实判断，不受纯视觉昼夜着色开关控制。

## 状态与所有权

- 成员、背包、金钱、已有统计：沿用框架既有状态和 Application；迁移不得覆盖。
- 全局步数：框架唯一完成步操作写入，不能在移动开始和完成时各写一次；复用既有字段。
- 驱虫剩余步数：框架道具／步后操作持久化；旧档默认 0，本步保护使用本步开始的快照。
- 四个黑／白笛局部标志与 Strength 局部标志：真实跨图（显式跨图传送、边缘连接）及 两种正常读档进入时清除；同图显式传送保留。可采用运行期状态，但新游戏／读档必须重置，不能残留上一游戏运行态。
- flashUsed：框架持久业务状态；有效遮罩存在、前置演出和文本正常完成时先写 true 与次数，再展开光圈。无有效遮罩则失败且不写；展开过程中异常不回滚已提交值。进入或恢复非黑暗地图时清除；黑暗地图间切换、黑暗地图读档时保留。显示层重建按同一规则幂等处理。黑暗事实不可用时不清除、不建遮罩并诊断；可用元数据中无该地图条目才按未标黑暗处理。
- 世界天气业务意图：由框架持有完整业务值并持久化，宿主屏幕作单向表现投影；不能从淡出中的旧显示类型反推意图。旧档按已验证的旧宿主天气映射初始化；未知输入拒绝或明确诊断，不凭空猜测。
- encounterVersion：框架业务状态，旧档默认 0；非法版本拒绝，内容查找／回退按正式合同。
- 遭遇宽限和累加：框架运行状态；分别明确新游戏、读档、真正进图、战斗、冲浪、版本变化的重置／保留，不笼统全部清零。持久与否及用户体验必须有明确测试。
- visitedMaps：框架记录成功进入／恢复的合法当前地图；旧档缺记录时只通过正式进入／恢复通知补记当前地图，不推断其它历史访问。Fly 目的地是派生结果，不建立独立持久解锁集合或作者事件解锁系统：同一地区地图格只取首条点记录，检查完整治疗／飞行三元组、其中目的地地图已访问及开关可见性；首条隐藏或不完整时不回退后续记录。没有开关字段则可见；带开关字段且开关号 ≤0 则隐藏；其它情况对应开关必须为开。只列当前所在区域的目的地，按当前地图区域定位元数据确定，缺定位时区域为 0。当前图已访问不等于无条件可飞。地区数据由 Fly 与图鉴各取窄投影，不造两套真相。
- 最近治疗中心、Teleport 返回点、Dig／逃脱点、静态家：分别定义来源、持久性、优先级、消费及清除；不能混成一个位置。
- 快捷登记：框架持久的有序道具列表；自动列出的队伍场外招式是派生结果，不持久缓存，执行时重新验资格。
- 多名有序事件伙伴链：框架持久，稳定原地图／事件身份；重复注册去重，来源无效应诊断且有恢复策略。
- Surf 业务模式：唯一业务权威和宿主通行／姿态单向投影；非法恢复位置必须明确处理。
- cycling／diving：仅在确知未骑行／未潜水时给 false；事实读取失败仍为不可用或非法，不能伪装 false。
- pending blackout return：只持久化确需恢复的身份、目的地、已完成阶段及结算标识；不得重复扣钱、治疗或统计。
- 实际地图、坐标、朝向和作者的 MZ 跟随者显示意图：宿主权威；框架不保存另一套可随意独立改写的位置。
- MZ 遇敌允许开关：宿主已有作者开关，框架遭遇模式必须读取并尊重，不建立可独立冲突的镜像。
- 操作令牌、函数回调及临时锁：运行期，不序列化；读档／新游戏更换代次，使旧回调失效。

## 宿主移动与天气

**读档进入**：MZ 正常读档后直接进入地图场景，不会发出框架需要的进入通知；适配器必须合成一次“读档进入”，用于重置局部运行态、补记当前已访问地图及适用的回程目的地处理。`reloadMapIfUpdated` 登记的同图转移归入读档重建分支，不能误当成保留局部标志的同图显式传送；同图天气不重掷。

**236 完整兼容合同**：战斗中整段跳过，不改天气且不等待；非战斗中沿用原 `changeWeather(type,power,duration)`，仅等待标志为真时按原 duration 帧数等待，总是返回 true。none 加淡出时业务天气立即为 None，显示可继续淡出；不要拦截 `Game_Screen.changeWeather` 造成框架自身投影回环。

## 二、移动入口矩阵与遭遇开关

入口、计步／被动及遭遇规则：

- 直行完成、换向后完成：每个实际完成步一次；每步至多一次遭遇。
- 原地转向、撞墙：不计普通步、不额外遭遇。
- 点击／触摸目的地：逐格完成各计一次；遭遇时清除旧目的地，防止战后自动续走。
- 到达事件格：该步的适用被动仍执行；到达事件被处理后不普通遭遇。
- 地图连接边界：跨边动作只计一次；使用正确的目标落点事实，若事件／转移阻断则不遭遇。不得原图和目标图各记一次。
- 伙伴自身移动：不触发玩家计步或遭遇。
- Surf 上下水跳跃：能力专用操作，不伪造普通步；之后正常移动按实际步处理。
- 强制路线／解释器移动／跳跃：按各自专用规格分类，不默认当普通玩家输入。
- 普通传送、读档恢复：不计额外普通步。
- 钓鱼、Sweet Scent、Rock Smash：各走主动入口，不套普通移动概率。

MZ 命令 136（Change Encounter）在 framework 模式必须控制适用的普通随机遭遇，不能被新触发器忽略；其原生计数重置不得在框架模式额外消费不需要的原生 RNG。legacy 和 native 模式保留自身计数语义。作者显式事件战和随机遭遇开关的关系须分别定义，不能笼统禁止所有战斗。


## 三、步进顺序与等待终态

唯一完成身份 → 锁存本步位置、地形、适用队伍和起始驱虫有效性 → 提交计步、适用友好及驱虫递减等前缀 → 必要时在同一父操作内询问续用并打开过滤背包 → 检查操作代次、地图和相关状态后继续毒伤／全灭 → 与到达事件串行调度 → 仅在事件及其他门未处理时进入普通遭遇。

驱虫从 1 降到 0，本步仍受起始快照保护；续用成功只扣一次，取消不撤销已经完成的步数。续用和到达事件不得争抢消息窗，也不能静默丢弃询问。事件或外部操作若改变地图、读档代次或队伍，必须验证是否允许继续，不能盲用旧快照。

终态：

- 重复答复只接受一次；旧代次回调无效。
- 读档／新游戏使旧操作失效；不能对新状态写入。
- 等待期正式保存明确拒绝，不只依赖菜单不可见。
- 场景关闭或宿主异常：保留已提交前缀，停止未提交部分，释放本操作自己的锁。
- 开战失败：不重复计步、不自动生成另一只；给出明确可处理终态。
- 地图目标加载失败：不越界、不覆盖当前地图数据，允许明确重试或取消。
- 回程传送失败：只重试未完成阶段，不重复已结算部分。
- 不虚称整个跨 UI 流程能单次原子回滚；逐阶段记录提交边界。

## 四、四种遭遇模式与随机合同

- framework：正式表和框架触发是唯一权威，MZ 原生敌群不能另开战；原生计数不参与触发。
- legacy-note：旧 PSEncounter 备注按既有兼容路径运行，记录新规则不适用之处；不使用正式表的完整规则。
- mz-native：保留宿主原生路径及计数。
- none：两种随机遭遇路径都关闭。
- 同图正式表和旧备注冲突给清晰诊断，不叠加；框架恢复失败时不静默回退到原生战斗。各模式的计数和重置逐一验证，不能要求四种模式的原生计数都不变。

按规格核实普通遭遇各阶段：机会／类型与触发 → 候选物种及等级 → 允许门（含适用驱虫等）→ 单打约束／双打门 → 开战及完整个体生成。队首、道具、哨子修正分属正确阶段，不能集中成泛化修正。被驱虫拒绝时不得提前生成完整个体或消费生成专用随机数；本框架的普通遭遇强制单打在双打概率抽取之前返回，不抽不使用的随机数。

RNG 消费目录至少列触发、候选、等级、允许门、生成、钓鱼、场外效果、视觉及延期病毒：各自列抽取条件、范围、次序、早退不抽的条件。用途可注入并可重放；如果声称独立随机流，须有独立状态或明确派生，多个函数各自调用同一 Math.random 不算独立流。具体概率、范围和修正顺序必须追溯净化规格；不得为合同完整而编造数值。

## 开战上下文与回程

事件命令的空白天气/地形/环境保持原来的 none，显式 none 覆盖世界，inherit 使用进入时锁存的业务事实。普通遭遇可使用世界默认；字段逐项解析，非法值不能当作空白。HeavyRain 映射 rain，Storm/Fog 是否带入地形取决于 `OVERWORLD_WEATHER_SETS_BATTLE_TERRAIN`。`battleTime` 只选择背景时段，不参与捕获。

洞穴判断使用地图业务元数据而不是洞穴遭遇表；诱饵球依据实际钓鱼来源；黄昏球使用实际时段／洞穴事实。战斗开始锁存来源、环境与时段，捕获时不重新读取当前世界。晴天进化提供明确 value:“None”；不可用不能当 absent 或 false，从而错误跳过有序进化条目。

地图连接应有方向、偏移、目标及落点／通行校验；邻图可预取或受控异步等待，不强制大型缓存框架。目标未就绪或失败不得非法越界、覆盖当前数据或永久静默表现为不可通行。跨边、Surf、伙伴及进图事实应一致。

- 战败入口复用已有结算凭证；野外全灭自己幂等处理，不扣战败钱。治疗、统计、载具／伙伴等副作用按适用分支在预定转移前、至多一次提交，不重复现有战败结算；保留 lateHeal／战败后进化与回程顺序。
- `reserveTransfer` 成功只表示预定；只有 `performTransfer` 实际成功并确认目标地图及坐标后，才能同步确认抵达、清检查点并释放阻止保存的操作。此确认必须早于 `onTransferEnd` 自动保存。不能笼统要求“所有 GameState 写入在转移前”。
- 预定后尚未落位不能标记完成；异常／失败保留稳定可恢复检查点。活动转移期间禁存；失败后的稳定状态必须可以保存，或有经证明的可靠落盘方案。重试只做未完成阶段，不重复结算，不静默改目标；失败和恢复可见。
- 冷 Continue 恢复须等地图场景就绪、且 MZ 没有待执行转移（含 `reloadMapIfUpdated`），不能叠加两个转移。

只有宿主实际请求了自动存档才延期、去重并执行，不凭空造一次自动存档。详见[地图与旅行](../maintainers/world.md)和[遭遇统计合同](../testing/encounter-statistics.md)。
