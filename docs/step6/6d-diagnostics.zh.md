# 6D：普通失败提示和隔离诊断边界

批准 r2 T05 的本轮切片：生产运行组件／新游戏启动、坏编译内容、训练家入口、查询/设置徽章，以及原 WP07 的五条 Management 事件包装。源内容编译、战斗/物品/徽章和存档规则保持原样。具体发行与实机验收另行确认。

| 故障 | 普通运行／伪 test | 已认证本地隔离构件 |
| --- | --- | --- |
| BattleFlow 首次装载生产组件或新游戏初始化失败 | 组件加载／依赖解析失败为 PF-ENGINE-LOAD，其他未识别的初始化失败为 PF-NEW-GAME，已有安全的内容短码保留。启动保持原有捕获语义，不安装替代状态、不使用 fixture。初始化记录、console 及后续无状态错误不含原异常、路径、require 栈或 JS 堆栈，已有存档字段不作为可见文本来源。 | 仅已绑定且实际生效的隔离构件可额外给固定相对入口 `js/engine/build/production.cjs` 与修复提示；不显示具体依赖、原始原因或真实位置。 |
| BattleFlow 无法读取、解析、适配或验证编译内容 | 游戏数据不可用，短码区分 READ / JSON / VERSION / INVALID。无文件名、任意验证键、原异常或运行栈。内容不缓存、不切换到 fixture。 | 相同玩家提示；本地 console 可额外给固定相对路径 `data/framework/content.json`、固定阶段提示和 `$`／`$.schema`。不显示实际失败输入或任意 JSON 键。 |
| 未知训练家、坏参数或特殊宿主拒绝 | 原事件继续/拒绝/异常契约不变。未知训练家按现有语义写本次结果 0，并显示不含原始 ID/版本的提示；固定参数格式仍可指引，不拼接宿主错误。 | 同样安全；本轮未给训练家增加地图定位或导出原异常。 |
| QueryBadge / SetBadge 拒绝 | 已知整数、布尔、索引或变量问题可用稳定原因，其余仅安全短码。保持原结果变量与应用规则。 | 同样安全；本轮不增加位置或输入日志。 |
| ShowMessage、ShowChoices、ShowNumber、ShowTextInput、RegisterHallOfFame | 保留原安全 WP07 错误，停止/显示行为不变；裸 `Utils.isOptionValid('test')` 不授权定位。 | 只有同一私有 stage 出品的 Management 且对应 SaveLocation 实际绑定工作时，额外输出固定插件/命令、有限数值定位、由解析器发出的字段/提示；无法确认位置就留空。 |

隔离正例是维护用测试构件，不是独立的生产作者模式。直接设置插件参数、裸 test、普通二进制或缺失、混合、被替换的储存绑定，均不授权展开。没有安装新的全局 hook、每帧扫描、持久日志或联网；普通插件的安装顺序未改。真实作者构件可另定义生产作者权限后再验，不把隔离测试能力当发布许可。

明确区分作者手动运行的本地 `content-cli check` 与游戏运行时。CLI 可比较源输入和旧输出，报告固定 schema 字段与重建短因；游戏不能依赖发布中不存在的作者输入，按实际可读、可解析、符合当前 schema 且组装成功才使用运行时资料。隔离单元/集成结果不代替 T05 真实原生运行、发布构件 Slot 99、打包路径清单或 T07 全量。
