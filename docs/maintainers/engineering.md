# 工程与验证维护说明

## 装配与兼容边界

来源、构建产物、作者输入和执行配置分别核对。按[宿主来源核验](runtime-sources.md)和[作者接入说明](../user-guide/integration.md)固定装配顺序；显式选择作者输入，不用默认样例替代。输入规则、战斗桥、应用端口和 MZ 宿主分层。作者类型按[类型合同](../contracts/party-types.md)保序去重，空列表使用规定默认；桥接无法表示未来类型时按完整物种的原生资料回退，不部分过滤或改掉作者记录。

## 分层检查与应用投影

先验证主结果和操作归属，再由唯一写入方提交；宿主展示、变量和等待不是同一事务。投影失败或变量 0 不应把自己的等待永远挂住，不得重做已提交结果。状态端口如果抛错，应保有旧值。参见[应用操作合同](../contracts/application-operations.md)。静态导入及宿主名检查用来避免误依赖，不是防任意恶意代码的沙箱；参见[分层规则](../contracts/ownership.md)。

## 宿主与性能验证口径

分开记录源码、无窗口真实/替身模块、NW 窗口、发行包和仅凭文档复建。通过类型检查、构建或只启动不等于完成宿主流程；合成作者数据不验证发行素材。现行无窗口入口和输入绑定见[验证说明](../testing/runtime-binding.md)。

## 参考对照和支持平台

规格推导的期望不是原版运行结果。冻结成长对照只有自身固定的证据范围；常规策略排除的部分不能算通过，也不说明别的机制达到跨语言等价。已验证的宿主、Mac 签名和公证以及 Demo 边界以[接入说明](../user-guide/integration.md)为准。

## 宿主输入等待与性能警告

拥有场景对象不表示已经可以输入；等真实原生开始与可交互条件，记录输入帧。未确认根因的超时不能只加等待或跑到通过。固定机器、负载、采样及冷启动条件才比较；单次短样本不足以证明无退化或无泄漏。参阅[原生输入合同](../contracts/host-input.md)。

## 图鉴资源生命周期风险

现有测量不能确定图鉴长期 Renderer 内存变化的成因。分开记录整 App 与 Renderer RSS，使用等业务次数及等暴露时间对照；触及资源或卸载路径时按相同条件复测。实际素材和新进程 Continue 仍是独立边界，不把旧有限结果或无窗口结果包装成无泄漏。
